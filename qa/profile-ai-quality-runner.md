# AI 댓글 품질 검증 실행 도구

## 이번 단계와 한계

기존 원픽 10개 입력 8세트를 반복 실행·기록·비교할 수 있는 **운영 앱과 분리된 Node CLI**다. 기본 명령은 계획 생성이며 API 키를 읽거나 외부 요청을 보내지 않는다. 이번 개발에서는 실제 모델 호출, 회원 데이터 조회/수정, AI 댓글 게시, 서버/앱 배포를 하지 않았다.

실제 공급자 응답은 아직 측정하지 않았다. 모의 테스트 통과와 문장의 의미 품질 합격을 구분한다. 이 도구는 로그인, RLS, 생성 제한, 공개/숨김 등을 포함한 앱 통합 검사를 대신하지 않는다.

## 명령

프로젝트의 기존 `mobile` 의존성 설치가 필요하다. TypeScript는 기존 잠금 파일에 있는 컴파일러를 재사용하고 패키지를 추가하지 않는다. 명령은 저장소 루트에서 실행한다.

```sh
# 비용·자격 증명·네트워크 없는 계획: 8세트 × 3회 = 24회 예정
node qa/run-profile-ai-quality.cjs plan --out=qa/results/plan-01

# 별도로 승인된 운영자 환경에서만 실제 유료 실행한다.
# OPENAI_API_KEY는 안전한 환경변수로 제공하며 명령 인자/채팅에 적지 않는다.
# 아래 명령은 구현된 실행 방법이지, 이번에 실제 실행했다는 기록이 아니다.
node qa/run-profile-ai-quality.cjs run --repeats=3 --confirm-live-calls=24 --out=qa/results/run-01

# 동일 입력·동일 반복 수의 두 실제 실행 결과를 비교
node qa/run-profile-ai-quality.cjs compare --baseline=qa/results/run-01/results.json --candidate=qa/results/run-02/results.json --out=qa/results/comparison-01
```

`--repeats=1`이면 8회이며 `--confirm-live-calls=8`을 명시해야 한다. 1~3회 반복만 허용한다. 비용 한도는 달러 금액이 아니라 **최대 24회 요청, 요청당 현재 생산 코드의 출력 토큰 한도**다. 입력 토큰 비용·가격·키 유효성은 계획 단계에서 알 수 없으므로 금액을 추정해서 채우지 않는다. 현재 모델은 코드에서 읽으며 모델 접근 오류가 나도 자동으로 다른 모델을 호출하지 않는다.

Supabase Secrets의 키를 추출하거나 자동으로 읽지 않는다. 실제 실행을 맡는 운영자의 별도 환경에서만 키를 제공한다. CI 환경에서는 유료 실행 명령을 차단하고 네트워크 없는 테스트만 한다. 정상 출력을 받기 전까지 반복 재시도하는 기능은 없다.

## 생산 코드와의 일치

`profile-ai-runtime.cjs`는 체크인된 `index.ts`, `quality.ts`, `contract.ts`를 읽는다. 신뢰된 저장소 소스에서 모델 요청 객체와 순수 출력 처리 함수만 TypeScript 구문 트리로 추출한다. Deno 서버나 Supabase 클라이언트는 실행하지 않는다.

현재 생산 코드의 모델·reasoning·출력 한도·JSON 스키마·작성 지시문·입력 구성기·나이 표현 검사를 재사용한다. QA용으로 지시문을 따로 복제하지 않는다. 소스 구조/요청 필드가 예상 범위를 벗어나면 **추출 실패로 중단**하며, 그때 어댑터도 코드 검토 후 갱신한다. 이 VM은 외부 사용자 코드 실행용 보안 샌드박스가 아니며 임의 파일/입력 소스를 받지 않는다.

기준 댓글과 `expectations`는 보고서와 수동 검토에만 쓴다. 생성 요청은 `case.picks`만 입력 구성기로 전달한다. 모델에는 계정 ID·실제 회원 한줄평·사진·SNS 정보가 들어가지 않는다.

## 기록 파일

| 파일 | 기록 |
|---|---|
| `results.json` | 실행 모드, 입력/요청 해시, 정확한 생산 소스 SHA-256, 모델·프롬프트 버전, 회차별 출력·오류·시간·토큰 사용량 |
| `report.html` | 입력 10개와 회차별 결과를 펼쳐 비교하는 읽기 전용 보고서. 외부 요청·스크립트 없음 |
| `review-template.json` | 결과별 근거 원픽 번호·검토자·검토 시각·판정·의견. 자동 통과로 채우지 않음 |
| `comparison.json` | 같은 입력의 이전/다음 결과 상태·자동 검사·시간 차이·문자 중복률. 의미 품질 점수 아님 |

기존 결과 폴더는 덮어쓰지 않는다. 결과 파일은 기본 사용자 전용 권한으로 저장하고 `qa/results/`는 Git에서 제외한다. 검토표는 실행이 끝난 뒤 사람이 채워 별도로 보관하며, 도구가 이를 검토한 것처럼 승인 상태를 만들어내지 않는다. 내용과 연결할 수 있도록 결과 해시를 포함한다.

## 실패 및 비교 규칙

HTTP 오류(401/403/404/429/5xx 등), 네트워크 실패, 시간 초과가 나면 그 회차를 기록하고 나머지 요청을 멈춘다. 오류 본문·API 키·전체 응답 헤더는 저장하지 않는다. 20초 제한은 응답 본문 읽기까지 적용하며, 큰 응답은 256KiB에서 중단한다. 공급자가 이미 받은 요청이 과금되지 않았다고 보장하지 않는다.

처리 중에는 시도 직전과 직후 체크포인트를 기록한다. 중단된 실행을 자동 재개하지 않는다. 실행 중 미완성 `results.json`이 남으면 시도 여부를 확인한 뒤 운영자가 별도 판단해야 한다. 정상 응답의 형식/나이 검사가 실패한 경우는 실패 결과를 보존하고 승인된 나머지 회차를 진행한다. 누락 결과를 기준 댓글로 대체하지 않는다.

자동 검사는 JSON 형식·필수 필드·길이·키워드·기존 나이 표현 검사다. 말투 관련 일부 문자열은 **사람이 볼 경고**이며 공격성의 의미를 판정했다고 주장하지 않는다. 짧은 본문과 위트 생략을 곧바로 품질 실패로 보지 않는다.

같은 제품/다른 이유 쌍은 회차별로 연결한다. 문자 3-gram 중복률은 비슷한 문장을 검토할 보조 신호다. 중복률이 낮아도 개인화 성공이라는 뜻은 아니다. 전후 실행의 입력 해시나 반복 수가 다르면 비교를 중단한다. 모델/프롬프트 변경은 기록하되 입력이 같을 때만 정렬해 비교한다. 실패·미실행 회차도 보고서에 남겨 성공률을 부풀리지 않는다.

## 검증 기록

로컬에서 `mobile/scripts/test-profile-ai-quality-runner.cjs`의 **33개 테스트**를 통과했다. 실제 생산 요청·작성 규칙을 읽어 24개 모의 응답을 기록하는 경로도 검사했다. 모든 전송은 모의 처리이며 실제 공급자 호출은 0회다. 최종 저장 커밋의 전체 자동 검사 결과는 PR Checks에서 별도로 확인한다.
