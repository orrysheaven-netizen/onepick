# T/F 말투를 같은 근거로 비교하기

## 이번 변경과 범위

같은 원픽 10개를 읽는 `direct`(담백한 해석)와 `warm`(다정한 해석)을 나란히 검토한다. 말투를 바꾸었다는 이유로 다른 취향·개인사·능력을 만들어내지 않는지가 핵심이다. 사용자 MBTI 판정·점수화 기능이 아니다. 이번 변경은 QA 기록 및 비교 도구에 한정한다. 앱 UI, 모델 지시문, DB/RLS, 서버 배포는 변경하지 않는다. 실제 모델 호출은 하지 않는다.

## 발견한 식별자 문제

기존 계획 fingerprint는 datasetHash·반복 수·생산 소스 파일 해시만 포함했다. 두 말투는 같은 파일과 같은 입력을 사용하므로 requestHash와 promptVersion이 달라도 fingerprint가 같았다. `identityVersion: 2`에서는 tone, 모델, 정확한 작성 규칙/스키마/요청 해시와 한도를 함께 묶는다. 검토표에도 tone을 기록한다. 같은 소스의 T/F 계획이 서로 다른 식별자를 갖는 회귀 검사를 추가했다. 이 해시는 데이터 일치 확인용이며 서명이나 변조 불가능한 감사 증명이 아니다.

기존 identityVersion 없는 보고서는 수정하거나 임의로 T/F로 분류하지 않는다. 새 비교기는 새 형식의 계획/결과를 요구한다. 계획 재생성은 오프라인이며, 과거 실제 실행 결과가 있다면 원본을 보존하고 별도로 검토한다. 이 변경이 유료 재실행을 자동으로 승인하거나 시작하지 않는다.

## 오프라인 명령

저장소 루트에서 기존 mobile 의존성을 설치한 환경으로 실행한다. 다음은 모델 호출 없이 입력과 비교 양식만 만든다.

```sh
node qa/run-profile-ai-quality.cjs plan --tone=direct --repeats=1 --out=qa/results/tone-direct-plan
node qa/run-profile-ai-quality.cjs plan --tone=warm --repeats=1 --out=qa/results/tone-warm-plan
node qa/compare-profile-ai-tones.cjs --direct=qa/results/tone-direct-plan/results.json --warm=qa/results/tone-warm-plan/results.json --out=qa/results/tone-comparison-plan
```

`--tone`은 명시적 선택이며 지정한 경우 기존 `ONEPICK_QA_TONE`보다 우선한다. 지정하지 않으면 기존 기본 동작을 유지한다. 잘못된 값과 compare 명령에서의 tone 덮어쓰기는 거부한다. 입력 8세트 × 각 모드 1회는 비교 8쌍·예정 요청 합계 16회다. 위 plan 명령의 실제 요청은 0회다. 두 모드를 각 3회 검토하면 합계 48회가 될 수 있지만, 유료 실행은 기존 실행별 최대 24회와 별도 정확한 호출 횟수 승인 규칙을 유지한다. 비교 명령은 run 명령이 아니며 합산 계획만으로 호출을 시작하지 않는다.

## 비교 조건

- 직접·다정한 말투의 지정 위치가 맞고 같은 실행 모드(plan/mock/live)인지 확인한다.
- 원픽·한줄평·반복 수가 같고, 모델·생산 소스 파일·스키마·한도가 같아야 한다. 말투 외의 변경은 기존 일반 compare 도구로 따로 검토한다.
- 계획 해시·행별 요청 해시·사례 ID·회차를 확인한다. 빠진 행·중복 행·잘못된 입력·허위 완료 표시를 거부한다.
- 한쪽이 실패하거나 미실행이면 해당 칸을 유지한다. 예시를 채우거나 실패를 삭제해 성공률을 높이지 않는다.
- plan은 결과 없음, mock은 모의 응답, live는 실제 실행 기록으로 구분한다. 외부에서 임의 작성한 파일이 실제 호출의 증거인지 인증하는 기능은 아니다.
- 출력 본문이 바뀌면 비교 ID와 출력 해시도 달라져 이전 검토표와 구분할 수 있다.

## 생성 파일

`report.html`은 같은 입력의 두 결과를 나란히 표시한다. 모바일에서는 세로로 배치한다. 외부 스크립트·이미지·네트워크 요청이 없고 출력 텍스트는 이스케이프한다. `comparison.json`은 매칭된 결과와 상태를 기록한다. `review-template.json`에는 아래 항목을 모두 미검토로 남긴다.

- 두 말투의 핵심 관찰이 동일한 선택 근거에 연결되는가?
- T가 근거를 명확히 정리하되 비판·독설로 흐르지 않는가?
- F가 부드럽되 없는 감정·관계·생활사를 만들지 않는가?
- 나머지 선택과 모순되거나 나이·민감한 특성을 추정하지 않는가?
- 읽기 편하고 위트가 선택 조합에 근거하는가? 위트 생략은 실패가 아니다.

각 말투의 근거 원픽 번호, 검토자, 검토 시각, 판정과 의견을 사람이 작성한다. 검토 파일을 자동으로 승인하거나 앱 공개 권한과 연결하지 않는다. 기존 폴더는 덮어쓰지 않으며 결과 파일은 사용자 전용 권한으로 생성한다.

## 검증

`mobile/scripts/test-profile-ai-tone-review.cjs`의 22개 검사를 로컬에서 통과했다. 실제 생산 요청 구성기를 읽되 모든 결과는 계획 또는 합성 모의 데이터다. 네트워크 fetch는 테스트에서 차단한다. 전체 CI 결과는 최신 저장 커밋에서 별도로 확인한다. 앱의 계정·공개/숨김 흐름과 실제 두 말투의 의미 품질은 이 검사의 범위가 아니다.
