# OnePick 공용 작업 원칙

최종 갱신: 2026-09-28  
적용 대상: ChatGPT/Codex, Claude Code, OnePick 관련 모든 작업

이 문서는 사용자가 대화에서 확정한 **공통 작업 원칙의 우선 참조 문서**다.  
ChatGPT/Codex와 Claude Code는 작업 시작 전 이 문서를 먼저 확인한다.

## 1. 우선순위

과거 협의 내용과 이후 공유된 최신 문서의 내용이 다르면 **최신 문서의 내용을 따른다**.

충돌 시 기본 적용 순서는 다음과 같다.

1. 사용자가 가장 최근에 확정한 지시
2. 이 공용 작업 원칙 및 이후 갱신된 최신 공용 문서
3. 해당 작업의 최신 명세·디자인·PRD 문서
4. 기존 역할 분담·기술 문서
5. 과거 대화·이전 협의 내용

오래된 문서나 대화 기록을 근거로 최신 결정을 되돌리지 않는다.

## 2. 극초기 MVP 원칙

OnePick의 모든 작업은 **극초기 MVP 방향성**에 맞게 진행한다.

- 핵심 사용자 흐름과 실제 검증에 필요한 최소 범위를 우선한다.
- 비필수 기능, 과도한 구조화, 고도화, 확장 대비 설계는 후순위로 둔다.
- 비용·운영 복잡도·유지보수 부담을 늘리는 요소는 MVP 검증에 필수일 때만 채택한다.
- 기존 기획이나 구현이 이 원칙과 충돌하면, 최신 사용자 지시와 최신 문서를 기준으로 범위를 줄인다.
- “나중에 필요할 수 있음”만을 이유로 초기 MVP 범위를 넓히지 않는다.

## 3. Figma 작업자 표기

Figma에서 Claude와 ChatGPT의 작업물을 구분할 수 있도록 **화면 번호 또는 제목 앞에 작업 주체를 명시**한다.

권장 형식:

- `지피티 75. 원픽 등록 v6`
- `클로드 76. 홈 v6`
- 또는 `[지피티] 75. ...`, `[클로드] 76. ...`

새 화면 생성, 기존 화면 수정, 정리, 인계 시 동일하게 적용한다.

## 4. Figma 중복 화면 처리

새로 만들려는 화면이 기존 화면과 중복되거나 유사하면 **바로 새로 만들거나 덮어쓰지 않는다**.

먼저 사용자에게 다음을 비교해 알린다.

- 기존 화면 번호·제목
- 새 작업안과 기존 화면의 차이
- 추가되는 요소
- 삭제되는 요소
- 변경되는 동작·문구·레이아웃

그 다음 처리한다.

- 사용자가 승인하면 기존 화면을 업데이트한다.
- 사용자가 승인하지 않으면 기존 화면을 그대로 존치한다.
- 승인 전에는 중복 화면을 임의로 새로 만들거나 기존 화면을 덮어쓰지 않는다.

## 5. 적용 범위

이 원칙은 Figma뿐 아니라 앱 구현, DB, 관리자 화면, QA, 문서화, 자동화, 작업 인계에도 공통으로 적용한다.

세부 구현 규칙은 각 전문 문서(`docs/design-foundations.md`, `docs/ai-role-division.md` 등)를 따르되, **이 문서 또는 이후의 최신 사용자 지시와 충돌하면 최신 기준을 우선**한다.

## 6. 문서 유지

이 대화에서 사용자가 새로운 공통 원칙을 확정하면 이 문서를 갱신한다.  
기존 결정을 바꾸는 내용은 예전 문장을 병렬로 남겨 혼동시키지 말고, 최신 결정을 기준으로 명확히 정리한다.
