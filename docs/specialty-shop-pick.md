# 전문몰 원픽: 초기 유입 컨셉

상태: 1차 구현됨 — 전문몰 카테고리 개방(상품군 6개), 저장 시점 URL 정규화와
중복 방지, 마트형 차단, 한줄평 광고 차단, 신고 사유 `self_promotion`, 상품 상세의
판매처 링크. 아이템 마스터 사전 시딩(운영 데이터)과 홈 카드의 도메인 표시는 아직이다.
`content-seeding.md`의 초기 카테고리 운영과 `commercialization-rights-gate.md`의
상업화 경계, `follow.md`의 공유 확산 논의를 잇는다.

## 왜 필요한가

- MVP의 병목은 "왜 들어오는가"다. 애정템·취향공유는 자기표현이라 밀어내는 힘이고,
  이미 다른 앱이 하고 있다. 전문몰 추천은 당겨오는 힘이다. "원두 어디서 사?"는
  실재하는 질문인데 검색 결과가 광고로 오염돼 답할 곳이 없다.
- 원픽 구조에 더 잘 맞는다. 좋아하는 과자는 셋일 수 있지만 **정착한 전문몰은 실제로 하나다.**
  재구매가 곧 충성이라, "카테고리당 1개" 제약이 인위적 규칙이 아니라 실제 행동의 기록이 된다.
- 공유가 자연스럽다. "여기서 사"는 사람들이 실제로 메신저에 보내는 문장이다.
  자랑 링크와 달리 받는 사람이 실제로 누른다.
- 구조가 이미 준비돼 있다. `items.official_url`과 `brands.logo_url`이 존재하고,
  유튜브 채널 카탈로그가 "URL을 가진 외부 실체를 아이템으로 다루는" 선례다.
  쇼핑몰은 그보다 단순하다(외부 API 쿼터도, 30일 데이터 삭제 정책도 없다).

## 대상 정의

**전문몰**은 하나 또는 소수 품목만 전문적으로 취급하는 판매처다.

- 포함: 원두 로스터리 자사몰, 차 전문몰, 양말 전문 브랜드몰, 문구 전문몰,
  향 제품 전문몰, 수제 조미료 전문몰처럼 품목이 좁은 곳.
- 제외: 네이버쇼핑, 컬리, 올리브영, 쿠팡처럼 여러 품목을 함께 파는 마트형.
- 이 경계는 데이터로 판정할 수 없고 운영으로만 지켜진다. **카테고리 설명 문구에
  제외 규칙을 문장으로 박아둔다.** 정의가 화면에 없으면 마트형이 올라온다.

## 사용자 이용 / UX

- 목표 흐름: 홈에서 다른 사람의 전문몰 원픽과 이유를 읽는다 → 같은 곳을 쓰면
  `나도 이게 원픽`, 다른 곳을 쓰면 같은 카테고리에서 내 몰을 고른다.
  기존 `people-first-home.md`의 카드 동작을 그대로 쓴다.
- 카드 구성은 기존과 같다. 상품 사진 자리에는 몰 이름과 정규화된 도메인을 보여준다.
  한줄평(1~100자)이 추천 이유다.
- 선택 흐름도 기존 아이템 검색/선택 화면을 그대로 쓴다. 전용 등록 폼을 만들지 않는다.
- 없는 몰은 기존 미등록 아이템 요청 흐름(관리자 승인)을 탄다. 다만 아래 시딩 때문에
  첫 사용자가 승인 대기에 걸리는 경우를 최소화한다.
- 한줄평에 URL·할인코드·쿠폰 문구를 넣을 수 없다는 안내를 입력 시점에 보여준다.

## 카테고리 설계

카테고리 트리는 최대 3단계이고 말단만 `is_pickable`이다(자식이 있으면 선택 불가).
전문몰은 최상위 하나에 상품군을 말단으로 둔다.

```
전문몰 (is_pickable=false)
├─ 원두 전문몰     ← 선택 대상
├─ 차 전문몰
├─ 양말 전문몰
└─ 문구 전문몰
```

- **초기 개방은 6~8개만.** `content-seeding.md`의 완료 기준은 카테고리당 사용자 3명 이상,
  서로 다른 아이템 2개 이상이다. 카테고리를 넓히면 어느 곳도 밀도에 도달하지 못한다.
- 애정템 카테고리와 **이름을 짝지어 둔다**(`원두` / `원두 전문몰`). 공개 프로필에서
  "내 원두 원픽은 ○○, 나는 △△에서 산다"가 나란히 보인다. 스키마 변경이 필요 없다.
- 아이템과 구매처를 실제로 연결하는 관계는 이번 범위가 아니다.

## 상업화 오염 방어 (같은 릴리스에 포함)

전문몰 추천은 돈이 걸린 영역이라 몰 운영자 본인·대행사·어필리에이터가 반드시 들어온다.
사용자 20명 규모에서는 그런 계정 하나로 홈이 무너진다. 정책 문구로는 막히지 않으므로
**아이템 저장 시점의 구조로 막는다. 카테고리 개방과 같은 릴리스에 넣는다.**
오염된 뒤에는 되돌릴 수 없다. 그 몰을 고른 사용자의 원픽까지 함께 지워야 하기 때문이다.

- **URL 정규화를 저장 시점에 강제한다.** 스킴·호스트 소문자화, `www.` 제거,
  **쿼리스트링 전량 제거**, 경로 루트화. `ref` / `utm_*` / `partner` 같은
  어필리에이트 파라미터가 구조적으로 무력화되고, 같은 몰이 여러 아이템으로
  쪼개지는 것도 함께 막힌다.
- **도메인 유니크만으로는 부족하다.** 국내 전문몰 상당수가 스마트스토어·아임웹·카페24
  입점형이라 호스트가 같고 경로만 다르다. 플랫폼 호스트 화이트리스트를 두고
  **그 경우에만 첫 경로 세그먼트까지 포함**해 유니크를 잡는다.
- 한줄평에 URL·할인코드 패턴을 차단한다. 지금 한줄평은 자유 텍스트라 그대로 광고판이 된다.
- 신고 사유에 "본인이 운영하는 몰"을 추가한다. 기존 신고/차단 흐름에 항목만 얹는다.
- 기존 `picks.status`의 `needs_review`를 광고성 한줄평 보류에 사용한다. 새 상태를 만들지 않는다.

## 아이템 마스터 사전 시딩

라면·영화·음악은 외부 카탈로그가 아이템을 자동으로 채워준다. **전문몰은 외부 카탈로그가
없어 전부 사용자 제출 + 관리자 승인이다.** 그런데 `prelaunch-first-user-journey.md`의
릴리스 게이트는 "5픽 완료 → AI 평가"다. 고르려는 몰이 매번 `pending-product`
스테이징에 걸리면 5픽을 채우지 못해 게이트가 열리지 않는다.

- 운영자가 전문몰 **30~50개를 아이템 마스터에 미리 등록한다.**
- 이것은 `content-seeding.md` 원칙 2 위반이 아니다. 그 원칙이 금지하는 것은
  **픽(취향)을 대신 만드는 일**이고, **아이템 마스터를 채우는 일**은 해당하지 않는다.
  두 작업을 운영 문서에서 구분해 기록한다.
- 시딩한 몰은 기존 `item_aliases` + trigram 검색으로 찾힌다. 별도 검색 경로를 만들지 않는다.
- 시딩은 아이템까지다. 운영자가 어느 몰을 고르는지는 시딩하지 않는다.

## 애정템과의 관계

전문몰 원픽은 **사람당 개수가 적다.** 한 사람이 정착한 전문몰은 3~5개면 많은 편이라
전문몰만으로 5픽 게이트를 채우기는 빡빡하다. 애정템 카테고리 4~6개를 함께 열어
게이트를 지킨다. 초기 컨셉의 전면은 전문몰, 픽 개수를 받치는 것은 애정템이다.

취향공유는 별도 컨셉이 아니라 **결과물**이다. 이미 있는 AI 취향 평가와 공개 프로필이
그 역할을 하므로, 진입 문구가 아니라 공유 시점의 메시지로만 쓴다.

## 공유 확산에 미치는 영향

- **공유 링크 미리보기의 중요도가 올라간다.** 웹은 SPA이고 `vercel.json`이 모든 경로를
  `index.html`로 rewrite하며 OG 메타 태그가 없다. 공유 링크가 메신저에서 제목·이미지 없는
  맨 링크로 뜬다. 전문몰 카드는 몰 이름·도메인·한줄 이유로 미리보기가 잘 나오는 형태라
  크롤러 전용 prerender의 효과가 특히 크다.
- **이름 표시의 우선순위는 내려간다.** 유용한 정보는 누가 추천했는지 몰라도 눌린다.
  `profiles.username`이 `^[a-z0-9_]{3,20}$`라 한글이 들어가지 않는 문제는 그대로지만
  1순위는 아니다.
- **친구의 친구 추천은 계속 보류한다.** 대신 `picks`만으로 되는 **"같은 몰을 고른 사람"**을
  쓴다. 전문몰 선택은 취향 신호가 강해 같은 아이템 연결보다 근접도가 높고,
  `people-first-home.md`의 "추천 알고리즘·인기순 없음" 원칙을 깨지 않는다.

## 하지 않는 것

- 가격·재고·할인 정보 수집, 실시간 크롤링, 구매 전환 추적.
- 어필리에이트 링크, 제휴·협찬 배치, 광고 노출.
- 몰 로고 자동 수집(상표권). 초기에는 이름과 도메인 중심의 텍스트 카드로 간다.
- 몰 평점, 별점, 리뷰 수, 인기순 정렬, 추천 알고리즘.
- 마트형 종합몰 카테고리 개설.
- 전용 등록 폼, 전용 검색 경로, 전용 피드 탭.

## 구현 위치

| 규칙 | 코드 |
| --- | --- |
| URL 정규화 | `private.normalize_shop_url()` |
| 마트형 판정 | `private.is_marketplace_shop_url()` |
| 전문몰 카테고리 판별 | `private.is_specialty_shop_category()` |
| 아이템 저장 규칙 | `items_enforce_specialty_shop` 트리거 |
| 한줄평 광고 차단 | `private.review_contains_promotion()` + `picks_enforce_review_policy` 트리거 |
| 클라이언트 거울 | `mobile/src/lib/shops/shopUrl.ts` |

모든 규칙은 트리거에 있다. 사용자 제출 RPC, 관리자 등록/수정, 승인·병합이 모두
`items`와 `picks`를 직접 쓰기 때문에 경로마다 검사를 넣으면 한 곳이 빠진다.
`shopUrl.ts`는 같은 규칙을 화면에서 미리 알려주기 위한 사본이며 권한이 없다.
데이터베이스가 판정하고, 사본은 설명만 한다. 둘은 함께 고쳐야 한다.

## 검증 / 측정

- DB 테스트: URL 정규화 결과 동일성(쿼리스트링 유무·`www.` 유무·대소문자),
  입점형 플랫폼의 경로 세그먼트 유니크, 한줄평 URL/할인코드 차단,
  마트형 도메인 차단 목록, 중복 몰 제출 시 기존 아이템으로 수렴.
- 앱 테스트: 전문몰 카테고리 선택 → 시딩된 몰 검색 → 저장 → 공개 프로필에
  애정템과 짝으로 노출, 미등록 몰 요청의 기존 승인 흐름 유지.
- 측정: 전문몰 카테고리의 카테고리당 선택 인원과 서로 다른 몰 수(밀도),
  전문몰 원픽의 공유 발생률과 링크 클릭 → 가입 전환율,
  사람당 전문몰 원픽 수와 5픽 게이트 도달률,
  광고성 신고 건수(오염 지표. 이 값이 오르면 방어 구조부터 손본다).

## 남은 작업

- **아이템 마스터 사전 시딩.** 실제 전문몰 30~50개는 운영 데이터라 코드로 넣지
  않았다. 기존 관리자 상품 등록 화면으로 넣으면 되고, 입력 시점에 같은 규칙이
  적용된다. 이 시딩 전에는 첫 사용자가 승인 대기에 걸린다.
- **홈 카드의 도메인 표시.** `home_pick_feed_page`의 반환 컬럼에 `official_url`이
  없어 홈 카드에서는 도메인을 보여주지 않는다. RPC 반환 컬럼을 바꾸는 일이라
  홈 계약과 기존 홈 테스트를 함께 건드린다. 지금은 상품 상세에서만 보여준다.
- **마트형 목록 운영.** 목록은 함수 안의 배열이라 추가에 마이그레이션이 필요하다.
  감사 가능성을 얻는 대신 치르는 비용이고, 초기 규모에서는 이 편이 낫다.

## 배포

마이그레이션은 기존 규칙대로 Git에 준비하고 `main` 머지 시 Supabase 연동으로 배포한다.
카테고리 개방과 상업화 방어 구조는 분리해서 배포하지 않는다.
