# 기존 연결을 보존하는 OnePick 자동화 분리

Refs #225 (항목 9). PR #247의 활성화 준비 문서입니다.
현재 컴퓨터의 GitHub CLI 로그인과 Codex GitHub 연결은 유지합니다.
기존 연결을 일괄 해제하거나 새 App이 Codex 연결까지 대체했다고 간주하지 않습니다.
이 문서는 실행 환경을 생성하거나 운영 배포를 승인하지 않습니다.

## 분리해야 하는 두 가지

| 대상 | 필요한 경계 | 현재 증거 |
| --- | --- | --- |
| 실행 환경 | OnePick 자동화가 사용자 PC의 로그인·파일·브라우저·연결 도구에 접근하지 못함 | 기존 CI와 배포 잡은 GitHub-hosted runner를 사용하지만 App 요청은 현재 PC에서 보냄 |
| 승인자 접근 | 자동화가 승인자 명의의 OnePick 승인 댓글과 PR 승인을 만들 수 없음 | 현재 PC에 승인자 계정의 CLI·커넥터가 남아 있어 미완료 |

서버나 작업 디렉터리만 바꾸어도 두 경계가 모두 생기는 것은 아닙니다.
특히 현재 데스크톱 에이전트가 승인자 연결을 계속 사용할 수 있다면,
원격 작업이 App으로 실행됐다는 사실만으로 승인 댓글의 독립성을 증명할 수 없습니다.
현재 데스크톱 작업을 운영 배포 자동화의 독립 승인 검증 완료 사례로 사용하지 않습니다.

## 실행 환경 후보

사용자가 선택한 검토 대상은 이미 사용 중인 **GitHub-hosted runner**입니다. 별도 유료 서버를
만들거나 이 PC에 상주 실행기를 설치하지 않고 기존 워크플로 구조를 이용할 수 있습니다.
현재 `ubuntu-latest` 잡은 GitHub가 제공하는 새 VM에서 실행됩니다. 단일 CPU
공유 VM 컨테이너와 self-hosted runner를 동일한 격리로 간주하지 않습니다.

기존 배포 워크플로는 이미 `plan`, 비밀값 없는 `verify`, 승인 검증 후 `apply`를
서로 다른 잡으로 실행합니다. 단순히 같은 구조의 워크플로를 하나 더 추가해
환경 분리가 끝났다고 표시하지 않습니다. 앞으로 요청을 보내는 실행기까지 옮길 때는:

- 검토된 main 코드만 실행하며 임의 저장소·브랜치·명령·다운로드 URL 입력을 받지 않습니다.
- 승인자 PAT, 사용자 OAuth 토큰, Git 자격 증명 저장소, SSH agent,
  사용자 홈 폴더, 브라우저 프로필, Codex 연결을 전달하지 않습니다.
- OnePick 한 곳으로 제한한 App installation token을 사용합니다.
  실행 요청만 하는 구성은 작업별 토큰을 `Actions: write`와 필요한 읽기 권한으로 축소합니다.
- App 개인키를 runner에 등록하려면 별도의 main 전용 환경과 보호된 워크플로가
  준비돼야 합니다. 토큰 권한을 줄여도 개인키 자체는 App의 전체 설치 권한으로
  새 토큰을 만들 수 있다는 한계를 기록합니다.
- 키는 일반 저장소 시크릿, 파일, 아티팩트, 캐시, 채팅 또는 로그로 옮기지 않습니다.
  개인키의 새 보관 위치는 대상과 접근 범위를 검토한 뒤 정합니다.
- 실행기에는 Supabase 운영 자격 증명을 주지 않습니다. DB 비밀값은 기존
  `Production`의 승인된 DB 접근 잡에만 전달합니다.

별도 서버/VM이 이미 있다면 같은 경계를 확인한 후 대안으로 사용할 수 있습니다.
다른 Windows 계정은 홈·자격 증명·브라우저·관리자 권한·연결 도구가 실제로
분리됐는지 확인해야 합니다. 폴더 분리, 환경변수 삭제, 다른 터미널 창,
같은 사용자 권한의 컨테이너만으로는 충분하지 않습니다.

## 기존 연결을 유지할 때의 승인자 조건

읽기 전용 상태 확인에서 현재 GitHub CLI가 `orrysheaven-netizen`의 OAuth 로그인과
`repo`, `workflow` 권한을 사용하는 것을 확인했습니다. 이 연결은 선택 저장소만
허용하는 App 설치 토큰이 아닙니다. `repo` scope 자체에는 OnePick 하나만 제외하는
설정이 없으므로, 현재 토큰을 그대로 유지하면서 제외가 완료됐다고 표시할 수 없습니다.
다른 인증 방식으로의 전환은 다른 작업의 영향과 기능 호환성을 확인한 후 별도로 결정합니다.
토큰 원문이나 자격 증명 저장소 내용은 조회하지 않았습니다.

다음 중 하나의 경로가 **실제로 검증돼야** `identitySeparated`를 켤 수 있습니다.

1. 기존 연결은 다른 작업에 계속 사용하되, 에이전트가 그 연결로 OnePick에서
   승인자 명의의 승인·설정 변경을 수행할 수 없도록 저장소 접근 범위를 제한합니다.
   제공자가 저장소별 제외를 지원하는지부터 확인합니다. 지원하지 않으면 완료로 표시하지 않습니다.
   사람의 OnePick 접근은 에이전트가 조작하거나 자격 증명을 읽을 수 없는 별도 승인 환경에 둡니다.
2. 기존 개발 연결을 유지해야 하고 OnePick만 제외할 수 없다면, 에이전트에 연결한 적 없는
   별도 사람 승인 계정 또는 별도 서명 검증 방식을 검토합니다. 새 계정·권한·서명 체계를
   임의로 만들지 않으며, 숫자 ID 변경은 사람 검토 PR을 거칩니다.

현재 승인자 ID는 `329510562`로 그대로 둡니다. 이 계정의 기존 에이전트 접근을
그대로 둔 채 "서버만 분리했으므로 독립 승인"이라고 선언하지 않습니다.
다른 작업의 연결을 끊지 않는다는 선택은 승인 조건을 생략한다는 뜻이 아닙니다.

## 완료 증거와 미완료 상태

- 완료: App 설치 범위, App 명의 PR, 사용자의 직접 PR 승인, App 병합,
  main 수동 실행과 재실행의 actor/triggering_actor 및 성공 결과.
- 미완료: App 요청 실행기의 전용 환경, 승인자 연결의 OnePick 접근 분리,
  main의 필수 사람 승인, Production 비밀값 이관, 최소 권한 QA 자격 증명,
  승인 기록 초기 설치, 폐기 가능한 대상의 전체 적용 검증.
- 환경 점검에서 비밀값을 열거하거나 출력하지 않습니다. 실제 호스트·워크플로·권한 설정과
  실행 기록을 근거로 판단하며, 자체 점검 스크립트의 성공만으로 격리를 증명하지 않습니다.
- 검증 완료 전 `enabled` 및 모든 readiness 플래그는 false를 유지합니다.
  PR #247의 비활성 상태가 현재 main의 이전 수동 DB 배포 워크플로를 중지한 것은 아닙니다.
  기존 경로를 통한 적용을 이번 준비 작업에서 실행하지 않습니다.
