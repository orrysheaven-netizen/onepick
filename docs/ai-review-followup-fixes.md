# AI 댓글 추가 점검 후 수정

## 범위

최소 공개 원픽 10개, 한줄평 중심 해석, 나이 표현 제외, 공격적·부정적 인물평 금지, 선택에 근거한 위트는 그대로 유지한다. API 설정은 보류한다. 이번 변경은 기존 PR #47의 개발 브랜치 코드와 테스트다. 운영 DB 스키마/권한, 공개 카테고리, 모델 종류, 실제 사용자 원픽은 변경하지 않는다.

## 1. 화면에서 확인한 댓글만 공개

공개 클릭에서 `id`와 원본 `generatedAt`을 함께 캡처한다. 서비스/저장소가 이 값을 전달하고, 공개 UPDATE가 `profile_id`, `id`, `generated_at`, `is_stale=false`를 한 문장에서 비교한다. 먼저 최신 댓글을 읽고 조건 없이 공개하는 방식이 아니다.

`generated_at`은 기존 서버 저장 함수에서 새 생성 때마다 바뀌는 생성 시각이다. 원본 문자열의 PostgreSQL 마이크로초를 보존하며, Date 변환으로 밀리초로 반올림하지 않는다. `id` 비교는 삭제 후 재생성한 행도 구별한다. 앞으로 본문을 수정하는 서버 경로를 추가할 때도 생성 버전이 반드시 바뀌어야 한다.

버전 누락/형식 오류는 공개 요청 전에 거부한다. 일치하는 행이 없으면 `AI_REVIEW_STALE`로 처리하고 최신 댓글을 다시 불러온다. 자동으로 새 버전으로 바꾸거나 공개를 재시도하지 않는다. 화면 안내는 “원픽이나 AI 댓글이 바뀌었어요. 최신 내용을 확인한 뒤 공개해주세요.”이다.

숨기기는 오래된 화면에서도 가능하도록 버전 조건을 붙이지 않는다. 최소 원픽 수나 AI 설정도 숨기기의 조건이 아니다. 기존 Auth 검증, 본인 프로필 필터, RLS, 본문 수정 금지는 유지한다.

이것은 새 앱의 이전 화면 경쟁 상태를 고치는 조건부 UPDATE다. 사람이 실제로 읽었는지를 증명하지는 않는다. 기존 소유자의 직접 UPDATE 권한을 회수하거나 모든 구버전/직접 API 요청에 새로운 RPC 사용을 강제한 것은 아니다. 앱 배포 전에는 사용자 화면에 이 수정이 적용되지 않는다.

## 2. 나이 검사 오탐 완화

`나이`/`나잇`의 무조건적인 부분 문자열 검사 대신 단어 경계와 한국어 어미를 확인한다. ‘나이브스 아웃’, ‘미드나잇 인 파리’, ‘나이키’, 단순 제품 세대 표기와 출시연도 같은 비연령 표현의 회귀 사례를 추가했다.

숫자 나이뿐 아니라 스물다섯 살, 서른두살, 삼십대 등 명시적인 한글 연령 표현도 검사한다. 요약·본문·키워드를 각각 확인하며, 정상 작품명이 포함됐다고 문장 전체를 예외 처리하지 않는다. 원본 한줄평/카탈로그 데이터를 수정하거나 키워드에 맞춰 원본을 삭제하지 않는다.

이 검사는 제한된 문자열 검사다. 모든 작품명이나 모든 우회 표현을 완벽히 구별하는 의미 분류기, 공격성 판별기, 실제 모델 품질 검증기는 아니다. 기존 프롬프트와 실제 출력의 별도 품질 검증은 계속 필요하다.

## 검사

- `test-profile-ai-account.cjs`: 기존 계정·응답 회귀 검사에 공개 버전 누락, 삭제/재생성, 미세 시각 차이, 검증 중 변경, 숨김 유지 등을 추가한다. 모의 DB가 필터를 실제로 평가하도록 보완한다.
- `test-profile-ai-publication-ui.cjs`: 실제 카드/훅 코드를 모의 환경에서 실행해 클릭 시 버전 전달, 숨김, 오래된 카드 차단, 오류 안내, 재시도 금지를 확인한다.
- `test-profile-ai-age-guard.cjs`: 정상 고유명사와 한글/숫자 연령 표현을 요약·본문·키워드 각각에서 검사한다.
- `supabase/tests/ai_profile_publication_version.sql`: 실제 PostgreSQL의 조건부 UPDATE, 마이크로초 비교, 삭제/재생성 및 기존 소유자 RLS를 합성 데이터로 검사한다. 트랜잭션 종료 때 전부 롤백한다.
- 최신 커밋의 Mobile CI, Web build, Database Tests, AI function smoke 결과를 별도 확인한다. 통과하지 않은 검사를 통과했다고 간주하지 않는다.

## 남은 항목

화면/서버의 분석 가능 원픽 집계 통일, 주류 선택 없이도 10개를 채울 수 있는 카테고리 구성, 실패 후 재요청 안내는 이번 두 수정과 별도로 남는다. 실제 모델 호출, 로그인 브라우저 전체 검증, 서버/앱 배포 및 PR 병합도 수행 여부를 구분한다.
