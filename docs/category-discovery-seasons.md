# 세부 음식 카테고리 · 탐색 노출 · 제철 추천

상태: 구현 계약  
기준일: 2026-09-23

## 목적

OnePick의 원픽 질문을 실제 검색 단위까지 좁힌다.

- `곱창` / `막창` / `대창`
- `곱창김` / `돌김`
- `민어회` / `전어회` / `방어회`

세분화 자체가 화면 복잡도로 이어지지 않도록 **원픽 단위와 탐색 노출 단위를 분리**한다.

## 불변식

1. 카테고리 트리는 최대 3단계를 유지한다.
   - 예: `먹을것 → 해산물 → 전어회`
2. 실제 원픽은 가장 세밀한 pickable leaf에 저장한다.
3. 상위 그룹은 묶음/탐색용이며 별도 원픽을 받지 않는다.
4. 지역은 카테고리가 아니다.
   - `region_1`, `region_2`, 주소/좌표를 검색·필터에 사용한다.
5. 온라인/오프라인은 카테고리가 아니다.
   - 기존 `item_channels`의 channel 속성을 사용한다.
6. 한 실제 가게는 `places`에 한 번만 존재한다.
   - `item_places`의 place × category 관계로 같은 가게의 곱창/대창/막창을 서로 다른 원픽 후보로 만든다.
7. `picks_one_current_per_category`는 유지한다.

## 탐색 노출

`category_discovery_rules`는 “선택 가능한가?”가 아니라 “넓은 탐색 화면에 지금 보여줄 만큼 데이터가 쌓였는가?”만 결정한다.

- 규칙 없음 / `always`: 즉시 탐색 노출
- `threshold`: 설정한 조건을 만족하면 탐색 노출
- 초기 음식 세부 leaf 기본값: 공개 item 3개 **또는** active Pick 3개

중요: 임계치 전에도 leaf는 open/visible/pickable 상태를 유지한다.

따라서 다음은 계속 가능하다.

- 이름/별칭으로 카테고리 검색
- AI 카테고리 제안
- 직접 링크/등록 흐름
- 기존 사용자 프로필의 원픽 표시

다만 `browse_categories()`가 반환하는 넓은 탐색 카테고리 목록에서는 숨긴다. 데이터가 기준을 넘으면 코드 변경 없이 자동 노출된다.

## 기존 넓은 카테고리

기존 broad leaf가 이미 존재하는 경우(예: `회`)에는 삭제하거나 UUID를 바꾸지 않는다.

새 원픽과 새 place-backed item은 가능한 한 더 구체적인 leaf를 사용한다. 기존 데이터는 별도 검증 없이 자동 이동하지 않는다.

## 제철 추천

`category_seasons`는 카테고리의 월 범위와 편집 우선순위를 저장한다.

- 봄: 도다리회
- 여름: 민어회
- 가을: 전어회
- 겨울: 방어회

월 범위는 11월→2월처럼 연말을 넘길 수 있다.

`seasonal_category_recommendations(date, limit)`는 다음을 모두 만족하는 leaf만 반환한다.

1. 요청 날짜가 제철 범위 안
2. 현재 open/visible/pickable leaf
3. 탐색 노출 임계치 충족

즉 데이터가 없는 제철 카테고리를 홈/탐색에 억지로 노출하지 않는다.

## UI

탐색 화면 상단에 결과가 있을 때만 **제철 원픽** 섹션을 노출한다.

- 예: `전어회 · 가을 제철`
- 탭하면 기존 3단계 카테고리 선택 상태로 이동
- 별도의 “계절 카테고리” 트리는 만들지 않는다.

## 운영

세부 카테고리를 추가할 때:

1. 기존 broad leaf의 item/Pick을 확인한다.
2. 기존 데이터는 자동 이동하지 않는다.
3. 새 fine leaf를 추가한다.
4. 검색 별칭을 추가한다.
5. 데이터가 적으면 threshold discovery rule을 둔다.
6. 계절성이 명확한 경우에만 season metadata를 추가한다.
7. 데이터가 충분히 쌓이면 자동 탐색 노출을 사용하며, 필요 시 관리자가 rule을 조정한다.
