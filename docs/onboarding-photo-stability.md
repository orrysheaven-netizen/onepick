# 배포 전 안정화: 사용자명 복귀와 사진 처리 응답

## 사용자명/로그인 복구
- 원픽 선택에서 PROFILE_NOT_FOUND와 AUTH_REQUIRED를 일반 저장 실패와 구분하고 각각 사용자명 설정/재로그인 버튼을 제공한다.
- 기존 choose_pick 의도로 같은 상품/카테고리로 복귀한다. 원픽을 자동 저장하지 않으며 본문 초안, 파일 데이터, 인증 토큰을 URL에 넣지 않는다.
- 사진 업로드의 AUTH_REQUIRED도 기존 add_item_photo 의도로 로그인 후 같은 상품으로 복귀한다.
- 사용자명 폼은 계정과 검증된 복귀 의도별로 분리한다. 로그인 확인 중/실패 시 입력기를 숨기고 같은 계정의 일시 오류에서는 초안을 유지한다.
- 사용자명 저장에 동기적 단계 잠금을 적용해 첫 렌더 전 중복 전송을 막고 저장 중 편집을 막는다. 실패하면 다시 시도할 수 있다.
- 이전 계정/화면의 늦은 결과가 현재 화면을 이동시키지 않도록 마운트와 최신 세션을 확인한다. 저장 후 세션 확인이 잠시 실패하면 확인된 결과를 보관하고 복구 후 명시적인 계속 버튼을 제공한다.
- 생성 요청은 시작한 계정 ID를 저장 계층으로 전달하고 실제 인증 사용자와 비교한다. DB RLS는 그대로 유지한다.
- 응답 유실/동시 생성 후 다시 시도할 때 이미 존재하는 자신의 프로필은 반환한다. 다른 사용자의 이름은 여전히 거부한다. 이 처리는 새 사용자명으로 덮어쓰는 기능이 아니다.

## 사진 처리/상품 조회 실패
- 성공 응답을 받은 사진 요청은 재전송하지 않는다. 오래된 버튼 핸들러도 재업로드하지 않게 동기적으로 막는다.
- 뒤이은 상품 조회 실패 시 `사진 등록 요청은 처리됐어요`와 조회 재시도를 보여준다. 이것은 자신의 사진이 반드시 채택됐다는 뜻이 아니다. 먼저 등록된 이미지가 있을 경우 기존 이미지가 유지된다.
- 실패/권한변경 시 과거 상품 정보·사진·댓글·업로드 버튼은 표시하지 않는다. 처리 응답을 받았다는 안내만 유지하며 정상 조회를 통해 현재 상태를 확인한다.
- 상품 ID가 없는 링크의 비활성 조회는 로딩 중으로 표시하지 않는다. 로그인 확인 오류도 비활성 상품 조회의 로딩보다 먼저 처리한다.
- 실패한 사진 저장에서는 기존 미리보기와 확인 상태를 유지한다. 앱 종료 후 파일/초안 복원은 포함하지 않는다.

## 검증과 배포
- test-onboarding-photo-recovery.cjs를 소스 수정 전에 추가해 기존 오류를 재현한다. 기존 회귀 검사는 제거하지 않는다.
- 테스트는 실제 소스를 변환한 결정적 훅/컴포넌트 실행 및 저장 계층 모의 검사다. 실제 카카오 OAuth·기기 사진 선택·네트워크 DB 종단 간 검사를 수행한 것으로 간주하지 않는다.
- 같은 PR #11 및 기존 작업 브랜치를 유지한다. main 병합/운영 DB·사용자 데이터·호스팅 변경은 하지 않는다. 이전에 준비한 DB 마이그레이션의 운영 적용도 계속 보류한다.
- 기존 Cloudflare 주소의 배포와 실제 iPhone/Android 사용 검증, 공용 사진 오류 신고/정정, 의존성 취약점 영향 분석은 별도 완료 조건으로 남는다.
