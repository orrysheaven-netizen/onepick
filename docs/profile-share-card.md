# 프로필 공유 카드 이미지

상태: 반영됨(웹). `early-user-acquisition.md` 3.1을 이 문서로 구체화했고 설계대로 구현했다. `prelaunch-first-user-journey.md` 8단계의 공유 페이로드 계약도 함께 고쳤다. 네이티브 카드와 사진은 아래 범위 밖 그대로 남아 있다.

## 왜 이 형태인가

유입은 공개 프로필 링크를 받은 사람에게서 시작한다(`early-user-acquisition.md` 2·3.2). 그런데 지금 `프로필 공유하기`가 내보내는 것은 사용자명·현재 원픽 수·URL 세 줄뿐이다(`mobile/src/lib/share/shareProfile.ts`). 카카오톡과 인스타그램에서 이것은 열어볼 이유가 없는 링크 한 줄로 보인다.

원픽 단위 이미지 카드는 **이미 있다**(`mobile/src/lib/share/sharePickCard.web.ts`, 1080×1350 canvas). 없는 것은 프로필 단위 카드다. 유입 장치로 쓰이는 쪽은 원픽 하나가 아니라 취향 컬렉션 전체이므로, 이쪽이 비어 있는 것이 문제다.

그래서 새 렌더러를 만들지 않는다. 기존 카드의 캔버스 유틸을 공유 모듈로 올리고 프로필 카드가 같은 것을 쓴다. 캔버스 코드가 둘로 갈라지면 두 카드의 디자인이 조용히 어긋난다.

실제로 그럴 뻔했다. 작업 중 `main`에 브랜드 락업 변경(#154)이 들어와 원픽 카드만 새 락업과 한글 라벨로 바뀌었다. 락업도 `cardCanvas.ts`의 `drawBrandLockup()`으로 올려 두 카드가 같은 것을 그리게 했고, 영문 kicker는 카드에서 쓰지 않는다.

## 카드에 무엇을 담는가

한 장에 담을 수 있는 것은 많지 않다. 담는 기준은 "받은 사람이 링크를 열 이유"다.

- `@사용자명`
- 원픽 최대 4개. 카테고리명 + 상품명. 5개 이상이면 `외 N개`로 접는다.
- AI 평가 `summary` 한 줄. **조건을 만족할 때만** 넣는다(아래 공개 범위 참조).
- 하단에 프로필 URL 한 줄과 서비스 표시.

담지 않는 것과 이유.

- **한줄평은 넣지 않는다.** 원픽 카드가 이미 한줄평 중심이다(`WHY THIS ONE`). 프로필 카드까지 문장을 채우면 4개를 읽기 전에 카드가 끝난다. 프로필 카드는 목록이고 원픽 카드는 문장이다.
- **취향 구성 비율은 넣지 않는다.** `ProfileTasteComposition.dimensions`의 백분율은 그림으로 보면 그럴듯하지만, 캔버스에 차트를 그리는 비용 대비 "이 사람이 뭘 골랐는가"보다 덜 궁금하다. 필요해지면 별도 검토한다.
- **사진은 넣지 않는다(1차).** 아래 참조.

## 사진을 넣지 않는 이유

프로필 사진과 상품 사진은 Supabase 스토리지에서 온다. 외부 origin 이미지를 캔버스에 그리면 캔버스가 오염되어 `toDataURL()`이 보안 오류로 실패한다. 즉 **카드 생성 자체가 실패한다.**

- 우회하려면 이미지에 `crossOrigin="anonymous"`를 걸고 스토리지가 CORS 헤더를 내려줘야 하며, 헤더가 빠지거나 캐시된 응답이 헤더 없이 돌아오는 경우까지 처리해야 한다.
- 결정: 1차는 타이포그래피만 쓴다. 기존 원픽 카드도 같은 구성이므로 일관된다. 사진은 스토리지 CORS 동작을 먼저 확인한 뒤 별도로 붙인다. 붙일 때도 이미지 로딩 실패가 카드 생성을 막지 않아야 한다.

## 사용자 이용 / UX

공개 프로필(`mobile/src/app/(tabs)/(home,explore,notifications,profile)/u/[username].tsx`)과 내 프로필의 공유 진입점은 지금처럼 **버튼 하나**로 둔다. 이미지/텍스트 선택을 사용자에게 묻지 않는다.

동작 순서:

1. 카드 이미지를 만든다.
2. `navigator.share({ files })`가 가능하면 이미지와 URL을 함께 보낸다.
3. 파일 공유가 안 되면 이미지를 내려받고, **같은 흐름에서 URL을 클립보드에 복사한 뒤 안내한다.** 이미지만 저장되고 링크가 사용자 손에 없으면 공유가 끊긴다. 지금 원픽 카드의 다운로드 폴백에 빠져 있는 지점이다.
4. 카드 생성 자체가 실패하면(`IMAGE_CARD_UNSUPPORTED` 포함) 조용히 기존 텍스트 공유로 넘어간다. 오류 문구를 새로 띄우지 않는다. 공유 실패가 아니라 형태가 달라진 것뿐이다.

`url`을 무시하는 공유 대상이 있으므로 `text`에도 URL을 포함한다. 이미지 안의 URL은 눌리지 않는다는 것을 전제로 설계한다.

기존 `shareError` 처리는 유지한다. 4단계까지 모두 실패한 경우에만 표시한다.

## 앱 구동 / 프런트

- `sharePickCard.web.ts`의 `wrapLines` / `splitLongToken` / `roundedRect` / `drawLines` / `dataUrlFile` / `downloadCard` / `clean`을 `src/lib/share/cardCanvas.web.ts`로 옮기고 두 카드가 같이 쓴다. 원픽 카드의 렌더 결과는 바뀌지 않아야 한다.
- 프로필 카드는 `shareProfileCard.web.ts` / `shareProfileCard.ts`(네이티브 stub) 쌍으로 둔다. 원픽 카드와 같은 플랫폼 분기 방식이다.
- 네이티브는 이번 범위가 아니다. 현재 `sharePickCard.ts`와 같이 `IMAGE_CARD_UNSUPPORTED`를 던지고 텍스트 공유로 떨어진다. 테스터 배포가 웹(Cloudflare Pages)이므로 웹이 먼저다.
- 카드는 **화면이 이미 조회한 데이터로만** 그린다. 카드 생성을 위해 추가 조회를 하지 않는다. 공유 버튼이 새 네트워크 요청을 기다리지 않아야 한다.
- 폰트는 원픽 카드와 같이 `system-ui`를 쓴다. 웹폰트를 로드해 캔버스에 쓰면 로드 타이밍에 따라 폴백 폰트로 렌더되는 카드가 섞인다.
- 카드 크기는 1080×1350으로 원픽 카드와 맞춘다.

## 공개 범위 / 개인정보

카드는 **새로운 공개 경로가 아니다.** 서버가 임의 프로필의 카드를 렌더하는 엔드포인트를 만들지 않는다. 그리면 차단·정지·비공개를 우회하는 조회 통로가 된다. 카드는 클라이언트가 이미 RLS를 통과해 받은 데이터로만 그린다.

AI 평가 `summary`는 다음을 **모두** 만족할 때만 넣는다.

- `ProfileAiComment.isVisible === true` — 공개하지 않기로 한 평가가 이미지로 나가면 되돌릴 수 없다. 이미지는 회수되지 않는다.
- `ProfileAiComment.isStale === false` — 오래된 평가는 카드에 함께 찍힌 현재 원픽 목록과 어긋난다.
- 값이 비어 있지 않다.

하나라도 어긋나면 AI 줄 없이 원픽 목록만으로 카드를 만든다. AI가 없다고 카드 생성을 막지 않는다. AI 평가가 아직 없는 사용자도 공유할 수 있어야 한다.

파일명에는 사용자명만 쓴다(`onepick-<사용자명>.png`). 원픽 카드와 같이 허용 문자 외에는 치환한다.

## 검증

구현에서 추가한 회귀 검사는 `mobile/scripts/test-profile-share-card.cjs`이며, 아래 목록을 모두 덮는다. 원픽 카드 렌더 회귀는 기존 `test-share-card.cjs`가 유틸 추출 후에도 같은 출력을 확인한다.


- `prelaunch-first-user-journey.md` 8단계의 기대값을 바꾼다. 현재 계약은 "공유 페이로드에 공개 프로필 URL과 현재 픽 수가 들어간다"이다. 새 계약은 "이미지 파일 공유가 가능하면 파일과 URL이, 아니면 URL이 사용자 손에 남는다"이다. `scripts/test-first-user-prelaunch.cjs`를 함께 고친다.
- 새 회귀 검사에서 확인할 것:
  - AI가 비공개(`isVisible === false`)일 때 카드 텍스트에 summary가 없다.
  - AI가 stale일 때 summary가 없다.
  - 원픽이 5개 이상일 때 4개 + `외 N개`로 접힌다.
  - 원픽이 0개여도 카드가 만들어진다.
  - 파일 공유 불가 시 URL이 클립보드에 복사된다.
  - 카드 생성 실패 시 텍스트 공유가 호출된다.
- 원픽 카드 렌더 회귀: 유틸을 옮긴 뒤 기존 원픽 카드 출력이 바뀌지 않는지 확인한다.
- 긴 상품명, 공백 없는 긴 토큰, 이모지가 섞인 사용자명에서 줄바꿈을 확인한다. 기존 `splitLongToken`이 처리하는 경우와 같다.

## 구현하며 정한 것

설계에 없던 것 두 가지를 구현 중에 정했다.

### 단일 행은 `wrapLines`로 그릴 수 없다

`wrapLines(ctx, value, maxWidth, maxLines)`는 마지막 허용 줄을 **항상** 잘린 것으로 표시한다(끝 글자를 지우고 `…`를 붙인다). `maxLines`가 2 이상이면 대개 실제로 넘칠 때만 걸리지만, `maxLines = 1`에서는 짧은 문자열도 무조건 한 글자를 잃는다. `@tester`가 `@teste…`가 된다.

프로필 카드는 사용자명·카테고리·상품명을 각각 한 줄로 그리므로 전부 여기에 걸렸다. `cardCanvas.ts`에 `fitLine()`을 따로 두고, 실제로 폭을 넘을 때만 `…`를 붙인다. `wrapLines`는 원픽 카드의 렌더 결과를 바꾸지 않기 위해 그대로 둔다.

### 다운로드 폴백의 반환값을 셋으로 나눈다

`shared` / `downloaded-with-link` / `downloaded`. 마지막 값은 "이미지는 저장했지만 링크는 사용자 손에 없다"는 뜻이고, 이때만 화면이 기존 텍스트 공유를 이어서 연다. 클립보드 복사가 거부되는 환경(권한 거부, 비보안 컨텍스트)에서도 링크가 반드시 전달된다.
