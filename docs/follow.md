# 아는 사람의 원픽을 먼저 보는 팔로우

상태: **프로필 팔로우는 MVP 노출 / 피드·알림은 분리 보류** — 2026-10-02 사용자 결정으로 공개 프로필의 팔로우/팔로잉 CTA를 노출한다. 비로그인 → 로그인 → 원 프로필 복귀 → 1회 자동 팔로우(#491)를 사용한다. 홈 팔로잉 전용 피드와 followee 원픽 변경 알림·설정·푸시는 계속 숨긴다. 공개 팔로워/팔로잉 수·목록은 #645·#647 완료 후 노출한다.

## 현재 MVP 노출 정책

- 공개 홈은 전체 음식·오프라인 원픽 피드만 사용한다. 기존 follow 관계가 있어도 팔로잉 피드로 자동 전환하지 않는다.
- 공개 프로필에서 Follow 버튼을 노출한다. 비로그인 사용자는 기존 로그인 시트를 거쳐 원 프로필로 복귀한 뒤 1회 자동 팔로우한다.
- 홈의 `팔로잉 / 전체` 전환과 팔로잉 전용 피드는 노출하지 않는다.
- Settings에서 “팔로우한 사람의 원픽 변경” 설정을 노출하지 않고 관련 preference query도 시작하지 않는다.
- follow 관계·피드 RPC·알림 원천·서비스/컴포넌트 코드는 삭제하지 않는다. 표면별 feature gate로 분리해 독립 롤아웃한다.
- 공개 팔로워/팔로잉 수·목록은 기존 RLS를 열지 않고 sanitized RPC(#645)와 connections 화면(#647)으로 제공한다.

## 왜 필요한가
- 홈은 모르는 사람의 최신 원픽을 시간순으로 보여준다. 사용자가 늘수록 낯선 사람의 이유를 읽을 동기가 약해진다. 아는 사람의 이유는 읽는다.
- 원픽은 카테고리당 1개라 한 사람을 팔로우해도 받는 신호가 카테고리 수를 넘지 않는다. 피드가 넘치지 않고 "지민 님이 헤드폰 원픽을 바꿨어요" 같은 저빈도·고신호 알림이 성립한다. 다른 SNS의 팔로우와 다른 원픽만의 형태다.
- 팔로우 자체는 작다. 어려운 것은 앱 안에서 친구를 찾게 하는 일이다. 프로필 공유 링크가 없으면 팔로잉 피드는 비어 있다. 팔로우와 프로필 공유는 한 묶음으로 낸다.

## 사용자 이용 / UX
- 현재 MVP 목표 흐름: 공유 링크나 피드에서 다른 사용자 프로필로 들어온다 → 그 사람의 원픽을 본다 → 팔로우한다 → 팔로잉 관계로 저장해 다시 찾는다. 홈 팔로잉 전용 피드는 후속 롤아웃이다.
- 프로필 상단에 `팔로우` / `팔로잉` 토글 버튼. 단방향이며 요청/승인이 없다. 본인 프로필에는 표시하지 않는다.
- **후속:** 홈 `팔로잉 / 전체` 전환과 팔로잉 전용 피드는 현재 MVP에서 노출하지 않는다. 구현은 별도 gate 뒤에 유지한다.
- **후속:** 팔로잉 피드 빈 상태와 전체 탭 전환은 팔로잉 피드 롤아웃 때 사용한다.
- 프로필 `공유` 버튼: 프로필 딥링크를 OS 공유 시트로 보낸다. 비로그인으로 열면 둘러보기 가능, 팔로우는 기존 로그인 복귀 의도로 연결한다.
- **후속:** 팔로우한 사람의 원픽 변경 알림과 설정은 현재 MVP에서 노출하지 않는다.
- 공개 프로필에는 팔로워/팔로잉 수를 표시하고, 숫자를 누르면 팔로워/팔로잉 목록으로 이동한다(#645·#647). 이 수치는 인기순 정렬이나 추천 점수에는 사용하지 않는다.
- 팔로우당한 사람에게는 알림을 보내지 않는다(초기). 팔로우 해제는 조용히 처리한다.
- 차단하면 양방향 팔로우가 모두 해제되고 다시 팔로우할 수 없다. 계정 삭제 시 관계도 삭제된다.

## 앱 구동 / 프런트
- `FollowService`(신규) → `ReadRepository.getFollowState` / `WriteRepository.follow` / `unfollow` → `user_follows` 테이블. 프로필 화면의 버튼 상태는 낙관적 갱신 후 실패 시 되돌린다.
- 홈 팔로잉 탭: `HomeService.getHomePicks`에 `scope: 'all' | 'following'`을 추가하고 기존 `home_pick_feed_page` 대신 `home_following_feed_page` RPC를 호출한다. 카드 키는 기존과 같이 Pick ID. 캐시는 계정별 `people-v1`과 분리한 `following-v1`로 두고, 팔로우/해제 시 무효화한다.
- 알림: 기존 `notificationService`에 원픽 변경 알림 종류를 추가하고 댓글 알림과 같은 목록에 시간순으로 섞어 보여준다. 읽음 처리는 기존 방식.
- 프로필 딥링크: 기존 프로필 라우트(`/profile/[username]` 계열)를 그대로 쓰며 웹/네이티브 링크 처리만 추가한다. 새 경로를 만들지 않는다.
- 설정 화면에 "팔로우한 사람의 원픽 변경 알림" 스위치를 추가한다.

## 백엔드 / 공개 범위
- `public.user_follows(follower_id, followee_id, created_at)`, PK (follower_id, followee_id), `follower_id <> followee_id` 제약, 두 컬럼 모두 `profiles(id) on delete cascade`. 역방향 조회용 인덱스 `(followee_id, follower_id)`.
- RLS: select/insert/delete는 `follower_id = auth.uid()`인 행만. followee 쪽 조회는 본인 팔로워 수 RPC로만 노출한다. `user_blocks`와 같이 insert 트리거에서 `auth.uid()` 일치, 자기 자신 금지, 대상 프로필 존재, `private.users_blocked` 양방향 확인, 정지 계정 여부를 검사한다.
- `user_blocks` insert 트리거(또는 별도 after 트리거)에서 두 방향의 `user_follows` 행을 삭제한다. 차단 해제해도 팔로우는 복구하지 않는다.
- `home_following_feed_page(p_before_time, p_before_id)`: `home_pick_feed_page`와 같은 반환 컬럼, 같은 공개 조건(active 원픽, active/discontinued 상품, 정지되지 않은 등록자, 공개·선택 가능한 말단 카테고리), 같은 커서(`started_at desc, id desc`), 20개 + lookahead 1개. 여기에 `exists (select 1 from user_follows f where f.follower_id = auth.uid() and f.followee_id = p.user_id)`만 추가한다. SECURITY INVOKER, 검색 경로 고정, 사용자 ID를 인자로 받지 않는다. 비로그인 호출은 빈 결과.
- `follow_counts()`: 기존 호출자 본인 전용 계약은 유지한다. 공개 프로필 수·목록은 원본 `user_follows` RLS를 열지 않고 #645의 별도 sanitized RPC로 제공한다.
- 알림 테이블 `public.pick_change_notifications(pick_id, recipient_id, created_at, read_at)`: 댓글 알림과 같은 "참조만 저장, 텍스트 사본 없음" 원칙. `picks` insert 및 status가 active로 바뀔 때 trigger가 팔로워 전원에게 행을 만든다. 한줄평 수정은 트리거 대상이 아니다. 읽기 정책에서 차단·정지·비공개 조건을 다시 검사해 저장 이후 상태 변화도 숨긴다.
- 알림 팬아웃 상한: 팔로워가 많은 계정의 원픽 변경 한 번이 큰 insert가 되므로 트리거는 `limit`을 두거나(예: 1,000) 그 이상은 배치 처리로 넘긴다. 초기 규모에서는 트리거 직접 insert로 충분하다.
- 알림 설정은 `notification_preferences(user_id, followee_pick_change)` 본인 행으로 두고 트리거에서 확인한다. 행이 없으면 켜짐이다. `profiles`는 공개 조회가 가능해 설정을 두지 않는다.
- 관리자 RLS 예외를 포함한 기존 정책은 바꾸지 않는다. 신고/정지 흐름은 그대로이며 정지된 계정의 원픽은 팔로잉 피드에서도 빠진다.

## 하지 않는 것
- 맞팔 요청/승인, 비공개 계정, 인기순 정렬.
- 팔로우 추천, 연락처 동기화, 인기순 정렬, 추천 알고리즘.
- 팔로우당했을 때 알림(수요가 확인되면 추가).
- 다른 상품을 골랐을 때 상대에게 알림을 보내는 것(기존 원칙 유지).

## 검증 / 배포
- DB 테스트: 자기 팔로우 금지, 타인 명의 insert 금지, 차단 시 양방향 해제, 차단 상태 팔로우 금지, 정지 계정 제외, 팔로잉 피드의 자기 제외·커서 동률·삭제 후 다음 페이지, 비로그인 빈 결과, 알림이 한줄평 수정에는 생기지 않음, 차단 후 기존 알림 숨김.
- 앱 테스트: 팔로우 버튼 낙관적 갱신과 실패 복구, 팔로잉 탭 빈 상태 3종(팔로우 없음 / 원픽 없음 / 로드 실패), 팔로우·해제 후 캐시 무효화, 알림 목록에 댓글 알림과 섞여 시간순 정렬, 설정 스위치 반영.
- 두 계정 검증(`two-user-validation.md`): A가 B 프로필 링크로 진입 → 팔로우 → B가 원픽 변경 → A 알림 수신 → A 팔로잉 탭에 반영 → A가 B 차단 → 팔로우·알림·피드에서 모두 사라짐.
- 측정: 가입 후 7일 내 1명 이상 팔로우한 비율, 팔로우 유무별 7일/30일 리텐션, 팔로잉 탭에서 시작된 원픽 등록 수. 팔로우 비율이 낮으면 병목은 프로필 공유 유입이다.
- 마이그레이션은 Git에 준비하고 CI·독립 리뷰·dry-run 후 **사용자 별도 승인**이 있을 때만 Production에 적용한다. 홈 `전체` 탭은 변경하지 않으므로 구버전 클라이언트 영향은 없다.
