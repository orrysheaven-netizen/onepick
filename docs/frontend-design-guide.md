# OnePick 프론트엔드 디자인 가이드 (초안)

작성일: 2026-09-30 · 작성: Claude · 상태: **초안 — PM/UX 검토 전**

이 문서는 `docs/design-foundations.md`(Foundations v1)를 **앱 코드에서 어떻게 적용하는지** 정리한 실무 가이드입니다. 방향은 "토스처럼 명확하고 깔끔하게"입니다. 토스의 브랜드(파란색, 서체, 아이콘)가 아니라 **원칙**만 빌려옵니다.

- Foundations와 이 문서가 다르면 **Foundations가 우선**합니다.
- 이 문서는 새 화면·새 기능을 만들지 않습니다. 현재 UI 안정화 단계(`docs/shared-working-rules.md` §3)의 **기존 화면 통일**에 씁니다.
- 라우팅·인증 의도·딥링크·입력 상태·로딩/오류/빈 상태·저장 동작 같은 기능 계약은 바꾸지 않습니다.
- §11의 "결정 필요" 항목은 사용자 결정 전까지 적용하지 않습니다.

---

## 1. 다섯 가지 원칙

| # | 원칙 | 화면에서 뜻하는 것 |
| --- | --- | --- |
| 1 | **한 화면, 한 가지 일** | 화면마다 사용자가 할 일은 하나. 주 버튼(`Button` primary)은 화면당 하나. |
| 2 | **제목이 먼저 말한다** | 첫 줄 제목만 읽어도 이 화면에서 뭘 하는지 알 수 있게. 입력 화면은 질문형("어떤 메뉴를 등록할까요?"). |
| 3 | **덜어내서 정돈한다** | 선·그림자·아이콘·색을 더하기 전에 여백과 글자 굵기로 먼저 구분. |
| 4 | **중요한 것만 진하게** | 한 영역에 진한 글자(`text/primary` + Bold)는 하나. 나머지는 `text/secondary`·`text/tertiary`. |
| 5 | **막히지 않게** | 빈 상태·오류·비활성 버튼에는 항상 이유와 다음 행동이 있다. |

## 2. 화면 뼈대

### 2.1 공통

- 좌우 여백은 `OnePickSpace.gutter`(16). 화면마다 20·24를 따로 쓰지 않습니다.
- 섹션 사이 `OnePickSpace.xxxl`(32), 섹션 제목과 내용 사이 `md`(12), 같은 묶음 안 요소 사이 `sm`(8).
- 최대 폭은 `OnePick.maxWidth`(480). 웹 넓은 화면에서도 가운데 한 줄 레이아웃을 유지합니다.
- 배경은 한 화면에 한 가지. 카드로 감싸는 대신 여백으로 묶는 것을 먼저 시도합니다.

### 2.2 화면 유형별 패턴

**A. 입력 단계 화면** (원픽 등록, 온보딩, 프로필 편집)

```
┌ Header (56) : ‹  [가운데 제목]  [텍스트 동작] ┐
│ Page Title  "어떤 메뉴를 등록할까요?"          │  ← 질문형, 1~2줄
│ Body/secondary  한 줄 도움말 (필요할 때만)      │
│                                               │
│ Field Label + Input                           │
│ …                                             │
├───────────────────────────────────────────────┤
│ [          주 버튼 · 가로 채움 · 52          ] │  ← 하단 고정, 좌우 16, 아래 safe area + 16
└───────────────────────────────────────────────┘
```

- 한 단계에 입력은 가능한 한 하나. 이미 여러 개인 화면을 쪼개는 것은 기능 변경이므로 이 가이드 범위 밖입니다.
- 키보드가 올라오면 하단 버튼도 키보드 위로 따라 올라와야 합니다.
- 필수 입력이 비어 있으면 주 버튼은 `disabled`. 왜 비활성인지 입력칸 아래 Caption으로 알려 줍니다.

**B. 목록·피드 화면** (홈, 탐색, 알림)

- 맨 위는 `App Header`(메인 탭) 또는 `Header`(하위 화면).
- 섹션은 `SectionHeader`(Headline + 오른쪽 "전체보기" 같은 이동 링크).
- 행(List Row·Notification Row 등)은 터치 영역 최소 높이 56, 행 사이 구분선 대신 여백을 먼저 씁니다. 구분선이 필요하면 `border/default` 1px, 좌우 gutter 안쪽에서 시작.

**C. 상세 화면** (상품 상세, 공개 프로필)

- 가장 위에 대상(이름·사진)과 핵심 숫자 1개. 부가 정보는 아래로.
- 행동 버튼은 하나를 주 버튼으로, 나머지는 `secondary`·`ghost`.

**D. 완료·결과**

- 짧은 완료는 `Toast`(하단 가운데, 2초 내외). 화면 전환이 필요한 완료만 결과 화면을 씁니다(새 화면 추가 금지 — 기존 화면 안에서 처리).

## 3. 글자

Foundations의 7개 스타일(`OnePickType`)만 씁니다. `fontSize`를 직접 쓰지 않습니다.

현재 앱에는 9~48px 사이 **30가지 이상**의 크기가 직접 쓰여 있습니다(2026-09-30 `app/`·`components/` 기준, 12·13·14px가 가장 많음). 화면을 통일할 때 아래처럼 옮깁니다.

| 지금 쓰는 크기 | 옮길 스타일 | 비고 |
| --- | --- | --- |
| 9–11 | `caption`/`captionMedium` (12) | 12 미만 글자는 쓰지 않음 |
| 12–13 | `caption`/`captionMedium` (12) | 메타·시간·라벨 |
| 14–15 | `body`/`bodyMedium` (14) | 본문·버튼 |
| 16–18 | `headline` (16) | 카드·헤더 제목 |
| 19–21 | `title` (20) | 섹션 제목 |
| 22–28 | `pageTitle` (22) | 화면 첫 줄 제목 |
| 30 이상 | 글자가 아니라 **아이콘**으로 교체 | 예: 뒤로가기 `‹`를 36px 글자로 그린 곳(`app/ranking/*`, `app/provider/*`) → `Header` 컴포넌트 |

- 굵기는 400·500·700만. 800·900 금지.
- 강조는 크기보다 **굵기와 색**으로. 한 줄 안에서 크기를 섞지 않습니다.
- 숫자(원픽 수 등)는 `headline` 이상 + Bold로 두고, 단위("명", "개")는 같은 줄의 `caption`/`text/secondary`로 붙입니다.

## 4. 색

### 4.1 규칙

- 화면 코드에 헥스 값을 쓰지 않습니다. `OnePick.*` 역할 토큰만 씁니다.
- 새로 고치는 코드는 **Foundations 역할 이름**(`bgDefault`, `textSecondary` …)을 씁니다. 기존 이름(`muted`, `accent` …)은 화면 통일 때 함께 옮깁니다.
- 탠저린(`bgAccent`)은 로고 점·테마 선택·강조 면에만. **탠저린 위 글자와 탠저린 작은 글자는 쓰지 않습니다.**
- 주 버튼·선택된 칩은 잉크(`actionPrimary`).
- 상태색(`danger`·`success`·`warning`)은 상태를 알릴 때만. 장식으로 쓰지 않습니다.
- 파랑·인디고는 OnePick 색이 아닙니다(토스 파랑을 빌려오지 않음). 예외: 카카오·Apple 로그인 버튼.

### 4.2 기존 토큰 → Foundations 토큰

| 기존 | Foundations | 주의 |
| --- | --- | --- |
| `text` | `textPrimary` | 값 같음 |
| `muted` (#5C5C63) | `textSecondary` (#6B6E78) | 약간 밝아짐. 흰 바탕 대비 4.5:1 이상 유지 확인 |
| `hint` | `textTertiary` | 본문에 쓰지 않음 |
| `accent`·`accentDeep` (글자로 쓸 때) | `textPrimary` | 링크도 잉크 |
| `accent` (면으로 쓸 때) | `actionPrimary` | |
| `accentSoft` | `bgAccentSubtle` | |
| `surface` | `bgDefault` | |
| `sunken` | `bgMuted` | |
| `background` (#FAFAF7) | `bgDefault` (#FFFFFF) | **보이는 변화.** 화면 단위로만 옮기고 일괄 치환 금지 |
| `border` | `borderDefault` | |
| `danger` (글자) | `textDanger` | |

기존 이름 사용이 약 900곳이므로 **일괄 찾아 바꾸기는 하지 않습니다.** 화면 하나를 통일할 때 그 화면 안의 이름만 옮깁니다.

## 5. 모서리·간격·그림자

- 모서리: `OnePickRadius.sm 8`(태그·썸네일) · `md 12`(버튼·입력) · `lg 16`(카드·팝업) · `xl 24`(시트) · `full`(칩·아바타). 기존 `small`·`card`·`pill`은 화면 통일 때 옮깁니다.
- 간격: `OnePickSpace`의 4·8·12·16·20·24·32만. 6·10·14 같은 값은 가장 가까운 토큰으로.
- 그림자는 쓰지 않습니다(팝업·시트 제외). 면 구분은 `bgSubtle`/`bgMuted` 배경이나 `borderDefault`로.

---

## 6. 컴포넌트

화면에서 `View`·`Text`·`Pressable`로 버튼·칩·빈 상태를 다시 만들지 않고 `@/components/ui`를 씁니다.

| 쓰임 | 쓸 것 | 규칙 |
| --- | --- | --- |
| 화면의 주 행동 | `Button` primary | 화면당 하나. 하단 고정일 때 `fullWidth` |
| 보조 행동 | `Button` secondary | 주 버튼 옆·아래 |
| 카드 안 가벼운 행동 | `Button` soft | 예: "나도 이게 원픽" |
| 텍스트 링크 | `Button` ghost | 본문과 왼쪽 정렬 |
| 삭제·탈퇴 | `Button` danger + `Confirm Dialog` | 되돌리기 어려우면 반드시 확인 |
| 선택 필터 | `Chip` | 선택 = 잉크 채움 + `accessibilityState.selected` |
| 섹션 제목 | `SectionHeader` | |
| 빈 상태·오류 | `StateCard` | 제목 + 설명 + 다음 행동 버튼 |
| 원픽 한 건 | `PickCard` | |
| 사람 | `Avatar` | |

Foundations에 있지만 코드 공용 컴포넌트가 아직 없는 것: `Header`, `Input`/`Field Label`, `List Row`, `Toast`, `Dialog`. 같은 모양이 화면마다 따로 그려져 있으므로(예: 뒤로가기 글자 버튼), 화면 통일 PR에서 **처음 필요한 화면과 함께** 만들고 다른 화면은 순서대로 옮깁니다. 공용 컴포넌트만 먼저 대량으로 만들지 않습니다.

## 7. 상태 화면

| 상태 | 보여줄 것 | 하지 말 것 |
| --- | --- | --- |
| 로딩 | 자리를 잡아 두는 회색 틀(`bgMuted`) 또는 가운데 작은 로딩 표시. 0.3초 안에 끝나면 아무것도 띄우지 않음 | 화면 전체를 흰색으로 비워 두기 |
| 빈 상태 | 왜 비었는지 + 다음 행동 버튼 (`StateCard`) | "데이터가 없습니다"만 쓰기 |
| 오류 | 무슨 일인지 + 사용자가 할 수 있는 것("다시 시도") | 에러 코드·영문 메시지 노출 |
| 비활성 버튼 | 왜 누를 수 없는지 입력칸 근처에 한 줄 | 이유 없이 회색 버튼만 두기 |
| 저장 중 | 버튼 `loading` (중복 누름 막음) | 버튼과 별개로 전체 화면 로딩 |
| 완료 | `Toast` 한 줄 | 확인 버튼이 있는 팝업 |

## 8. 문구 (UX 라이팅)

1. **해요체**로 씁니다. "~습니다", "~하시겠습니까?"는 쓰지 않습니다.
2. **짧게.** 한 문장에 한 가지 정보. 버튼은 2~6자 동사("등록하기", "다시 시도").
3. **능동·긍정형.** 할 수 없는 것보다 할 수 있는 것을 먼저.
4. **사용자의 말로.** 내부 용어(provider, 채널, 승인 대기 상태값)를 화면에 쓰지 않습니다.
5. **탓하지 않기.** "잘못 입력하셨습니다" 대신 "다시 확인해 주세요".

| 지금 | 바꾸면 |
| --- | --- |
| 신고할 콘텐츠를 찾을 수 없습니다. | 이미 삭제된 글이에요. |
| 내 콘텐츠는 신고할 수 없습니다. | 내 글은 신고할 수 없어요. |
| 저장에 실패했습니다. | 저장하지 못했어요. 다시 시도해 주세요. |
| 삭제하시겠습니까? | 이 원픽을 삭제할까요? |
| 확인 / 취소 | 삭제하기 / 그대로 두기 (무엇을 하는지 버튼에) |

- 관리자 화면(`app/admin`, `components/admin`)은 운영자용이므로 이 규칙을 강제하지 않습니다.
- 문구 변경도 기능 계약에 닿을 수 있습니다(예: 약관·개인정보 안내). 법적 문구는 바꾸지 않습니다.

## 9. 누름·움직임

- 누를 수 있는 것은 최소 44×44. 작은 아이콘은 `hitSlop`으로 넓힙니다.
- 누름 피드백은 공용 `Button`과 같이 투명도 0.9. 비활성만 0.6.
- 움직임은 200ms 안팎, 목적이 있을 때만(시트 올라오기, 토스트). 장식용 애니메이션은 넣지 않습니다.
- 스크롤 위치·입력값은 화면을 오가도 유지합니다(기존 동작 보존).

---

## 10. 접근성

- 글자 대비 4.5:1 이상(큰 제목 3:1). `textTertiary`는 본문에 쓰지 않습니다.
- 누를 수 있는 요소에 `accessibilityRole`과 이름. 아이콘만 있는 버튼은 `accessibilityLabel` 필수.
- 선택·비활성·로딩은 색만이 아니라 `accessibilityState`로도 알립니다.
- 글자 크기 확대 시 잘리지 않게 고정 높이 대신 `minHeight`.

---

## 11. 결정 필요 (적용 보류)

토스 방식을 더 따르려면 Foundations를 바꿔야 하는 항목입니다. **사용자 결정 전에는 적용하지 않습니다.**

| 제안 | 이유 | 비용·위험 |
| --- | --- | --- |
| Page Title 22 → 24 | 질문형 제목의 존재감. 토스 계열은 제목을 크게 씀 | Foundations·Figma 동시 수정 필요, 긴 제목 줄바꿈 증가 |
| 섹션 구분용 굵은 회색 띠(높이 8~12, `bgSubtle`) | 선 없이 섹션을 나누는 토스식 구분 | 새 토큰 1개, 홈·상세 레이아웃 변화 |
| 누름 피드백을 살짝 작아지기(scale 0.97)로 | 더 또렷한 누름 느낌 | 공용 컴포넌트 전체 동작 변화, 테스트 기대값 수정 |
| 화면 배경 `#FAFAF7` → `#FFFFFF` 일괄 전환 시점 | Foundations는 흰 배경이지만 코드는 아직 종이색 | 전 화면 시각 변화. 화면 통일 순서에 맞춰 하는 편이 안전 |

---

## 12. 화면 통일 PR 체크리스트

- [ ] 화면에 헥스 값·직접 `fontSize`·임의 간격(6·10·14 등)이 남아 있지 않다
- [ ] 주 버튼이 하나다
- [ ] 첫 줄 제목만으로 화면 목적을 알 수 있다
- [ ] 빈 상태·오류·비활성 버튼에 이유와 다음 행동이 있다
- [ ] 문구가 해요체이고 내부 용어가 없다
- [ ] 누를 수 있는 요소가 44×44 이상이고 접근성 이름이 있다
- [ ] 라우팅·인증·딥링크·입력 상태·저장 동작이 그대로다
- [ ] 390px 폭과 웹 480px 폭 둘 다 스크린샷으로 확인했다
