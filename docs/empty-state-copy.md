# 빈 상태 문구 기준 (Empty State Copy)

OnePick 전체 공통 기준. Figma `OnePick Social UI`와 앱 문구를 같은 표로 관리한다.
UX 라이팅 공통 규칙(해요체, 짧고 직접적으로, 가운데 점 금지, 사용자 책임 전가 금지)과 다이얼로그 `닫기` 규칙은 그대로 적용한다.

## 유형별 원칙

| 유형 | 원칙 | 예 |
| --- | --- | --- |
| 1. 다음 행동이 자연스러운 빈 상태 | 현재 상태 + 다음 행동을 함께, 짧게. CTA는 기존 경로가 있을 때만 | `첫 원픽을 골라보세요.` |
| 2. 검색 결과 없음 | 결과가 없다는 사실을 먼저 명확히 알린 뒤 다른 검색어 안내 | `‘라면탕’ 검색 결과가 없어요.` + `다른 검색어로 찾아보거나 …` |
| 3. 오류·권한·제한·삭제 | 긍정형으로 바꾸지 않고 정확한 상태 + 가능한 해결 행동 | `알림을 불러오지 못했어요.` + `다시 불러오기` |
| 4. 행동할 수 없는 빈 상태 | CTA를 억지로 넣지 않고 상태만 짧고 명확하게 | `아직 알림이 없어요.` |

새 빈 상태를 만들 때는 공용 `StateCard`(앱) / `Empty State`(Figma Foundations)를 쓰고, 버튼은 기존 Button 컴포넌트만 사용한다. 원래 없던 이동 경로를 새로 만들지 않는다.

## CTA 추가를 보류한 화면 (UX 변경이라 관리자 결정 필요)

- 탐색(31)·전체 피드(`feed.tsx`)·인기(`popular.tsx`)·랭킹(`ranking/*`)의 원픽 0 상태: 원픽 등록 버튼을 넣을 수 있지만 집계 화면에 등록 진입점을 새로 만드는 것은 UX 변경.
- 내 팔로잉 0: `관심 있는 사람을 팔로우해보세요` 문구만 적용. 사람 찾기 화면이 없어 CTA 미추가.
- 알림 0, 차단 사용자 0, 다른 사용자 프로필 원픽 0: 사용자가 직접 해결할 수 없는 상태라 CTA 없음(정책 유지).
