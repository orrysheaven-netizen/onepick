# 사람의 취향을 먼저 보는 홈

## 사용자 이용 / UX
- 목표 흐름: 다른 사람의 원픽과 이유를 읽는다 → 같으면 같은 상품을 내 원픽으로 선택한다 → 다르면 같은 카테고리에서 다른 상품을 찾는다.
- 카드 상단: 실제 등록자의 프로필 사진/사용자명. 이어서 카테고리, 상품 사진/이름, 등록자의 한줄평을 표시한다.
- `나도 이게 원픽`: 기존 상품 선택 화면으로 이동한다. 사용자가 자신의 한줄평을 쓰고 저장해야 실제 등록/변경한다. 홈 버튼은 쓰기 요청을 보내지 않으며 타인의 이유를 복사하지 않는다.
- 이미 같은 상품을 선택한 경우 `이미 내 원픽이에요`로 표시하고 내 한줄평으로 이동한다. 다른 상품을 골랐다면 변경 안내 후 기존 선택 절차를 이용한다.
- `나는 다른 원픽`: 해당 카테고리의 기존 검색/선택 화면으로 이동한다. 새 제품 생성으로 우회하지 않는다. 없는 상품의 기존 관리자 승인 요청 흐름은 유지한다.
- `의견 나누기`: 상품 상세에서 해당 작성자의 원픽 한줄평/댓글을 지정해 연다.
- 팔로우/싫어요/추천 알고리즘/선택 알림을 추가하지 않는다. 다른 선택은 상대방에게 반대 알림을 보내지 않는다.
- 비로그인도 둘러보고 다른 상품을 찾을 수 있다. 같은 상품 저장은 기존 로그인 복귀 의도로 연결한다.

## 앱 구동 / 프런트
- HomeService → 기존 ReadRepository의 getHomePicks → home_pick_feed_page RPC → useHomeData → 기존 홈 화면.
- 조회와 카드 키는 상품 ID가 아니라 Pick ID다. 같은 상품을 고른 여러 사람의 서로 다른 이유를 각각 보존한다.
- 로그인한 자신의 카드는 홈 둘러보기에서 제외하고 내 원픽/프로필 접근은 유지한다.
- 계정별 people-v1 캐시로 기존 집계 상품 캐시와 분리한다. 기존 원픽/사진 작업의 home 캐시 갱신을 그대로 사용한다.
- 사진 없는 상품의 공통 사진 등록 진입점, 댓글 알림 버튼, 프로필 연결, 로딩/빈 상태/다음 페이지 재시도를 유지한다.

## 백엔드 / 공개 범위
- 신규 RPC는 SECURITY INVOKER, 검색 경로 고정, 20개 + lookahead 1개. 기존 공개/차단 RLS를 적용하며 클라이언트의 로그인 세션으로 호출한다.
- active 원픽, active/discontinued 상품, 정지되지 않은 등록자, 공개·선택 가능한 말단 카테고리와 유효한 상위 카테고리만 조회한다.
- 현재 인증 사용자는 서버 auth.uid()로 결정하고 자기 원픽을 제외한다. 사용자 ID를 외부 인자로 받아 다른 계정의 피드를 가장하지 않는다.
- started_at DESC, id DESC 커서로 시간 동률도 안정적으로 넘긴다. 한줄평 편집은 선택 시각을 바꾸지 않아 홈 상단으로 밀어올리지 않는다.
- 홈에서 기존 최소 선택 인원 조건은 사용하지 않는다. 원픽 하나만 등록되어도 공개 조건에 맞으면 카드로 보여준다. 기존 집계 RPC/설정은 구버전 호환용으로 유지한다.
- 관리자 권한의 RLS 예외를 포함한 기존 정책은 바꾸지 않는다. 일반 사용자 간 차단은 DB 회귀 검사로 확인한다.

## 검증 / 배포
- 홈 서비스/화면/연속 조회 테스트를 새 사람 중심 계약으로 변경하며 기존 개인정보·세션·오류 복구 검사를 유지한다.
- 023_people_home_feed.sql은 사람별 카드, 자기 제외, 인기 기준 미적용, 커서 동률, 삭제 후 다음 페이지, 사진 필드, 차단/정지/비공개 제외를 CI 임시 DB에서 검사한다.
- 기존 사진 등록/자기소개와 같은 PR #11에 누적한다. main과 기존 Cloudflare 배포 브랜치는 바꾸지 않는다.
- 신규 마이그레이션은 Git에만 준비하고 운영 DB에는 적용하지 않는다. 사이트 단일화 및 실제 모바일 검증 전까지 현재 주소의 반영 완료로 안내하지 않는다.
