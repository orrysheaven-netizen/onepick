# 원픽 구매처 링크와 쇼핑꿀팁

상태: 단계적 롤아웃 — `picks.purchase_url` / `purchase_tip`, `shopping_domains`, `is_shopping_url`, 확장된 `change_pick` / `update_pick_review`가 구현되어 있고, 홈 피드가 링크·팁을 읽어 `쇼핑꿀팁`과 구매처 호스트를 표시하도록 준비했다. 사용자 입력 UI는 `OnePickFeatures.purchaseLinks`로 계속 닫아 두며, 피드 migration 적용 확인 후 별도 단계에서 연다. `register_pick` 경로와 프로필 카드 표시는 아직이다. `pick-themes.md`의 1단계(선택형 테마 라벨)를 이 설계로 대체한다.

## 왜 이 형태인가

`pick-themes.md`는 쇼핑꿀팁·애정템·취향템 중 하나를 등록할 때 고르게 하자는 제안을 검토하고, 세 갈래를 한 줄에 세우지 않기로 했다. 남은 문제는 그래서 등록 화면에 아무것도 나타나지 않는다는 것이었다.

이 설계는 그 자리를 **자기보고가 아니라 행동**으로 채운다.

- 애정템과 취향템은 "내 마음이 어느 쪽인가"를 묻는 것이라 사용자가 구분하지 못할 수 있다. 그래서 묻지 않는다.
- 쇼핑꿀팁은 다르다. "남에게 쓸모 있는 구매 정보가 있는가"는 사용자가 스스로 안다. 그리고 그 존재는 **링크를 남기는 행동**으로 드러난다.
- 이것은 `pick-themes.md`가 "쇼핑꿀팁은 사람이 아니라 정보에 대한 라벨"이라며 테마 목록에서 뺀 결론과 같은 이야기다. 입력이 다르니 자리도 다르다.

이 설계는 쇼핑꿀팁 축만 답한다. 애정템과 취향템은 여전히 미해결이며, 이 기능으로 알 수 없다.

## 도메인만 보고 테마를 정하지 않는다

"쇼핑몰 링크면 쇼핑꿀팁으로 자동 적용"은 틀리게 붙는다. 링크를 거는 이유가 둘인데 도메인은 그것을 구분하지 못한다.

- 여기서 싸게 사세요 — 꿀팁이다.
- 이게 정확히 그 제품이에요 — 단순 식별이다. 실제로는 이쪽이 더 흔하다.

10년째 쓰는 애정템도 대형 쇼핑몰에서 팔린다. 자동 적용하면 그 원픽이 쇼핑꿀팁이 되고, 사용자는 왜 그렇게 됐는지도 어떻게 되돌리는지도 모른다. 틀린 라벨이 조용히 쌓이는 쪽이 라벨이 없는 것보다 나쁘다.

결정: 도메인은 **언제 물어볼지**만 정한다. 무엇인지는 사용자가 정한다.

## 사용자 이용 / UX

목표 흐름: 원픽을 고른다 → 한줄평을 쓴다 → (선택) 산 곳 링크를 붙인다 → 쇼핑몰이면 한 번 확인받고 팁을 남긴다 → 저장한다.

- 기존 선택 화면(`/pick/choose`)의 한줄평 아래에 `제품 링크 (선택)` 입력을 둔다. 비워도 저장된다. 저장 실패 사유를 늘리지 않는다.
- 링크를 넣으면 그 자리에서 한 줄 묻는다: "여기서 살 때 알아두면 좋은 게 있나요?" → `있어요` / `그냥 제품 링크예요`. 기본값은 후자다.
- `있어요`를 고르면 팁 입력 칸이 열린다. 1~100자로 한줄평과 같은 제한을 쓴다. 팁을 채워야 쇼핑꿀팁으로 표시된다.
- **구현에서 바뀐 점**: 질문을 쇼핑몰 도메인일 때만이 아니라 **링크가 있으면 항상** 띄운다. 도메인 목록을 앱이 받아 캐시하는 경로와 그 조회 실패 처리를 통째로 없앨 수 있고, 목록에 없는 쇼핑몰·단축 URL이 다르게 취급되지 않는다. 대가는 제조사 페이지를 링크한 사람도 질문을 한 번 본다는 것인데, 답은 한 번의 탭이다. `shopping_domains`와 `is_shopping_url`은 남되 화면 분기가 아니라 아래 측정에 쓴다. 이 때문에 `살 때 팁 남기기` 수동 진입도 필요 없어졌다.
- 링크를 붙이지 않으면 확인 단계도 팁 칸도 나타나지 않는다. 링크를 쓰지 않는 사용자의 등록 흐름은 지금과 같다.
- 홈 카드: 팁이 있으면 `쇼핑꿀팁` 배지와 팁 한 줄을 한줄평 아래에 보여준다. 팁이 없고 링크만 있으면 구매처 호스트만 작게 보여준다. 프로필 카드 표시는 후속 범위다.
- 링크는 전체 URL이 아니라 **도메인만** 표시한다(`coupang.com`). 긴 URL은 화면을 망가뜨리고, 도메인 표시는 어디로 가는지 먼저 보게 한다.
- 링크는 외부 브라우저/새 탭으로 연다. 앱 안에서 쇼핑몰을 감싸 보여주지 않는다.
- 원픽을 바꾸면 링크와 팁도 함께 끝난다. 링크만 고치는 것은 한줄평 편집과 같은 자리에서 한다.

## 링크 정책

이 기능의 실제 위험은 링크 자체가 아니라 **제휴 링크**다. 열어두면 자기 리퍼럴 코드를 붙인 원픽이 쌓이고, 나중에 막으려면 이미 저장된 링크를 전부 손봐야 한다. 기능과 같은 PR에서 정한다.

- 저장 전에 추적·제휴 파라미터를 제거한다. `utm_*`, `gclid`, `fbclid`와 주요 쇼핑몰의 제휴 파라미터를 거부 목록으로 둔다.
- 제거는 **DB 쪽에서** 한다(쓰기 RPC 또는 트리거). 클라이언트에서만 하면 API를 직접 호출해 우회할 수 있다.
- 거부 목록이지 허용 목록이 아니다. 상품 식별 파라미터가 쇼핑몰마다 달라 허용 목록은 정상 링크를 깨뜨린다. 새 파라미터는 마이그레이션으로 추가한다. 이 한계를 인정하고 간다.
- `https`만 받는다. 길이는 2048자로 제한한다.
- 서버는 사용자가 넣은 URL을 **가져오지 않는다**. 미리보기 제목·썸네일을 만들지 않는다. 임의 URL을 서버가 요청하면 내부망 접근 통로가 된다.
- 단축 URL은 펼치지 않는다(같은 이유). 쇼핑몰로 판별하지 않으며, 수동 진입으로 팁을 남길 수 있다.
- 기존 신고 기능에 링크 사유를 추가한다. 관리자 화면에서 링크가 보이고 링크만 지울 수 있어야 한다.
- 제휴 링크 금지를 등록 화면 안내와 약관에 함께 적는다. `commercialization-rights-gate.md`의 점검 대상에 이 기능을 추가한다.

## 앱 구동 / 프런트

- 화면은 쇼핑몰 판별에 기대지 않는다(위 "구현에서 바뀐 점"). 링크 형식만 앞에서 확인하고, 진짜 검사는 DB가 한다.
- 링크와 팁 인자는 **넘기지 않으면 그대로 두고, 빈 문자열이면 지운다**. 화면이 저장된 링크를 아직 읽어오지 않으므로, 손대지 않은 입력은 값을 보내지 않아야 한줄평만 고친 저장이 링크를 조용히 지우지 않는다.
- 화면 → 훅 → 서비스 → 리포지토리 → Supabase 경계를 그대로 쓴다. 링크와 팁은 기존 `choosePick` 쓰기에 필드로 얹고 새 쓰기 경로를 만들지 않는다.
- 한줄평만 고쳤을 때와 마찬가지로, 링크·팁 편집은 선택 시각을 바꾸지 않는다. 홈 상단으로 다시 올라오지 않는다.

## 백엔드 / 공개 범위

- 상품이 바뀌면 이전 구매처는 그 선택의 것이 아니므로 새 원픽으로 이어받지 않는다. 바뀌기 전 원픽의 기록에는 남는다.
- `picks.purchase_url text`(nullable). 사람마다 다른 "내가 산 곳"이므로 픽에 붙는다. 제품 공용 공식 링크인 `products.official_url`과 다른 필드이며 서로 덮어쓰지 않는다.
- `picks.purchase_tip text`(nullable, 1~100자). 팁이 있으면 `purchase_url`도 있어야 한다는 제약을 둔다.
- **테마 컬럼을 새로 만들지 않는다.** 쇼핑꿀팁 표시는 `purchase_tip is not null`에서 파생한다. 라벨과 내용이 어긋날 수 없고, 되돌릴 때 지울 것이 적다.
- `picks_one_current_per_category`는 바꾸지 않는다. 링크는 원픽을 늘리지 않는다.
- 기존 픽은 두 값 모두 null로 두고 소급 입력하지 않는다.
- 쇼핑몰 도메인 목록은 `shopping_domains` 테이블로 두고 관리자만 쓸 수 있게 한다(`taste_dimensions`와 같은 RLS 형태). 앱 배포 없이 목록을 고칠 수 있어야 한다.
- 매칭은 호스트 정확 일치 또는 명시한 접미사 항목으로만 한다. 상위 도메인을 통째로 쇼핑몰로 보지 않는다(쇼핑몰이 아닌 서비스가 같은 도메인에 있다).
- 홈 RPC(`home_pick_feed_page`, `home_following_feed_page`)의 공개 조건과 커서 규칙은 바꾸지 않는다. 링크와 팁은 반환 필드 추가로만 붙인다. 기존 차단·정지·비공개 제외가 그대로 적용된다. `home_pick_feed_page`를 drop/recreate할 때 기존 `service_role` 실행 권한도 명시적으로 보존한다.

## 이 설계가 답하는 것

등록 화면에 기능이 생기면서 측정값이 함께 생긴다. `pick-themes.md`의 0단계(한줄평 표본의 kappa)는 이 수치로 대체한다. 실제 등록 행동이라 표본 수가 적어도 읽을 수 있다.

- 링크 첨부율 — 전체 원픽 중 링크를 남긴 비율.
- 그중 쇼핑몰로 판별된 비율.
- 확인 단계에서 `있어요`를 고른 비율. **쇼핑꿀팁이 실제로 존재하는 성격인지 답하는 값이다.** 이 값이 바닥이면 쇼핑꿀팁은 원픽에 없는 축이고, 팁 기능을 접는다.
- 수동 진입으로 팁을 남긴 건수 — 도메인 목록이 부족하다는 신호.
- 팁 내용 표본 점검. 실제로 구매에 쓸모 있는 정보인지, 그냥 한줄평을 한 번 더 쓴 것인지.

## 비목표

- 가격 추적, 최저가 비교, 재고·할인 알림을 만들지 않는다.
- 제휴 수익을 받지 않는다. 제휴 파라미터는 저장 시 제거한다.
- 링크 미리보기(제목·썸네일)를 서버가 가져오지 않는다.
- 테마 컬럼을 만들지 않는다. 애정템·취향템 선택지를 등록 화면에 넣지 않는다.
- 쇼핑꿀팁을 홈 정렬이나 추천 가중치에 쓰지 않는다. 홈은 계속 시간순이며 인기 기준을 쓰지 않는다.
- 링크 유무로 원픽을 더 위에 보여주지 않는다. 링크를 남기도록 압박하는 배지·점수·순위를 두지 않는다.
- 링크를 필수로 만들지 않는다.

## 검증 / 배포

- DB 회귀 검사: 파라미터 제거가 클라이언트를 우회한 쓰기에도 적용되는지, `https` 아닌 스킴과 길이 초과 거부, 팁만 있고 URL이 없는 행 거부, 도메인 목록의 관리자 전용 쓰기, 일반 사용자 간 차단·정지·비공개 제외가 링크 필드에도 적용되는지.
- 앱 회귀 검사: 링크 없이 저장, 쇼핑몰 판별 시 확인 단계 표시, `그냥 제품 링크예요`를 고르면 팁이 저장되지 않음, 도메인 목록 조회 실패 시 저장이 막히지 않음, 카드의 도메인 표시.
- 마이그레이션은 Git에만 준비하고 운영 DB 적용은 기존 절차를 따른다.
- `pick-themes.md`의 1단계를 이 문서로 대체한다는 줄을 그쪽에 남긴다.
