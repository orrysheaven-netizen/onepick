# OnePick 맛집 MVP 기반 설계

상태: 구현 계약 초안  
기준일: 2026-09-22  
대상: 첫 공개 MVP

## 1. 제품 정의

OnePick 맛집 MVP는 일반적인 맛집 검색/리뷰 서비스가 아니다.

> 전국을 기준으로 음식 카테고리마다 내가 가장 좋아하는 곳 하나를 기록하고,
> 다른 사람의 원픽 맛집 리스트를 팔로우하는 서비스.

핵심 제약은 기존 OnePick과 동일하다.

- 사용자 × 선택 가능한 세부 카테고리당 현재 원픽은 정확히 최대 1개다.
- 지역은 카테고리가 아니다. 주소/검색/필터 속성이다.
- 같은 음식 카테고리를 오프라인 맛집과 온라인 구매 대상이 공유한다.
- 리스트에서 맛집/아이템을 누르면 외부 사이트가 아니라 OnePick 내부 상세 페이지로 이동한다.
- 원픽 등록 유도는 카드의 주 CTA가 아니다. 필요할 때만 작은 보조 컨트롤을 둔다.
- 팔로우는 MVP 핵심 기능이다. 홈과 프로필에서 사람의 취향 리스트를 따라가는 구조를 우선한다.

현재 DB의 `picks_one_current_per_category` 유니크 인덱스는 이 규칙과 맞으므로 유지한다.

## 2. 화면 계약

### 홈

기본 사회적 흐름은 팔로잉이다.

- 팔로잉 사용자의 현재 원픽/변경을 최신순으로 보여준다.
- 카드의 주 클릭 영역: OnePick 내부 아이템 상세로 이동.
- 작성자 프로필: 사용자 프로필로 이동.
- 원픽 등록: 작은 보조 버튼만 제공. 대형 `나도 원픽` CTA는 사용하지 않는다.
- 전체 공개 피드는 보조 탭/탐색 수단으로 둘 수 있지만 팔로잉과 역할을 섞지 않는다.

기존 `home_following_feed_page`의 현재 원픽 조건과 차단/정지 필터는 유지한다.

### 프로필

프로필은 **맛집(FOOD) 원픽을 먼저 보여주고, 나머지 테마는 '실험실'로 분리한 취향 컬렉션**이다 (2026-09-26 결정).

> **극초기 MVP 갱신 (2026-10-10, #879 [6097734198](https://github.com/orrysheaven-netizen/onepick/issues/879#issuecomment-6097734198), #757/#826)** — 아래 2026-09-26 항목보다 우선한다.
> - 내 프로필·공개 프로필 원픽 목록, 헤더 `원픽 N`, 공유 카드는 **오프라인 식당 + 온라인 주문 음식**만 담는다.
>   판정은 `isMvpProfilePick`(`OnePickMvp.browseGroupSlug` 조상 상속 + `OnePickMvp.profileFoodChannels`) 하나를 쓴다.
> - 레시피(레시피 카테고리 하위 또는 recipe 채널)·비맛집 테마·매핑 없는/조상을 알 수 없는 원픽은 목록에 나오지 않는다.
>   channel이 없는 legacy 원픽은 `private.default_pick_channel`과 같은 순서(아이템 채널 offline→online→recipe, 없으면 online)로 판정한다.
> - 음식/기타 칩과 프로필의 실험실 진입은 숨긴다. 원본 데이터·실험실 화면·통계·RLS는 그대로이며, `원픽 N`은 첫 페이지가 아닌 같은 범위 전체 개수다.
> - '이전 원픽 기록'(기록 탭)은 제한 예외로 유지한다.

- 프로필 본문: FOOD 테마 원픽만 **오프라인 맛집 / 온라인 맛집 / 레시피**로 나눠 표시한다.
  테마를 알 수 없는(매핑 없는) 원픽도 본문에 남긴다.
- 실험실(`/lab/[username]`): CULTURE & ART·TECH·STYLE·LIVING 원픽. 프로필 본문 아래 "실험실" 한 줄과
  탐색 하단 입구(`/lab` → 내 실험실)로 들어간다. 원픽은 숨기거나 지우지 않고 실험실에서 그대로 보인다.
- 공개 프로필은 실험실 원픽이 있을 때만 입구를 보여주고, 공유 카드에는 FOOD 원픽만 담는다.
- `OnePickFeatures.lab`(메인 테마 `OnePickMvp.mainThemeCode`)을 끄면 모든 테마가 다시 프로필 본문에 함께 표시된다.

- 팔로우/언팔로우
- 초기 MVP에서는 팔로워/팔로잉 수를 노출하지 않음
- FOOD 현재 원픽 + 실험실 입구
- 한줄평
- 공유
- 기존 원픽 공유 링크와 이전 원픽 기록 유지

MVP 맛집 노출 제한을 적용하는 surface:

- 홈
- 탐색
- 온보딩 (실험실 테마 카테고리는 제안하지 않음)
- 신규 원픽 등록의 기본 진입/추천 (카테고리를 지정하지 않은 검색에서 실험실 테마 결과 제외)
- 프로필 본문 (실험실 테마는 실험실 화면으로 이동)

MVP 맛집 노출 제한을 **적용하지 않는** surface:

- 실험실 화면과 그곳에서 시작한 카테고리 지정 등록
- 기존 원픽 공유 링크
- 이전 원픽 기록
- AI 취향평가의 공개 원픽 입력

따라서 영화·책·게임·음악 같은 기존 카테고리를 `is_visible=false` 또는 `status=paused`로 바꿔 MVP에서 숨기지 않는다.
맛집 우선 노출은 앱 레벨 surface 정책으로 처리하며, 프로필 조회(서비스·RPC)에는 restaurant-only category filter를 넣지 않는다. 본문/실험실 분리는 화면에서 테마(`category_taste_dimensions`, 조상 상속)로 한다.

지역별로 같은 카테고리 원픽을 여러 개 만들지 않는다.

### 아이템 상세

- 매장/아이템 이름
- 세부 카테고리
- 대표 이미지
- 오프라인이면 지점/주소/지도 정보
- 온라인이면 주문/공식 링크
- 해당 아이템을 현재 원픽으로 둔 사람과 한줄평
- 작은 원픽 등록/변경 컨트롤
- 외부 링크는 상세 화면 안에서만 보조 액션으로 제공

## 3. 카테고리 원칙

현재 3단계 트리 계약을 유지한다.

```
먹을것(root, non-pickable)
  └─ 분류(group, non-pickable)
      └─ 세부 음식(leaf, pickable)
```

채널이나 지역을 트리에 넣지 않는다.

잘못된 예:

```
먹을것 → 서울 → 곱창
먹을것 → 오프라인 → 곱창
먹을것 → 온라인 → 곱창
```

올바른 예:

```
먹을것 → 고기 → 곱창
먹을것 → 고기 → 대창
먹을것 → 고기 → 막창
```

곱창 카테고리 하나를 오프라인 매장과 온라인 판매 아이템이 함께 사용한다.

### 세분화 기준

카테고리는 사용자가 실제로 “이 중 하나만 고른다면?”이라고 답할 수 있을 정도로 세분화한다.

- 곱창과 대창은 별도
- 평양냉면과 함흥냉면은 별도
- 돼지국밥과 순대국은 별도
- 소갈비와 돼지갈비는 별도
- 초밥과 회는 별도
- 소금빵과 베이글은 별도

반대로 지역, 가격대, 분위기, 목적은 카테고리로 만들지 않는다.

- 서울/부산/제주: 필터
- 데이트/회식/혼밥: 태그 후보
- 가성비/고급: 태그 후보
- 온라인/오프라인: 채널 속성

### 기존 데이터 보호

- 기존 category UUID/slug는 가능한 한 유지한다.
- 실사용 데이터가 있는 카테고리를 이름만 보고 분할/이동하지 않는다.
- 특히 `ramen`은 현재 카탈로그와 픽이 있으므로 변경하지 않는다.
- 광범위한 기존 말단을 더 세분화할 때는 item/pick 수를 먼저 확인한다.
- 데이터가 없는 광범위 말단은 필요하면 paused/hidden 처리하고 더 좁은 말단으로 대체한다.
- 카테고리를 삭제해서 과거 픽 FK를 깨지 않는다.

## 5. 온라인 / 오프라인 공용 모델

`items`는 영화/책/게임/음악 등 모든 OnePick 도메인이 공유한다.
따라서 주소/위도/경도 같은 맛집 전용 컬럼을 `items`에 직접 계속 추가하지 않는다.

### 제안 A: item_channels

하나의 item이 어떤 채널에서 존재하는지 표현한다.

```text
item_channels
- item_id        FK items(id)
- channel        offline | online
- target_url     nullable
- is_primary
- created_at
- updated_at
```

한 아이템이 오프라인 매장이면서 온라인 주문도 지원할 수 있으므로 단일 `item_type` 컬럼보다 다중 채널 관계가 안전하다.

### 제안 B: places + item_places

물리적 지점 자체는 `places`에 한 번만 저장한다.

```text
places
- id
- name
- branch_name
- road_address
- address
- region_1
- region_2
- latitude
- longitude
- place_provider
- provider_place_id
- map_url
- is_visible
- created_at
- updated_at

unique(place_provider, provider_place_id)
```

그리고 카테고리별 OnePick 후보인 `items`와 장소를 `item_places`로 연결한다.

```text
item_places
- item_id
- category_id
- place_id
- created_at

primary key(item_id)
unique(place_id, category_id)
foreign key(item_id, category_id) -> items(id, category_id)
```

이 분리가 필요한 이유는 한 물리적 맛집이 여러 세부 음식 카테고리의 후보가 될 수 있기 때문이다.

예:

```
OO곱창 강남점 (place 1개)
  ├─ 곱창 category item
  └─ 대창 category item
```

사용자는 곱창과 대창에서 각각 원픽을 고를 수 있지만, 두 item은 같은 내부 맛집 상세의 장소 정보를 공유한다.

반대로 같은 상호라도 실제 지점이 다르면 다른 place다.

- OO곱창 강남점
- OO곱창 부산점

### 외부 식별자

현재 `items.external_source + external_id`에는 전역 unique 제약이 있다. 따라서 실제 장소 provider identity를 category item마다 그대로 복제하면 한 장소를 여러 카테고리에 연결할 수 없다.

맛집 MVP에서는 다음처럼 분리한다.

- 실제 장소 identity: `places.place_provider + provider_place_id`
- category item의 내부 identity: `items.external_source='onepick_place'`
- category item의 `external_id`: `<place_uuid>:<category_uuid>`
- 같은 place + 같은 category는 하나의 item만 허용한다.
- 같은 place + 다른 category는 다른 item이지만 같은 `places.id`를 공유한다.
- 같은 이름 + 다른 provider place id는 별도 place/item으로 허용한다.
- 일반 온라인 상품의 이름 중복 판정과 place-backed item의 이름 중복 판정은 서로 간섭하지 않는다.
- 다중 지도 제공자 identity가 실제로 필요해질 때 별도 `place_external_refs`로 확장한다.

## 6. 반드시 해결해야 할 P0: 동일 상호 다른 지점

현재 일반 상품 등록 경로에는 같은 카테고리에서 동일한 `normalized_name`을 찾으면 기존 item을 돌려주는 경로가 있다.

물리적 매장에서는 이것이 안전하지 않다.

예:

```
사용자 A: OO곱창 강남
사용자 B: OO곱창 부산
```

상호명이 같다는 이유만으로 같은 item으로 합쳐지면 다른 사업장을 원픽하게 된다.

따라서 오프라인 맛집 등록을 공개하기 전에 다음을 구현한다.

1. 오프라인 등록은 장소 provider + place id를 먼저 확보한다.
2. 중복 검사는 이름이 아니라 안정적 장소 identity로 한다.
3. 같은 이름/다른 place id는 별도 item으로 허용한다.
4. 같은 place id는 기존 item을 재사용한다.
5. provider identity를 얻지 못한 수동 등록은 pending 상태에서 관리자 확인을 거친다.
6. 승인되지 않은 수동 장소는 원픽 대상으로 만들지 않는다.

이 조건을 만족하기 전에는 오프라인 등록 UI를 열지 않는다.

## 7. 원픽 불변식

온라인/오프라인을 분리하더라도 현재 원픽 제약을 풀지 않는다.

예:

```
카테고리: 곱창

OO곱창 강남점 (offline)
XX푸드 한우곱창 (online)
```

한 사용자가 둘을 동시에 현재 원픽으로 가질 수 없다.

현재 유니크 키:

```
(user_id, category_id) WHERE status IN ('active','needs_review')
```

를 유지한다.

채널은 “어디에서 소비하는가”이고 카테고리는 “무엇에 대한 원픽인가”다.

## 8. 팔로우 계약

이미 존재하는 `user_follows`, `home_following_feed_page`,
팔로워 원픽 변경 알림 구조를 MVP 핵심으로 승격한다.

유지할 보안/가시성 규칙:
- 자기 자신 팔로우 불가
- 차단 관계의 팔로우 제거/재생성 방지
- 정지된 계정 제외
- 홈 팔로잉 피드에서 자기 픽 제외
- 팔로우 취소 즉시 피드 제외
- 팔로우가 없어도 전체 공개 피드로 자동 fallback하지 않는다

추가 UX:
- 프로필의 팔로우 버튼을 주요 액션으로 둔다.
- 로그인 사용자의 홈 기본 탭/첫 피드는 팔로잉이다. 팔로잉이 비어 있어도 전체 공개 피드로 자동 전환하지 않고, 사용자가 `전체` 탭을 직접 선택한다.
- 초기 MVP에서는 팔로워/팔로잉 수를 보여주지 않는다. 관계 수치보다 “이 사람이 고른 맛집 리스트”가 중심 콘텐츠다.

## 9. 링크 계약

사용자 요구에 따라 리스트/카드의 핵심 링크는 내부 상세 페이지다.

- 카드/사진/매장명 → OnePick item detail
- 지도/예약/주문/공식 홈페이지 → item detail 안의 외부 링크
- 작은 원픽 등록 버튼은 카드 이동과 분리한다.
- 외부 URL을 카드 전체 press action으로 쓰지 않는다.

## 10. 지역 계약

전국 단위 원픽을 유지한다.

지역 필드:
- region_1: 시/도
- region_2: 시/군/구
- 주소/좌표

지역은 탐색 필터에 사용한다.

예:
- 전국
- 서울
- 경기
- 부산
- 제주

하지만 `서울 곱창`, `부산 곱창` 같은 별도 pick category는 만들지 않는다.

## 11. DB/RLS 원칙

새 public 테이블을 만들 때:

- RLS 활성화
- 필요한 role에만 명시적 grant
- 공개 읽기 범위와 관리자 쓰기 범위를 분리
- 일반 사용자가 장소 identity를 임의로 확정하지 못하게 한다
- pending 제출과 승인된 canonical place를 분리한다
- admin 권한은 기존 MFA 기반 관리자 판정과 같은 정책을 사용한다
- 새 함수는 가급적 security invoker를 사용한다
- definer가 꼭 필요하면 private schema와 명시적 execute 권한을 사용한다

## 12. 필요한 회귀 테스트

DB:
1. user × fine category 현재 원픽 1개 유지
2. 같은 카테고리에서 online → offline 변경 시 기존 픽 replaced
3. 같은 이름 + 다른 place id가 다른 item
4. 같은 place id가 중복 item을 만들지 않음
5. place identity 없는 오프라인 item은 승인 전 pick 불가
6. region 변경이 category/pick identity를 바꾸지 않음
7. item_places 공개 읽기/RLS
8. 관리자만 canonical place identity 수정 가능
9. 기존 라면/영화/책 등의 검색과 원픽 회귀 없음

앱:
1. 맛집 카드 탭 → 내부 상세
2. 작은 원픽 컨트롤이 카드 이동과 독립
3. 팔로우/언팔로우 즉시 홈 피드 반영
4. 지점명이 다른 동일 상호를 검색 결과에서 구분
5. 주소와 지역 표시
6. 온라인/오프라인이 같은 카테고리 화면에 함께 노출될 수 있음
7. (2026-10-10 극초기 갱신으로 대체) 내 프로필/공개 프로필은 오프라인 식당 + 온라인 주문 음식만 표시하고, 영화·책·게임·음악 등 기존 원픽은 삭제 없이 보존됨

## 15. 첫 구현 PR의 완료 조건

첫 DB 구현 PR은 아래를 모두 만족해야 한다.

- 장소는 상호명만으로 dedupe하지 않는다.
- 동일 상호의 서로 다른 지점을 동시에 저장할 수 있다.
- 동일 place identity의 중복 생성은 막는다.
- 세부 카테고리당 전국 원픽 1개 제약은 유지된다.
- 온라인/오프라인이 같은 category id를 공유한다.
- 기존 팔로우 피드/차단/정지 규칙이 깨지지 않는다.
- 기존 라면 원픽과 외부 콘텐츠 카탈로그가 깨지지 않는다.
- DB tests와 앱 회귀 테스트가 통과한다.
