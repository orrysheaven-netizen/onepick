# OnePick Social UI v5 기준선

상태: **구현 전 기준 문서 / Figma 16~31 검토용**

Figma v5 시안 16~31은 이 문서의 제품 원칙을 먼저 만족한 뒤 구현한다. 시안의 배치나 장식 요소가 아래 원칙과 충돌하면 코드보다 이 문서를 먼저 갱신해 결정을 남긴다.

## 1. 제품 성격

OnePick은 게시물 중심 SNS가 아니라 **사람이 지금 하나를 고른 상태와 그 이유**를 보는 서비스다.

- 한 Pick의 글은 한줄평 하나다.
- 좋아요/하트와 좋아요 수를 만들지 않는다.
- 타인의 Pick을 그대로 따라 고르는 `나도 이게 원픽`을 핵심 행동으로 두지 않는다.
- 원픽의 선택 시각이나 `새로 고름`, `○○에서 바꿈` 같은 변화 상태를 카드에 표시하지 않는다.
- 변화는 팔로워 알림으로 전달한다. 한줄평 수정만으로는 새 알림을 만들지 않는다.

## 2. 홈

기본 정보 위계:

```text
사람
[채널] 제공처
메뉴
“한줄평”
긍정 상태(해당할 때만) · 댓글 · 공유
```

- 로그인 사용자의 최초 피드 범위는 팔로잉 수가 1명 이상이면 `팔로잉`, 0명이면 `전체`다.
- 이후 사용자가 직접 선택한 탭은 count 재조회로 덮어쓰지 않는다.
- `✓ 내 원픽`은 같은 item + 같은 Pick channel일 때만 표시한다.
- `원픽 아님`이나 과거 선택을 암시하는 상태는 표시하지 않는다.
- 피드 정렬은 `started_at desc`를 유지하지만 시각은 화면에 노출하지 않는다.

## 3. 상품 상세과 댓글

- 현재 이 상품이 원픽인 사람의 한줄평에만 `✓ 이 집 원픽`을 표시한다.
- ended Pick의 한줄평에는 `이전 원픽`, `현재 선택이 종료된 한줄평`, `원픽 아님`을 표시하지 않는다.
- 현재 Pick 한줄평을 먼저, ended 한줄평을 뒤에 둔다.
- 원픽이 끝나도 그 상품 상세의 한줄평과 기존 댓글은 제품 기준상 유지한다.
- 댓글 작성자도 현재 원픽이 **같은 item + channel**일 때만 이름 옆에 `✓ 이 집 원픽`을 표시한다.
- 댓글은 작성자가 삭제하지 않는 한 남는다.
- 과거 원픽은 프로필/활동 기록으로 노출하지 않는다. 본인도 동일하다.

ended Pick thread 공개와 삭제, 댓글 작성자의 current-Pick match 데이터는 DB/RLS 보호영역이다. #448의 Claude 후속 계약이 완료되기 전에는 앱이 추측해서 표시하지 않는다.

## 4. 메뉴 랭킹

홈 메뉴 랭킹은 누적 인기 대신 **최근 7일 rolling window**를 쓴다.

- 제목 예: `이번 주 많이 고른 메뉴`.
- 숫자는 최근 7일 안에 그 메뉴를 현재 원픽으로 고른 **사람 수**다.
- 한 사람이 여러 채널에서 같은 메뉴를 현재 원픽으로 갖더라도 사람 수는 1명이다.
- 메뉴 자체는 계속 보여도 숫자는 3명 이상일 때만 표시한다. 기준은 `exploreRankingMinPicks`와 맞춘다.
- 홈 `전체 보기`에서 탐색으로 이동하면 원픽 많은 순으로 진입한다.
- #446의 DB 계약이 리뷰·병합·배포되기 전에는 최근 7일 숫자를 임의 계산하거나 누적 랭킹으로 대체하지 않는다.

## 5. 테마 전환

MVP의 주 테마는 맛집이다.

- 두 번째 테마에 실제 콘텐츠가 충분히 쌓이기 전에는 테마 전환 버튼을 주요 CTA처럼 보이게 하지 않는다.
- 필요하면 작고 비활성처럼 보이는 상태로 두되, 사용자가 눌러도 동작하지 않는 컨트롤은 접근성상 버튼 역할을 부여하지 않는다.
- 콘텐츠가 준비된 뒤 활성 전환 UX를 별도 결정한다.

## 6. 구현 원칙

- Figma 프레임 번호만 보고 데이터 의미를 새로 만들지 않는다.
- 현재 데이터로 정확히 판정할 수 없는 배지/숫자는 추측하지 않는다.
- DB/RLS 변경이 필요한 항목은 Claude 보호영역으로 분리하고 Codex 앱 PR과 섞지 않는다.
- 앱 변경은 한 PR에 한 책임으로 분리한다.
- v5 구현 전 이 문서를 기준으로 프레임별 차이를 먼저 목록화한다.

## 7. v5 구현 전 체크

- [ ] 카드에 시간/선택 변화 문구가 없는가
- [ ] 과거 원픽 여부를 직접·간접으로 노출하지 않는가
- [ ] `✓ 내 원픽` / `✓ 이 집 원픽`이 긍정 match에서만 보이는가
- [ ] 좋아요 또는 따라 고르기 CTA를 핵심 행동으로 만들지 않았는가
- [ ] 홈 기본 범위가 follow count 규칙과 맞는가
- [ ] 최근 7일 메뉴 숫자가 DB 계약과 최소 표본 3명 규칙을 따르는가
- [ ] DB 데이터가 없는 상태를 UI가 추측하지 않는가
- [ ] 두 번째 테마가 준비되기 전 전환 컨트롤이 과도하게 강조되지 않는가
