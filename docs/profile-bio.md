# 프로필 자기소개

## 사용자 이용 / UX
- 내 프로필의 사용자명 아래, SNS 영역 위에 자기소개 카드를 표시한다.
- 선택 입력이며 앱 편집 화면과 저장 서비스에서 100자 이내로 검증한다. Unicode code point 기준이며 줄바꿈을 지원한다.
- 추가/수정 → 입력 → 저장. 취소는 저장하지 않는다. 내용 지우기 후 저장하면 기존 bio를 null로 비운다.
- 저장 전 공개 프로필에서 다른 사람이 볼 수 있는 소개임을 안내한다. 예시 문구는 placeholder일 뿐 자동 저장하지 않는다.
- 공개 프로필은 기존 사용자명 아래의 bio 표시를 그대로 사용한다. 자기소개가 없으면 방문자에게 빈 입력칸을 노출하지 않는다.
- 저장 실패 시 초안을 유지하고, 중복 저장을 차단한다. 계정이 바뀌면 편집기를 다시 마운트하고 저장 전 실제 인증 사용자를 대조한다.

## 프런트 / 데이터
- ProfileBioEditor → useUpdateProfileBio → ProfileBioService.
- 기존 profiles.bio 컬럼과 소유자 RLS를 사용한다. 새 테이블/마이그레이션/권한 변경 없이 bio만 업데이트한다.
- 앱/서비스와 DB 모두 새로 저장되거나 수정되는 자기소개를 100자로 제한한다. 보안 제약 도입 전에 저장된 긴 소개는 마이그레이션에서 임의로 자르지 않으며, 다음 편집 시 사용자가 직접 100자 이내로 정리한다.
- 저장된 응답으로 해당 사용자의 내/공개 프로필 캐시만 불변 업데이트하고 프로필 조회를 갱신한다. 원픽 목록, SNS 링크와 다른 사용자의 소개는 변경하지 않는다.
- 화면에서는 일반 Text로 표시한다. HTML을 해석하거나 입력한 URL을 자동 실행하지 않는다.

## 검증 및 반영
- test-profile-bio.cjs: 길이/Unicode/빈 값, 인증 사용자 일치, bio 컬럼만 수정, 캐시 유지, 편집·취소·실패·재시도·중복탭, 공개 프로필 표시.
- 022_profile_bio.sql: CI의 임시 DB에서 기존 RLS의 소유자 수정, 익명 조회, 타인 수정 거부, 비우기, 차단/정지 노출 규칙을 검사하고 rollback한다.
- 기존 사진 등록 작업 PR에 누적하며 별도 운영 사이트를 만들지 않는다. Cloudflare 연결·사이트 통합 완료 전에는 main 병합/운영 배포를 보류한다.
- 운영 DB는 스키마 읽기만 수행했다. 기존 자기소개나 사용자 데이터는 변경하지 않았으며 실기기 검증은 별도이다.
