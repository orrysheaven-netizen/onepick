# AI 댓글 품질 기준 — taste-v5-no-age

## 확정한 문체

공개 원픽과 한줄평에서 선택 이유를 읽고 공통점이나 카테고리별 차이를 존중하는 말로 설명한다. 사용자나 취향을 공격하거나 부정적으로 판정하지 않는다. 비난·조롱·비꼼·냉소·훈계·칭찬으로 포장한 비하와 취향의 우열 비교를 금지한다. 짧은 한줄평이나 적은 원픽을 사용자에 대한 부정적 평가로 바꾸지 않는다.

긍정적인 문체는 무조건적인 칭찬과 다르다. 근거 없는 특별함·능력·수준을 만들어내지 않으며, 위험하거나 부적절한 행동을 긍정하지 않는다. 위트는 선택의 즐거운 조합에서 나온 한 문장 이내로 두고, 비꼼으로 읽힐 여지가 있으면 담백한 관찰로 바꾼다.

이전의 조건부 예상 나이 정책은 폐기한다. 나이·연령대·출생연도·세대와 정신연령·취향 나이 등 우회 표현을 요약·본문·키워드 어디에도 넣지 않는다. 한줄평에 직접 단서가 있어도 출력에서 반복·계산·추정하지 않는다.

## 화면 안내

`mobile/src/lib/profileAiCopy.ts`의 안내 문구:

> 원픽이 많고 한줄평이 구체적일수록 취향의 공통점을 더 잘 발견할 수 있어요.

본인 프로필의 첫 생성 안내와 기존 평가의 재평가 영역에서 동일한 문구를 사용한다. 타인의 공개 프로필에는 등록 권유를 표시하지 않는다. 모든 AI 댓글 말미에 같은 안내를 기계적으로 붙이지 않는다. 데이터가 늘면 성격 진단의 정확도가 보장된다는 의미가 아니다. 최소 생성 조건·권한·공개 정책은 변경하지 않는다.

## 코드와 입력

- 버전: `taste-v5-no-age`. 이전 age-enabled 버전과 구분하며 모델 종류와 응답 3필드는 유지한다.
- 나이 계산용 `referenceYear`를 모델 입력과 지문에서 제거한다. 원본 한줄평과 제품의 출시연도는 유지한다.
- `assertNoAgeComment`는 명확한 연령 표현을 저장 및 캐시 반환 전에 확인하는 제한적인 문자열 검사다. 모든 의미상 표현·긍정성·안전성을 판별하지는 못한다.
- 공격성/부정적 인물평 금지는 프롬프트와 수동 검토 기준이다. 어조 분류 모델이나 완전한 의미 검증기를 추가한 것이 아니다.

## 가상 기준 댓글과 미리보기

`quality.examples.ts`의 6개 가상 사례를 존중하는 문체로 정리했다. 같은 원픽/다른 이유의 두 사례, 카테고리별 차이, 반복해서 찾는 선택, 여백 중심의 선택, 이유가 짧은 경우를 포함한다. 원픽이나 한줄평이 적은 경우에는 현재 관찰 가능한 선택을 말하고 구체적인 이유를 더할 때의 가치를 부드럽게 안내한다.

`scripts/render-ai-comment-preview.ts`는 동일한 샘플과 화면 안내 문구를 사용해 독립 HTML을 만든다. 본인 미리보기·공개 상태·원픽 변경 후·AI 연결 준비 중을 비교한다. 상태 버튼은 로컬 화면만 바꾼다. 실제 계정·AI 호출·DB 쓰기·게시와 연결하지 않는다. 실제 앱 컴포넌트나 모델 출력 검증을 대체하지 않는다.

실행: `deno run --config supabase/functions/analyze-profile-taste/deno.json --allow-write=ai-comment-preview.html scripts/render-ai-comment-preview.ts`

## 검증과 한계

기존 `quality.test.ts`에 나이 제외·입력·샘플 형식 계약 검사 16개가 있다. 신규 `test-profile-ai-copy.cjs`의 8개 검사는 안내 문구, 소유자 영역의 사용, 존중하는 말투 지시, 짧은 이유의 표현, 근거 유지, 위트 기준, 샘플의 확인 대상 표현, 저장 전 연령 검사를 확인한다. 이들은 실제 모델 출력 품질 평가가 아니다.

각 변경 커밋의 최신 CI를 확인한다. 완료되지 않은 검사를 이전 성공으로 대신하지 않는다. 실제 문장의 근거·위트·공격성 여부는 API 연결 후 반복 생성과 수동 검토가 필요하다.

## 이번 작업의 범위

DB 변경, 실제 모델 호출, 사용자 평가 게시, 서버/앱 배포, PR 병합은 하지 않는다. API 설정은 보류 상태다. 이전 화면에서 새 평가가 공개될 수 있는 결함은 별도 출시 전 수정 항목이며 이 작업으로 해결됐다고 간주하지 않는다.
