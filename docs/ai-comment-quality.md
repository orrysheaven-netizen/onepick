# OnePick AI 취향 해석 품질 규칙

현재 운영 기준 프롬프트 버전: `taste-v8-editorial-evidence`

이 문서는 OnePick AI가 사용자의 공개 원픽과 한줄평을 해석할 때 지켜야 하는 편집 품질 기준을 정리한다. JSON 스키마, 안전 규칙, 나이·인구통계 추정 금지, 서로 다른 원픽 최소 2개의 구체적인 이유 연결, 공통점/대비 구조의 자율 선택 규칙은 기존 계약을 그대로 유지한다.

## 1. 연결 표현 반복 방지

- 같은 연결 어구 또는 사실상 같은 문장 시작 패턴을 한 응답 안에서 두 번 이상 반복하지 않는다.
- `~걸 보면`, `~점에서`, `~짚어주신 점을 보면` 같은 표현이 다시 필요하면 문장 구조 자체를 바꾼다.
- `근거 나열 → 대비 나열 → 요약` 같은 고정 조립 패턴을 기본형으로 사용하지 않는다.

검토 시에는 단순 어휘 중복뿐 아니라 문장 골격이 반복되는지도 본다.

## 2. 마무리는 요약이 아니라 재해석

- 마지막 문장은 앞 문장의 내용을 다시 압축하는 데 그치지 않는다.
- 근거가 충분하면 독자가 처음 떠올릴 법한 표면적인 해석을 한 번 짚은 뒤, 여러 원픽을 함께 보았을 때 드러나는 더 정확하거나 의외의 관점으로 한 단계 발전시킨다.
- 데이터에 없는 대비, 반전, 숨은 성격을 만들어내지는 않는다.

좋은 마무리는 앞의 근거를 없애지 않고, 그 근거를 보는 관점을 한 단계 바꾼다.

## 3. keywords는 교차 근거가 있어야 함

- keywords는 정확히 3개를 유지한다.
- 각 keyword는 서로 다른 원픽 최소 2개 이상에서 공통 근거를 찾을 수 있어야 한다.
- 특정 원픽 하나에만 해당하는 장르, 분위기, 캐릭터, 사용 특성은 keyword로 쓰지 않는다.
- 근거가 약할수록 여러 픽에서 확인되는 보수적인 표현을 사용한다.

이 규칙은 의미 규칙이므로 단순 문자열 검증만으로 완전히 판정할 수 없다. 자동 회귀검사는 프롬프트 계약의 존재를 확인하고, 실제 출력 품질은 샘플 결과의 수동 검토에서 교차 근거를 확인한다.

## 4. popularityPercent 사용 조건

- `popularityPercent`는 취향의 대중성/희소성이 실제 해석에 의미를 더할 때만 사용한다.
- `5% 이하` 또는 `80% 이상`을 우선 검토 트리거로 삼는다.
- 중간값은 다른 원픽과 뚜렷한 대비를 만드는 특별한 이유가 없으면 생략한다.
- 한 응답에서 최대 한 곳에만 사용한다.
- 낮은 값은 `비교적 드문 선택`, 높은 값은 `많이 선택되는 항목`처럼 해당 픽의 위치를 설명하는 보조 신호로만 사용한다.
- 수치 하나로 사용자의 성격, 특별함, 비주류성, 대중추종 성향을 단정하지 않는다.

5%/80% 경계는 절대적인 성격 판정 기준이 아니라 "이 수치를 해석에 쓸 가치가 있는지 먼저 확인하는 트리거"다.

## 회귀 검증

`mobile/scripts/test-profile-ai-prompt-quality.cjs`가 다음을 자동 확인한다.

- 프롬프트 버전이 `taste-v8-editorial-evidence`인지
- 연결어/문장 패턴 반복 방지 규칙이 존재하는지
- 재해석형 마무리 규칙이 존재하는지
- keyword의 최소 2개 원픽 교차근거 규칙이 존재하는지
- popularityPercent의 5%/80% 우선 조건과 최대 1회 규칙이 존재하는지
- 이전의 모호한 popularity 지시문이 남아 있지 않은지

실제 모델 출력의 의미 품질은 같은 입력을 여러 번 생성해 다음을 별도로 확인한다: 연결 패턴 반복 여부, 마지막 문장의 재해석 여부, 각 keyword의 두 원픽 이상 근거 여부, popularityPercent 사용이 수치 자체를 성격 판정으로 확대하지 않는지.
