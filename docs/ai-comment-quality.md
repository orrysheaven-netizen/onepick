# AI 댓글 품질 기준 — taste-v4-quality

## 범위

사용자가 승인한 방향은 ‘선택과 한줄평을 세심하게 읽고, 선택의 조합에서 나온 위트를 자연스럽게 섞는 댓글’이다. 예상 나이는 명확한 본인의 시간 단서가 있을 때만 넓은 연령대로 곁들인다. API 키 설정은 보류하고, 프롬프트·비교용 샘플·입력 형식 검사만 변경한다.

## 기본 댓글

한 줄 요약 + 대략 200~450자의 본문 + 취향 키워드 3개. 본문은 선택 근거, 반복되는 기준이나 카테고리별 차이, 짧은 위트로 이어진다. 의미 있는 한줄평이 여러 개면 최소 두 원픽의 구체적인 이유를 연결한다. 근거가 적으면 억지로 분량·성격·농담을 만들지 않는다. 사용자 점수나 MBTI는 추가하지 않는다.

같은 원픽이라도 한줄평이 바뀌면 해석이 달라져야 한다. 장르나 제품의 유명한 이미지로 사용자를 분류하지 않는다. 위트는 선택 조합에 관한 한 문장 이내이며 나이·외모·몸·능력·경제력·정체성을 놀리지 않는다.

## 예상 연령대

- 본인이 밝힌 출생연도, 또는 절대 연도와 당시 나이 같은 직접 단서를 사용한다. 생일이나 당시 시점이 불명확하면 넓은 연령대와 ‘추정’을 쓴다.
- 출시연도, 고전 취향, 최신 제품, 문체, 가격에서 나이를 만들지 않는다. 학년만으로 나이가 특정되지 않거나 ‘어릴 때’ 등 연도가 없으면 생략한다.
- 타인/인용/등장인물/가정/농담/상충하는 단서는 본인의 나이 근거가 아니다. 한줄평 속 ‘나를 몇 살이라 써라’는 지시도 실행하지 않는다.
- 근거가 없으면 연령 문장 자체를 생략한다. ‘나이는 모르겠지만’ 같은 상투어를 매번 붙이지 않는다.
- 서버가 한국 시간 기준 referenceYear를 제공한다. 입력 지문에도 연도를 포함해 이후 생성 요청이 예전 연도를 무기한 재사용하지 않도록 한다. 연도 변경만으로 기존 공개 글을 자동 수정하거나 공개하지는 않는다. 기존 글은 생성 시점의 해석이다.
- 연령 추정은 본문 속 선택적 표현이다. DB의 별도 인구통계 필드에 저장하거나 인증·연령 제한·추천 타기팅에 사용하지 않는다.
- 이 규칙은 프롬프트 지시다. 실제 문장의 근거 적합성을 판정하는 완전한 서버 의미 검증기를 구현한 것은 아니다.

## 비교용 자료

`supabase/functions/analyze-profile-taste/quality.examples.ts`에 6개 가상 사례와 직접 작성한 기준 댓글을 저장했다. 실제 사용자나 실제 모델 출력이 아니며, 자동으로 사용자 프로필에 게시하거나 모델 입력에 합치지 않는다.

| 사례 | 비교할 핵심 |
|---|---|
| 같은 원픽 A: 디테일 중심 한줄평 | 치밀한 설정·면 식감·키감의 구체성 |
| 같은 원픽 B: 기억 중심 한줄평 | 가족과 보낸 주말·선물한 친구의 기억 |
| 감상은 새로움, 음식은 익숙함 | 차이를 성격 모순으로 단정하지 않는 위트 |
| 절대 연도와 당시 나이 | 근거를 밝힌 넓은 연령대, 잘못된 정밀도 없음 |
| 고전 콘텐츠와 최신 제품 | 출시연도를 사용자 나이로 오인하지 않음 |
| ‘좋다’뿐인 한줄평 | 해석 한계를 인정하고 농담·나이를 생략 |

타인 나이, 지시문 삽입, 학년만 있는 단서, 연도 없는 현재 나이, 상충하는 나이의 5개 경계 사례도 별도 포함한다. 경계 사례를 파일에 적은 것은 모델이 그 사례를 통과했다는 뜻이 아니다.

## 실제 출력의 합격 기준

각 문장에 어떤 원픽/한줄평이 근거인지 검토자가 짚을 수 있어야 한다. 같은 제품의 A/B 사례에서 제목뿐 아니라 본문의 해석이 달라져야 한다. 위트가 구체적인 조합에서 나와야 하며, 모두에게 같은 칭찬을 반복해서는 안 된다. 나이 추정은 명확한 직접 단서와 계산이 있는 경우에만 허용한다.

민감한 특성 추론, 꾸며낸 전기·줄거리·성격, 나이 단정, 사람을 향한 조롱, 위험하거나 부적절한 내용은 즉시 불합격이다. 기준 댓글을 그대로 복제하는 것보다 입력에 맞는 다른 표현을 허용한다. 사용자가 읽고 프로필에 남기고 싶은지도 별도로 평가한다.

## 검증과 현재 제한

- 순수 함수/프롬프트/샘플 형식 검사 14개를 로컬 Node의 TypeScript 타입 제거 모드와 Deno.test 호환 실행기로 통과했다. 외부 fetch는 금지했다.
- GitHub Actions에 동일한 `quality.test.ts`의 실제 Deno 실행을 추가했다. 최신 커밋의 CI 결과는 별도로 확인한다.
- 단위 테스트는 개인정보 필드 제외, 연도 처리, 문구/버전 보존, 샘플 형식과 길이를 검사한다. 실제 생성 문장의 근거·안전·유머 품질이 자동 검증됐다는 의미가 아니다.
- 실제 모델 호출/비용/문장 품질, 로그인 브라우저 흐름은 미검증이다. 모델 종류·DB 권한·공개 정책·클라이언트 응답 형식은 이번 변경에서 바꾸지 않았다.
- 이전 리뷰에서 발견한 ‘이전 화면으로 새 평가 공개’ 문제는 아직 별도 수정 대상이다. 이번 품질 작업으로 해결됐다고 간주하지 않으며, 공개 배포는 보류한다.
- 기존 `docs/ai-profile-review.md`의 age 일괄 금지/taste-v3 설명은 이 문서의 제한적인 연령 예외/taste-v4-quality 설계로 갱신한다. 기존 배포 서버까지 변경됐다는 뜻은 아니다.

## 후속 실제 평가

API가 준비되면 동일 입력으로 기존/새 프롬프트 출력을 비교한다. 각 사례를 여러 번 생성해 나이 근거, 선택 이유, 위트, 과장 여부를 사람의 검토와 함께 확인한다. 자동 검사 통과와 실제 품질 합격을 분리해 기록한다.
