# AI 역할 분담 — Builder / Reviewer

결정일: 2026-09-21.

OnePick의 코드 작업은 **ChatGPT/Codex를 주 빌더**, **Claude Code를 독립 리뷰어·QA**로 나눈다. 두 에이전트가 같은 기능을 동시에 구현하지 않는다.

## 유일한 원본

대화 내용보다 GitHub의 `main`, PR, 커밋, migration, 테스트 결과를 우선한다. 두 에이전트의 설명이 다를 때도 저장소의 실제 상태를 기준으로 판단한다.

## 역할

| 업무 | ChatGPT / Codex | Claude Code |
| --- | --- | --- |
| 아키텍처·기능 구현 | 주 담당 | 검토·대안 제안 |
| 여러 파일 통합 수정 | 주 담당 | 회귀 검토 |
| Supabase DB·RLS·migration | 주 담당 | 보안·권한 검토 |
| 배포·CI | 주 담당 | 실패 경로·운영 위험 검토 |
| 외부 API·프런트/백엔드 연결 | 주 담당 | 예외·오류 검토 |
| 보안·성능·dead-code 조사 | 1차 대응 | 독립 2차 검증 |
| PR 리뷰 | 구현·통합 관리 | 독립 리뷰 |

Claude가 직접 수정해도 되는 범위는 기능 개발과 충돌 가능성이 낮은 보안 감사, 테스트 보강, dead-code 조사, 접근성·성능 조사, 문서화 등이다. 같은 파일이나 기능을 이미 다른 에이전트가 수정 중이면 중복 구현하지 않는다.

## 리뷰 기준

PR 리뷰는 다음 항목을 본다.

1. 기존 기능 회귀
2. DB / RLS 보안
3. 중복 코드
4. 모바일 UX
5. 오류 처리
6. 성능
7. 삭제 가능한 코드
8. 실제 배포 위험

발견 사항은 가능한 경우 `Critical / High / Medium / Low`와 함께 파일·위치, 재현 조건, 실제 결과를 남긴다. 근거가 없는 추측은 결함으로 기록하지 않는다.

## 금지

- 같은 기능을 두 에이전트가 각각 구현하기
- 한쪽이 다른 쪽 코드를 반복해서 되돌리는 왕복 수정
- `main` 직접 푸시
- 장기 통합 브랜치를 실제 trunk처럼 사용하기
- GitHub 상태를 확인하지 않고 대화 기록만으로 완료됐다고 판단하기

브랜치·worktree·CI·DB 테스트의 구체 규칙은 루트 `CLAUDE.md`와 `AGENTS.md`를 따른다.
