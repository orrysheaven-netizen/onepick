# AI 역할 분담 — Builder / Reviewer

결정일: 2026-09-21.

OnePick의 코드 주 작업 공간은 **ChatGPT/Codex**에 둡니다. **Claude Code**는 같은
저장소를 독립적으로 검토하는 **리뷰어·QA** 역할을 맡습니다. 개발자 1명 + 리뷰어 1명
구조이며, 같은 작업을 두 번 시키지 않습니다.

## 유일한 원본은 GitHub

```text
             ┌─ ChatGPT / Codex  (Builder)
             │        개발
             │          ↓
사용자 ──────┤       GitHub  ← 유일한 원본(Source of Truth)
             │          ↑
             │        검토
             └─ Claude Code     (Reviewer)
```

ChatGPT의 대화도, Claude의 대화도 프로젝트의 원본이 아닙니다. `main`, 브랜치,
커밋, PR, 마이그레이션, 테스트가 실제 상태를 결정합니다. 두 에이전트의 말이 서로
달라도 GitHub를 기준으로 판단합니다.

## 분담표

| 업무 | ChatGPT + Codex | Claude Code |
| --- | --- | --- |
| 전체 아키텍처 결정 | 주 담당 | 검토 |
| 실제 기능 구현 | 주 담당 | 보조·대안 제안 |
| 여러 파일 동시 수정 | 주 담당 | 검토 또는 대규모 리팩터링 |
| Supabase DB / RLS / 마이그레이션 | 주 담당 | 보안 검토 |
| 배포 관련 코드 (Cloudflare Pages, Supabase Functions) | 주 담당 | QA |
| 외부 API 통합 (TMDB, YouTube, IGDB, 도서) | 주 담당 | 오류·예외 검토 |
| 프런트/백엔드 연결 | 주 담당 | 회귀 검토 |
| 전체 코드베이스 분석 | 담당 | 강하게 활용 |
| 보안 코드 리뷰 | 1차 | 2차 독립 검증 |
| 버그 원인 분석 | 1차 수정 | 반대편에서 재검증 |
| UX·논리 이상점 | 기획 + 구현 | QA |
| PR 리뷰 | 구현자 | Reviewer |
| 최종 merge 판단 | 통합 관리 | 의견 제공 |

대략 Codex 70% / Claude 30%입니다.

## 하루 흐름

1. **07:00 (KST)** — Claude가 `main`과 열린 PR 상태를 읽고, 그날 할 일을 개략적으로
   보고합니다. 이 시점에는 **아무것도 고치지 않습니다.**
2. 사용자가 항목을 고르고 승인합니다.
3. Claude가 승인된 항목만 수행합니다.
4. 결과를 보고합니다. 코드 변경이 필요하면 원칙적으로 Codex에 넘깁니다.

## Claude의 PR 리뷰 형식

PR을 받으면 **수정하지 않고 먼저 검토**합니다. 점검 항목:

1. 기존 기능 회귀
2. DB / RLS 보안
3. 중복 코드
4. 모바일 UX
5. 에러 처리
6. 성능
7. 삭제 가능한 코드
8. 실제 배포 시 위험

보고는 `Critical / High / Medium / Low`로 분류하고, 각 항목마다
**파일:라인 + 재현 조건 + 실제 결과**를 답니다. 근거를 댈 수 없는 항목은 보고하지
않습니다. 추측은 리뷰어의 가치를 떨어뜨립니다.

더 나은 구현 방법을 발견해도 전체 코드를 갈아엎지 않습니다. "현재 방식의 문제 +
대안" 까지만 제시하고, 통합 판단은 Codex 쪽에서 합니다.

## Claude가 직접 개발해도 되는 영역

주 기능 개발과 충돌 가능성이 낮고 독립성이 높은 작업입니다.

- 보안 감사
- 대규모 dead-code 조사
- 테스트 코드 확충
- 접근성 검사
- 중복 코드 조사
- 성능 병목 조사
- 문서화
- 전체 코드베이스 리팩터링 **계획**

이 영역에서도 PR은 작게 나누고, 기능 브랜치와 같은 파일을 건드리면 먼저 알립니다.

## 하지 않는 것

- 두 에이전트에게 같은 기능을 각각 구현시키기
- Claude가 Codex 코드를 재작성하고 Codex가 다시 되돌리는 왕복
- 승인 없이 아침 브리핑 항목을 바로 착수하기
- `main` 직접 푸시 (CLAUDE.md의 브랜치 규칙 그대로)
