# 일반 카테고리 선택폭 보완

## 목적과 범위

AI 댓글 요청 조건인 **현재 분석 가능한 공개 원픽 최소 10개**를 유지하면서, 관심 없는 분야를 모두 선택할 필요가 없도록 일반 카테고리를 보완한다. 이번에는 대량 수집이나 외부 API 연동 대신 기존 카테고리·검색·선택 구조에 소규모 초기 카탈로그를 추가했다.

## 실제 개발 DB 반영 — 2026-09-19

대상은 `onepick-dev` (`ygoipwzakzdnkaaxyrgb`)다. 먼저 같은 데이터를 트랜잭션으로 시험 적용하고 비로그인 읽기·검색을 확인한 뒤 모두 롤백했다. 이후 동일한 데이터 추가와 공개 조회 검증을 한 트랜잭션션에서 실행해 커밋했다.

| 묶음 | 새 선택 카테고리 | 초기 항목 |
| --- | --- | --- |
| 먹을것 | 아이스크림 | 메로나, 투게더 |
| 읽을것 | 책 | 데미안(민음사 세계문학전집 44), 어린 왕자(비룡소 클래식 14) |
| 쓰는것 | 볼펜 | 모나미 153 블랙 & 화이트, 모나미 153 리스펙트 리파인 |
| 쓰는것 | 노트 | 무인양품 미표백 노트 A5, MD 노트 A5 무지 |

- 선택 카테고리 **4개**, 카테고리별 공개 항목 **2개**, 초기 항목 **8개**를 추가했다.
- 새 묶음 `읽을것`과 `쓰는것`은 선택 불가능한 상위 카테고리다. 기존 `먹을것` 묶음을 재사용했다.
- 적용 후 공개·선택 가능·open 상태이며 공개 항목이 있는 일반 카테고리는 **12개**다. 라면·과자·영화·드라마·음악·게임·유튜브·포켓몬과 이번 4개가 대상이다.
- 이 구성에서는 일반 카테고리 12개 중 10개에서 선택할 수 있다. 카테고리별 현재 원픽 하나라는 기존 규칙은 유지한다. 10개를 채워도 자동 생성하지 않는다.
- 기존 카테고리의 이름·위치·공개 상태, 기존 제품, 사용자 원픽과 한줄평, AI 댓글은 수정하지 않았다. 새 항목을 사용자 대신 원픽으로 등록하지도 않았다.

## 메타데이터와 출처

기계 판독용 원본은 `docs/general-category-starter.json`이다. 제품명, 제작자/브랜드명, 판본/제품 식별자, 공식 외부 링크 등 필요한 사실만 수동 확인했다. 확인일은 2026-09-19이다.

책은 제목만으로 판본을 합치지 않도록 ISBN13을 `model_code`에 보존하고 출판사·번역자를 `collection_name`에 기록했다. `release_year`는 해당 등록 판본의 연도이며 최초 원작 출간 연도를 뜻하지 않는다. 책 API나 전체 서지 데이터 연동을 추가한 것은 아니다. 향후 서지 연동 시 ISBN을 비교해 이 초기 항목과 중복되지 않도록 해야 한다.

`external_source=onepick_starter`와 고유 키는 **내부 초기 등록 식별자**다. 외부 공급자 API에서 자동으로 받은 정보라는 표시가 아니다. 제품별 크기·색상·판매 여부 등 확인하지 않은 정보는 추가하지 않았다. 가격이나 재고 보장을 표시하지 않는다.

## 적용 파일과 반복 실행

`supabase/operations/seed-general-categories.sql`은 명시적으로 실행하는 **데이터 추가 전용 작업 파일**이다. 자동 스키마 마이그레이션이나 매번 실행하는 기본 seed에 넣지 않았다. Supabase의 기존 `categories`·`items` 테이블과 권한을 사용한다.

- 단일 DO 문으로 실행해 오류 발생 시 부분 추가를 남기지 않는다.
- 생성 UUID를 고정하지 않고 slug와 내부 등록 키로 연결한다.
- 같은 키가 있으면 기존 행을 수정하지 않는다. 나중에 수정된 이름·공개 상태·외부 링크·사진을 덮어쓰지 않는다.
- 식별자와 분류가 충돌하거나 이미 이름/제품 식별자로 등록된 항목이 있으면 검토를 요청하는 오류로 중단한다. 검수 없이 중복이나 임의 병합을 하지 않는다.
- 기존 카테고리 트리 검증 및 관련 잠금을 유지한다. RLS·함수 권한·테이블 구조는 바꾸지 않는다.
- 운영 적용 시 대상 프로젝트와 사전 조건을 확인해야 한다. 이 파일을 다른 환경에 자동 적용하도록 설정하지 않았다.

## 검증

실제 개발 DB에서 비로그인 역할로 새 카테고리 4개와 공개 항목 8개가 읽히고, 기존 `search_items`가 항목별 이름과 해당 카테고리로 검색했을 때 정확한 항목 ID를 반환하는 것을 확인했다. 적용 후 일반 카테고리 12개와 카테고리별 2개 항목 집계도 확인했다.

`mobile/scripts/test-general-category-starter.cjs`는 로컬 Node에서 통과했다. JSON 원본과 SQL 입력 일치, 카테고리별 개수, 고유 키, 허용 HTTPS 출처, 두 ISBN 체크섬을 검사한다. 이 검사는 원격 링크의 미래 가용성이나 실제 화면 작동을 보장하지 않는다.

`supabase/tests/general_category_starter.sql`에 PostgreSQL 회귀 단언 14개를 추가했다. 신규 계층·항목, 기존 카테고리·제품·원픽·AI 댓글 보존, 재실행 중복/시각 변경 없음, 비로그인 읽기·검색, 운영자가 수정한 행을 재공개하거나 덮어쓰지 않는지를 확인하고 마지막에 롤백한다. 이 파일의 실제 실행 결과와 전체 자동 검사는 해당 커밋의 CI에서 별도로 확인한다.

## 화면과 AI의 남은 상태

현재 브랜치의 카테고리 탐색 및 미선택 목록은 DB 기반이다. 새 카테고리는 기존 일반 검색·선택·등록 요청 경로를 사용하며 별도 하드코딩을 추가하지 않았다. 실제 로그인 휴대전화/브라우저에서의 등록 완료 흐름까지 이번에 확인한 것은 아니다.

**카테고리 데이터는 개발 DB에 실제 반영했다.** 작업 파일·테스트·문서는 PR #47의 개발 브랜치에 저장한다. 이는 AI 키 설정이나 AI 기능 활성화와 구분한다. 이번에는 API 키 등록, 실제 AI 호출/평가 게시, 서버·앱 재배포, main 병합을 하지 않았다. 기존 배포 서버와 최신 AI 브랜치의 차이도 그대로 남아 있다.

초기 항목 2개씩은 선택 경로 확보를 위한 출발점이지 충분한 카탈로그라는 뜻은 아니다. 이용자가 찾는 항목은 기존 등록 요청·검수 흐름으로 보완한다. 최소 10개, 나이 표현 제외, 존중하는 말투, 한줄평 중심 해석 원칙은 변경하지 않았다.
