기준: 사용자가 이 대화에서 확정한 결정과 OnePick Figma. 이 문서는 적용 완료 보고가 아니라 구현 범위 및 의존성 추적이다.

## 화면 기준

- 39 (`136:164`): 하단 64px, 중앙 검정 원형 48px 등록 버튼, 알림 옆 주황색 6px 점. 탭에 들어갔다는 이유만으로 읽음 처리하지 않는다.
- 67/68 (`236:216`, `238:219`): 프로필 댓글에서 모든 내 댓글/답글 접근. 프로필 편집과 설정은 상단 우측. 프로필 등록 요청 내역과 과거 원픽 목록은 제거.
- 50~55: 한 화면에 한 입력. 기존 제품은 이미 있는 링크/사진 재입력 생략. 새 제품 사진과 한줄평은 필수. 한줄평 100자 제한 표시. 사진 첨부 후 등록 안내 제목 제거, 사진 수정/삭제 제공.
- 61~66: 새 메뉴 검색 흐름으로 교체. 같은 메뉴·채널에 기존 원픽이 있으면 변경 확인. 취소/실패 시 기존 원픽과 입력 보존. 원픽 해제와 한줄평 삭제는 별개.
- 70/71: 특정 지점을 우선 선택하되 브랜드 전체도 선택 가능. 브랜드 전체와 각 지점의 원픽 수/한줄평/댓글 작성 자격은 합산하지 않는다. 상호를 누르면 브랜드 프로필 안에 원픽 있는 모든 지점이 나온다.
- 72: 현재 동일 제품 원픽 보유자만 댓글/답글 작성. 제품은 제공처 + 지점 또는 브랜드 전체 + 메뉴 + 채널로 식별. 본인 한줄평에도 작성할 수 있다.
- 73: 기존 제공처여도 **새 온라인 제품**은 개별 구매 링크, **새 레시피**는 원문·영상 링크 필수. 기존 같은 제품이면 저장된 링크 재사용. 제공처 홈 주소를 개별 링크로 대체하지 않는다.
- 74: 레시피 링크 썸네일 자동 적용. 없거나 실패하면 사진 직접 등록 필수. 채널 아바타를 제품 사진으로 쓰지 않는다. 사진 수정 취소는 이전 사진 유지, 삭제는 빈 사진 상태, 링크 변경은 썸네일 재확인.

## 서버 담당 인계 명세 (아직 전달 / 구현 완료 아님)

저장소 AGENTS.md에 따라 migration, RLS, Auth core, Storage는 Claude 소유다. 앱에서 권한 검사를 흉내 내거나 기존 RPC 성공을 새 계약 성공으로 간주하지 않는다.

### A. 즉시 등록 / 원픽 교체

- 새 제품에 채널, 제공처, 지점/브랜드 범위, 메뉴 분류, 개별 링크 또는 지도 링크, 유효한 대표 사진, 1~100자 한줄평을 검증한다.
- 제품 생성 + 한줄평 + 현재 원픽 전환을 원자적으로 저장한다. 승인 대기 후 원픽으로 전환하는 현재 계약과 다르다.
- 동일 사용자·메뉴·채널의 현재 원픽은 하나다. 기대 이전 선택 ID 또는 버전으로 동시 변경을 감지하고 재확인을 요구한다. 재시도는 중복 생성하지 않는다.
- 클라이언트 성공 응답은 저장된 item ID / pick ID. 운영 검토는 사용자에게 상태/내역/승인 알림으로 노출하지 않는다.
- 수정 필요 이벤트만 사유와 수정 대상 ID를 제공. 기존 입력을 복구하고, 재요청 후 홈으로 돌아간다.

### B. 한줄평과 댓글

- 원픽 해제/변경은 기존 한줄평 및 대화를 보존한다. 과거 원픽 이력은 사람별 목록/API로 공개하지 않는다.
- 제품별 한줄평 조회는 현재 선택 우선, 비현재 한줄평 뒤, 안정적인 커서 및 특정 한줄평/댓글 딥링크를 제공한다. 종료 시각/교체 대상/이전 상태를 노출하지 않는다.
- 한줄평 삭제는 본인만. 현재 한줄평이면 원픽도 함께 해제한다. 다른 제품의 현재 원픽은 건드리지 않는다.
- 댓글이 달린 한줄평 삭제: 본문·작성자·깃발을 제거한 `삭제된 한줄평입니다` 자리 유지, 댓글 보존. 댓글 없는 한줄평은 목록 제거. 삭제된 한줄평은 한줄평 수에 제외.
- 답글 있는 댓글 삭제도 작성자/본문 제거 후 자리 유지. 답글 없으면 제거. 타인의 댓글을 함께 삭제하지 않는다.
- 쓰기 시점에 작성자의 **현재 정확히 같은 제품·채널 선택**을 서버에서 검사한다. 한줄평 작성자가 현재 선택자인지와는 별개다. 본인 한줄평 작성 제한 없음.
- 읽기 응답에 현재 선택자 boolean, 작성 가능 여부, 삭제/수정 가능 여부, 삭제 상태와 실제 카운트를 제공한다. 본인 댓글은 해제 이후에도 프로필에서 페이지 끝까지 접근/삭제 가능해야 한다.

### C. 브랜드 / 링크

- 브랜드 전체와 특정 지점은 별도 제품 범위. 지도 링크/주소와 지점 소속을 검증한다. 카운트·댓글 자격을 브랜드로 합산하지 않는다.
- 브랜드 프로필에 현재 원픽이 하나라도 있는 모든 지점을 페이지 조회. 브랜드 전체 섹션은 별도로, 선택 0이면 숨김.
- 원문/구매 링크와 제공처 홈 링크 구분. 링크 미리보기는 SSRF/크기/형식/재시도 및 실제 영상 썸네일 검증 필요.

### D. 앱 안 알림만

- 내 원픽 새 한줄평 / 내 한줄평 댓글 / 내 댓글 답글 / 수정 필요 / 팔로잉 원픽 구분.
- 각각 제품 / 한줄평 / 부모 댓글 / 수정 대상 / 팔로잉 사용자+메뉴+채널 기준 그룹. 댓글과 답글 중복은 답글만, 본인 이벤트 제외, 한줄평 수정은 팔로잉 알림 없음.
- 대표 작성자/미읽음 인원/최신 활동, 안정적인 그룹 ID와 읽음 스냅샷 버전 제공.
- 탭 열기만으로 읽음 처리하지 않고, 목적지 로드 성공 후 해당 시점까지 읽음. 도중 도착한 새 알림은 남는다.
- 승인/검토 중/등록 완료 이벤트는 목록 및 미읽음 집계에서 모두 제외해야 한다. 앱 목록만 숨겨 유령 점을 만들지 않는다.

## 동시 작업 / 충돌 주의

- #451 한줄평 표시, #452 홈 기본 탭, #453 문서, #455 팔로잉 channel, #456 한줄평 읽기 RPC: 별도 작업 진행 중. 중복 구현하지 않는다.
- #457의 등록 요청 프로필 재노출은 이 대화의 '수정 필요만 공유, 요청 내역 비노출' 결정과 충돌하므로 이 기준선에는 포함하지 않는다.
- #448 댓글 설계는 이 대화의 이후 결정(현재 동일 제품 선택자만 작성, 해제 후 유지, 한줄평 삭제와 대화 보존)과 다른 부분이 있어 서버 구현 전에 위 명세로 맞춰야 한다.
- 홈 최근 7일 숫자 표시 기준: Figma 초기 10명과 #448 별도 대화 3명 기록이 달라 이 브랜치에서 임의 변경하지 않는다. 탐색 대표 제품 기준 3명과 별개로 확인한다.

## 출시 조건

이 문서의 미완료 항목이나 DB 계약을 완료로 표시하지 않는다. 기존 사용자 데이터를 변경하는 배포는 독립 리뷰와 필수 `typecheck`, `verify-web`, `database-tests` 통과 후 사용자가 병합한다. 이 브랜치는 자동 병합/운영 DB 변경을 수행하지 않는다.

## 1차 검증 범위와 한계

- 타입 검사, 141개 회귀 검사 통과. 추가 네이티브 탭 이벤트 검사 포함 navigation/control 14개 검사 통과.
- 웹 export 및 13개 직접 경로 검증 통과. 브라우저에서 비로그인 홈/알림/프로필 표시와 키보드 기반 프로필·중앙 등록 이동 확인.
- 전용 일반 사용자 QA 자격 증명이 실행 환경에 없어 로그인 상태 실서버 저장/수정은 검증하지 않았다. 프로필 편집·설정·댓글 진입, 미읽음 점과 로그아웃 캐시 차단은 합성 테스트로 검증했다. 실제 기기 터치/제스처 검증은 남아 있다.
- 홈 데이터 요청은 로컬 미리보기에서 오류 상태가 표시되었으므로 실데이터 로딩 성공으로 기록하지 않는다.
- 내 댓글 목록은 테마 필터를 제거했지만, 해제한 원픽 대화 접근과 정확한 댓글 위치 이동은 서버 읽기 계약 후속이 남아 있다. 댓글 총수도 임의의 예시 숫자를 넣지 않았다.
- 알림 탭은 기존 알림 서비스에 연결했다. 승인 알림 제거/수정 요청 목적지/그룹별 읽음은 별도 서버 계약과 앱 연결이 필요하다. 이 PR을 알림 정책 전체 완료로 간주하지 않는다.
