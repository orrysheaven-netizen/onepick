# 원픽 저장 후 확인 동선

## 수정 범위
사람 중심 홈은 로그인한 사용자 자신의 원픽을 카드에서 제외한다. 기존 `/pick/choose` 저장 완료 화면의 `홈에서 확인하기`는 이 정책과 맞지 않아 제거한다.

- 기본 버튼 `내 원픽 보기`: 저장 응답의 `itemId`와 Pick `id`를 기존 상품 상세에 전달한다. 해당 사용자가 방금 저장한 원픽/한줄평으로 연결한다.
- 보조 버튼 `다른 사람의 원픽 계속 보기`: 기존 홈으로 돌아가 다른 사람의 선택을 둘러본다.
- 내 선택은 내 프로필, 다른 사람의 선택은 홈에서 볼 수 있다는 안내를 표시한다.
- 두 버튼은 저장 성공 응답 이후에만 표시한다. 버튼은 이동만 수행하며 원픽 생성/변경 API를 다시 호출하지 않는다.
- 현재 화면을 replace하므로 완료된 선택 화면을 불필요하게 한 단계 더 쌓지 않는다. 전체 네이티브/브라우저 탐색 기록을 리셋하는 기능은 아니다.

## 저장 결과 보호
문자열 한줄평 대신 서버가 반환한 Pick과 당시 상품 정보를 저장 완료 상태로 보관한다. 최신 상태 조회가 늦거나 실패해도 저장 성공을 실패처럼 표시하거나 이전 Pick ID로 이동하지 않는다. 상품 상세에서는 기존 조회 권한 및 삭제/비공개 처리를 그대로 적용한다.

계정/상품/카테고리 변경 시 폼을 새로 생성해 이전 계정의 저장 결과와 초안을 재사용하지 않는다. 로그인 확인 중이거나 세션 오류가 있으면 저장 결과와 이동 버튼을 숨긴다.

## 기존 흐름 유지
`/pick/register`는 이미 실제 저장 결과의 Pick ID로 상세 이동하므로 변경하지 않는다. 상품 등록 승인 대기는 원픽 저장 성공으로 표시하지 않고 기존 프로필/등록 요청 흐름을 유지한다. 사진, 댓글, 한줄평 작성 규칙, 홈의 자기 제외 정책, DB 및 배포 설정을 변경하지 않는다.

## 검증
`mobile/scripts/test-pick-save-result.cjs`는 신규 선택, 변경, 한줄평 수정, 반환 ID 기준 이동, 다른 사람의 원픽으로 복귀, 저장 대기/실패/재시도, 저장 후 조회 실패, 로그인/계정 및 상품 키 분리를 검사한다. 기존 전체 회귀 테스트도 실행한다. UI 검사는 모의 네이티브 컴포넌트와 결정적 상태를 사용하며 실제 휴대폰 종단 간 검사는 아니다.
