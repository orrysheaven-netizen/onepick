# 두 사용자 흐름 검증

2026-09-17, onepick-dev 데이터베이스에서 실행했다.

## 실행 방식

하나의 트랜잭션에서 일반 사용자 A/B와 별도 관리자 계정을 임시 생성했다. 실제 authenticated/anon 역할과 사용자 식별자를 전환하면서 앱이 사용하는 함수와 접근 정책을 검증했다. 모든 검증 뒤 ROLLBACK으로 계정과 데이터를 되돌렸다. 기존 사용자의 기록을 테스트 대상으로 사용하지 않았다.

## 통과한 검증

- 등록 요청은 승인 대기로 저장되고 원픽을 자동 생성하지 않는다.
- 같은 사용자의 동일 요청 재시도는 기존 요청을 재사용한다.
- 일반 사용자는 자신의 요청을 승인하거나 승인된 상품을 직접 생성할 수 없다.
- 승인 전 상품은 원픽으로 선택할 수 없고, 다른 사용자는 미승인 요청을 볼 수 없다.
- 관리자는 승인, 중복 요청 연결, 반려를 처리할 수 있다. 이미 처리한 항목에 이전 상태 기준 변경을 보내면 덮어쓰지 않는다.
- 승인 후 두 사용자는 같은 상품에 각자의 원픽과 한줄평을 저장한다. 같은 상품 재선택은 한줄평을 갱신하며 원픽이 중복 생성되지 않는다.
- 사용자 B가 A의 원픽에 댓글을 남기면 A에게 보인다. A는 B의 댓글을 수정할 수 없다.
- A가 다른 상품으로 변경하면 기존 원픽은 과거 기록이 되고 현재 원픽은 하나만 유지된다.
- 원래 상품의 현재 인원이 2명에서 1명으로 줄고 새 상품은 1명이 된다. B도 A의 변경된 공개 원픽을 조회할 수 있다.
- 비로그인 공개 조회에서 승인 상품과 현재 원픽이 정상 조회된다.
- 별도 서비스 검사로 내 현재 한줄평 우선 표시, 중복 제거, 이전 선택 제외, 비로그인 목록을 확인했다.

## 정리 확인

검증 종료 후 임시 계정, 카테고리, 상품, 원픽을 다시 조회한 결과 모두 0개였다. 트랜잭션 내 댓글과 감사 기록도 같은 롤백에 포함된다.

## 범위와 남은 확인

이는 실제 DB 함수·접근 정책 검증이다. 두 계정으로 카카오 로그인하여 브라우저에서 전체 흐름을 클릭한 검증은 아니다. 실제 이메일/카카오 계정을 새로 만들거나 로그인 정보를 변경하지 않았다. iPhone Safari 로그인 복귀, 기기 사진 선택·업로드, 두 브라우저 화면 간 자동 갱신은 별도의 실기기 점검 대상이다.

카테고리 미지정 요청 기능은 원격 DB 적용 승인 대기 중이다. 이번 검증은 현재 운영되는 카테고리 지정 요청 흐름을 대상으로 한다.

재실행용 회귀 검사: `supabase/tests/009_two_user_lifecycle.sql`. 해당 파일은 기존 DB 테스트 러너의 pgTAP 형식을 사용한다. 이번 원격 검증은 pgTAP 설치 없이 동일한 DO/ASSERT 본문을 직접 실행했고 오류 없이 완료했다.
