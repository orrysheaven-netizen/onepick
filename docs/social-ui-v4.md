# OnePick Social UI v4

상태: **디자인 기준안 확정 / 구현 전**

Figma: https://www.figma.com/design/77VUmD5myMWbuISkIPz37W/
최종 제목 위계 기준: `15 Title Hierarchy Final Check` — A안 기본 / D안 메뉴 고정 화면 / B안 좁은 한 줄 목록.

## 목표

OnePick을 일반 게시물 SNS가 아니라 **사람들의 현재 원픽과 이유가 흐르는 취향 서비스**로 보이게 한다.

핵심 원칙:

- 글은 Pick의 한줄평 하나다. 별도 게시물 본문을 두지 않는다.
- 좋아요/하트와 좋아요 수를 두지 않는다.
- 원픽은 지속되는 현재 상태이므로 홈·메뉴 카드에 게시 시각이나 `새로 고름`, `○○에서 바꿈` 같은 선택 상태 문구를 표시하지 않는다.
- 메뉴는 클릭 가능한 탐색 진입점이다.
- 메뉴 상세은 유저들의 현재 원픽을 나열한다.
- 음식 Pick은 `매장 / 온라인 / 레시피` 채널을 명확히 구분한다.
- 채널 표시는 콘텐츠 제목보다 먼저 둔다.
- 음식의 개별 콘텐츠는 제공처와 메뉴를 **시각적으로 분리**한다. 여러 메뉴가 섞이는 목록은 A안: `[채널][제공처]` 한 줄 → 메뉴명 메인 제목. 제공처는 잉크색·보통 굵기, 메뉴명은 더 큰 메인 제목이다. 메뉴가 화면 제목으로 이미 정해진 곳은 D안으로 제공처를 크게 하고 메뉴 줄은 생략할 수 있다. 좁은 검색 결과만 B안 `[채널] 제공처 · 메뉴명`을 사용한다.
- 집계 표기는 `N명이 선택`보다 OnePick 언어인 `원픽 N`을 사용한다.
- 제공처 이름은 내부 프로필로 연결한다.
- 외부 링크와 SNS는 선택 정보다. 없는 정보는 UI에서 숨긴다.

## 1. 홈

정보 순서:

1. 사용자
2. `[채널] 제공처` — 잉크색·보통 굵기
3. 메뉴명 — 메인 제목
4. 한줄평
5. `✓ 내 원픽 · 원픽 N · 댓글 N · 공유`

예:

```text
orry
[매장] 서울집
미역국
“국물이 진한데 부담스럽지 않음”

✓ 내 원픽 · 원픽 7 · 댓글 10 · 공유
```

규칙:

- 좋아요 없음.
- 별도 게시물 본문 없음.
- 같은 item이 내 현재 원픽이면 `내 원픽` 배지만 표시한다.
- `나도 이게 원픽`은 기본 CTA로 두지 않는다.
- 사진 없는 피드 카드의 이미지 영역은 #552의 사용자 결정 전까지 확정하지 않는다(영역 제거 vs `bg/placeholder`).
- 제공처는 provider profile로, 메뉴명은 메뉴 상세로 이동할 수 있게 한다. 터치 영역이 지나치게 잘게 쪼개지면 카드 전체는 Pick 상세로 열고, 메뉴/제공처는 별도 명확한 보조 링크로 둔다.
- 카드 높이는 내용에 맞게 줄이고 불필요한 하단 빈 여백을 두지 않는다.
- 한줄평/댓글 영역은 기존 Pick 또는 Item 상세로 이어진다.

## 2. 탐색: 메뉴를 클릭 가능한 진입점으로

메뉴 목록은 전체 행이 클릭 가능해야 한다.

예:

```text
[사진] 미역국
       ○ ○ ○
       원픽 23
       매장 · 온라인 · 레시피            ›
```

필수 affordance:

- 전체 행 최소 터치 높이 확보.
- 오른쪽 chevron.
- `원픽 N`과 사용자 아바타 미리보기.
- pressed/hover 상태.
- 메뉴 이름은 단순 라벨처럼 보이지 않게 한다.

## 3. 메뉴 상세: 유저들의 현재 원픽

예: `미역국`

상단:

```text
미역국

[전체] [매장] [온라인] [레시피]

현재 원픽 23
```

목록:

```text
orry
[매장] 서울집
“국물이 진한데 부담스럽지 않음”

✓ 내 원픽 · 원픽 7 · 댓글 10 · 공유
```

채널 탭:

- **전체**: 세 채널의 현재 Pick을 시간순으로 섞어 표시.
- **매장**: `picks.channel='offline'`.
- **온라인**: `picks.channel='online'`.
- **레시피**: `picks.channel='recipe'`.

현재 `ReadRepository.getPicks`는 category 필터와 커서를 지원한다. 구현 시 input에 channel 필터를 추가하면 메뉴 상세의 정확한 채널별 페이지네이션을 DB 스키마 변경 없이 만들 수 있다.

## 4. 채널 표시

사용자 노출 문구:

- 등록 선택: `매장 / 온라인 / 레시피`
- v4 카드/메뉴 상세도 동일한 짧은 문구를 우선 사용한다.

표기:

```text
A안 — 여러 메뉴가 섞인 카드:
[매장] 서울집
미역국

[온라인] 99밀크티
클래식 밀크티

[레시피] 엄마의식탁
미역국

D안 — 메뉴가 화면 제목으로 이미 정해진 곳:
[매장] 서울집
(메뉴 줄 생략 가능)

B안 — 좁은 한 줄 검색 결과:
[매장] 서울집 · 미역국
```

채널별 정보 우선순위:

| 채널 | 내부 프로필 | 주요 외부 행동 | 보조 정보 |
|---|---|---|---|
| 매장 | offline provider | 지도 보기 | 홈페이지/예약/SNS |
| 온라인 | online provider | 공식몰 보기 | 브랜드 사이트/SNS |
| 레시피 | recipe source | 영상 보기 | 제작 채널/SNS |

## 4.1 원픽 / 댓글 지표 정의

- **원픽 N**: 해당 콘텐츠 대상의 현재 active Pick 수다. 음식에서는 같은 메뉴(category)·채널·대상(item)을 기준으로 센다. 교체되어 종료된 과거 Pick은 포함하지 않는다.
- **댓글 N**: 현재 카드에 표시된 **그 사용자의 Pick 한줄평 thread**에 달린 공개 댓글 수다. 다른 사용자의 같은 대상 한줄평에 달린 댓글은 합치지 않는다.
- 따라서 메뉴 상세의 한 사용자 카드에서는 `✓ 내 원픽 · 원픽 7 · 댓글 10 · 공유`처럼 상태 → 대상 전체 원픽 수 → 그 사람의 대화 수 → 공유 순서로 표시할 수 있다.
- 제공처 프로필의 메뉴 목록처럼 특정 사용자 Pick을 가리키지 않는 행에는 `원픽 N`만 표시하고 댓글 수는 표시하지 않는다.
- 좋아요/하트 수는 만들지 않는다.

## 6. 링크 / SNS 규칙

### 행동 링크

사용자가 바로 행동하는 링크:

- 매장: 지도, 공식 홈페이지, 예약
- 온라인: 공식몰/공식 판매처
- 레시피: 원본 영상

### SNS

제공처/출처를 더 알아보는 링크:

- Instagram
- YouTube
- Blog
- 기타 허용 플랫폼

### Optional UI

링크가 없는 경우:

- disabled 버튼을 만들지 않는다.
- `링크 없음`을 표시하지 않는다.
- `연결` / `SNS` 섹션 자체를 숨긴다.

일부 링크만 있으면 있는 항목만 표시한다.

## 7. 현재 데이터 구조와 v4의 관계

### 이미 활용 가능한 것

#### 매장
- `providers(kind='offline_branch')`
- `places`
- `item_providers`
- `item_channels.channel='offline'`
- 지도 URL

#### 온라인
- `providers(kind='online_store')`
- `online_stores.official_url`
- `item_providers`
- `item_channels.channel='online'`

#### 레시피
- `items.external_source='youtube_video'`
- `items.creatorName` 표시 데이터
- `item_channels.channel='recipe'`
- 원본 YouTube 영상 URL

#### 공통
- `ItemChannelLinks`는 링크가 0개이거나 조회 실패일 때 아무것도 렌더링하지 않는 optional UI 원칙을 이미 사용한다.

### 아직 없는 것

#### Provider SNS
오프라인/온라인 provider에 Instagram·YouTube·블로그 등을 여러 개 저장하는 공통 구조는 아직 없다.

후속 검토안:

```text
provider_social_links
- provider_id
- platform
- url
- sort_order
- created_at
- updated_at
```

제약 원칙:

- provider 공개 상태를 상속한다.
- https URL만 허용한다.
- platform allowlist를 둔다.
- 사용자 클라이언트는 읽기만 하고, 쓰기는 관리자 경로로 제한한다.
- 링크가 없어도 provider 자체는 정상 표시된다.

#### 레시피 출처 프로필
현재 provider 모델은 `offline_branch / online_store`만 지원한다. 레시피 영상에는 creator 이름이 있지만, 여러 영상을 하나의 제작 채널 프로필로 안정적으로 묶는 canonical source identity는 없다.

따라서 v4 UI의 `레시피 출처 프로필`은 디자인 목표이며, 구현에서는 다음 중 하나를 별도 검토한다.

1. YouTube channel ID를 이용한 별도 `recipe_sources` 계층.
2. provider를 레시피까지 확장하는 별도 스키마 결정.

기존 provider의 의미를 검토 없이 넓히지 않는다.

## 8. 프로필

본인 프로필:

- 프로필 공유 버튼.
- 팔로워/팔로잉 수는 표시하지 않는다.
- 음식 원픽은 한줄평을 포함한 행형 목록.
- `음식 / 다른 취향`으로 구분.

타인 프로필:

- 초기 공개 MVP에서는 Follow CTA를 노출하지 않는다(`OnePickFeatures.follow=false`).
- 팔로워 수는 표시하지 않는다.
- 팔로우 구현·공유 딥링크 계약은 후속 롤아웃을 위해 `follow.md`에 보존한다.

## 9. 하단 내비게이션

v4 기준:

```text
홈 | 탐색 | (+) | 알림 | 프로필
```

- 중앙 `+`를 원픽 등록 핵심 Action으로 유지한다.
- 홈 헤더에 별도 `+`를 두어 같은 행동을 중복하지 않는다.
- 실제 플랫폼 아이콘 세트를 사용하고 문자/점 placeholder는 최종 구현에서 제거한다.

## 10. 상세 / 댓글 / 알림

상세:

- 한줄평 하나만 본문으로 표시.
- 좋아요 없음.
- 댓글 / 공유만 유지.
- 채널이 제공처 이름보다 먼저 표시된다.

알림:

- Threads형 행 + 구분선.
- 초기 공개 MVP 알림은 댓글 중심으로 유지한다. 팔로우 원픽 변경과 등록 승인/병합/반려 알림은 현재 노출하지 않으며, 관련 구현은 후속용으로만 보존한다.
- 좋아요 알림은 없다.

## 11. 최근 7일 랭킹

디자인 목표:

- 메뉴별 `최근 7일 원픽`.
- 매일 굴러가는 rolling 7-day.
- 최소 표본 미달이면 순위 숫자와 선택 수를 숨긴다.

현재 `category_ranking`은 **전체 active Pick 누적 기준**이다. 따라서 실제 구현에는 기간 조건이 들어간 별도 RPC/계약이 필요하다. UI 문구만 먼저 `최근 7일`로 변경하지 않는다.

## 13. 구현하지 않는 것

- 좋아요/싫어요.
- 좋아요 수/반응 수 기반 인기 지표.
- 팔로워 수 공개.
- 외부 링크가 없는 경우의 disabled 버튼.
- SNS 수에 따른 순위/추천.
- 레시피 source identity를 임시 문자열만으로 합치는 것.
- `최근 7일` UI를 누적 랭킹 데이터에 붙이는 것.
