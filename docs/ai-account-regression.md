# API 키 없는 AI 평가 계정·응답 회귀 검사

## 범위와 발견 사항

API 연결 설정은 보류하고 기존 `feature/ai-profile-evaluation` / PR #47에서 계정 전환·공개/숨김·응답 처리를 점검했다. 운영 DB, 서버 배포, 실제 원픽과 사용자 평가는 변경하지 않는다.

기존 서비스는 기대하는 프로필 ID를 평가 요청 후에만 비교했다. 저장소의 `generate()`에는 시작한 프로필 ID가 전달되지 않았고, 공유 Supabase 클라이언트가 호출 시점의 세션을 선택했다. 화면의 상태 점검 이후 계정이 바뀌는 경우까지 요청 자체를 특정 계정에 묶는 장치가 필요했다.

## 수정

- 서비스가 `expectedProfileId`를 요청 전 저장소로 전달한다. 잘못된 원픽 수(NaN·무한대·소수 등)도 호출 전에 거부한다.
- 저장소는 로컬 세션에서 토큰을 확보한 후 `auth.getUser(token)`으로 사용자를 검증한다. 로컬 세션은 인증 판단의 근거가 아니라 요청에 사용할 토큰의 출처로만 쓴다.
- 생성 POST에는 검증한 토큰을 명시적으로 넣는다. 공유 클라이언트의 전역 인증값을 수정하지 않는다.
- 요청 중 계정 변경/로그아웃을 감지하면 뒤늦게 반환된 성공 결과를 반환하지 않는다. A→B→A, 로그아웃 후 같은 A로 재로그인도 감지한다. 동일 사용자의 토큰 갱신은 허용한다.
- Auth 이벤트 콜백에는 비동기 Auth 호출을 넣지 않고, 성공·실패 모두 구독을 해제한다.
- 공개/숨김도 소유 계정을 먼저 확인하며 기존 DB 소유권 필터와 RLS를 유지한다. OpenAI 설정이나 모델 호출에 의존하지 않는다.
- 응답을 TypeScript 타입만으로 신뢰하지 않고 실행 시 검증한다. 대상 프로필·시스템 작성자·공개/오래됨 상태·요약/본문·서로 다른 키워드 3개·날짜를 검사한다.
- 반환 객체는 허용 필드만 복사한다. 모델명·원픽 스냅샷 등 내부 필드를 화면 캐시에 넣지 않는다.

## 자동 테스트

`mobile/scripts/test-profile-ai-account.cjs`는 실제 서비스·저장소·응답 검증 코드를 불러와 모의 Auth/DB/함수 응답으로 **50개 시나리오**를 실행한다. 테스트 중 전역 네트워크 fetch는 실패하도록 바꾼다. 실제 API 키, 사용자 토큰, 모델 호출, DB 쓰기는 사용하지 않는다.

기존 원픽 수·계정 분리, 인증 실패, 검증 중 전환, 요청 중 로그아웃·다중 전환, 토큰 갱신, 통신 실패, 인증 구독 정리, 서버 오류 분류, 잘못된 작성자·본문·키워드·상태, 내부 필드 제외, 비공개/공개/오래된 결과 매핑, 공개·숨김과 DB 오류 처리를 포함한다.

로컬에서 50개를 통과했다. 계정 ID를 전달하지 않는 이전 호출로 되돌리면 첫 회귀 검사가 실패하는 것도 확인했다. 기존 `npm test` 실행기가 `test-*.cjs`를 자동 탐색하므로 Mobile CI에 포함된다. 전체 타입 검사와 회귀 검사의 최종 결과는 이 변경 커밋의 GitHub Actions에서 별도로 확인한다.

## 검증의 한계

모의 테스트는 실제 DB RLS 검증, 로그인 브라우저/휴대전화 화면 테스트, AI 문장 품질 검증을 대신하지 않는다. 서버가 이미 접수한 생성 요청을 클라이언트 로그아웃으로 되돌린다고 보장하지 않는다. 원래 계정에 대한 서버 처리는 완료될 수 있지만 새 계정의 토큰으로 바꾸어 보내거나 전환 후 성공 결과를 반환하지 않도록 한다.

이번 변경은 기존 서버 인증·RLS를 약화하지 않으며, API 키 등록이나 운영 앱 배포 없이 가능한 클라이언트 보호와 회귀 테스트에 한정한다.
