# OnePick 브랜드 v1 — 적용 초안과 검증 경계

Refs #303. Owner: codex. Size: M. Area: frontend.

## 초기 자산 변경 (`f78a4309`)

- 지시서에 실제 포함된 확정 SVG는 6개다. 가로/흰색 가로/세로 로고와 밝은/어두운 앱 아이콘, 파비콘 원본을 변경 없이 저장했다. 회귀 테스트가 기존 원본 SHA-256을 고정한다.
- 가로 헤더는 24/28px 높이와 원본 비율을 유지한다. 바깥 여백은 표시된 점의 지름 이상이며 홈 링크에는 접근성 이름이 있다. 흰색 가로 로고는 `appearance="dark"`로 명시적으로 선택한다. 앱 전체 다크 모드를 새로 도입하지 않는다.
- 앱 아이콘 원본에서 불투명 180/192/512 PNG를 만들었다. 180은 Apple Touch, 192/512는 웹 매니페스트에 연결한다. 기존 네이티브 앱 아이콘 설정은 보존한다. 파비콘 ICO에는 16/32/48px가 들어 있다.
- 기존 OG 메타데이터와 앱 플러그인/인증/기능 플래그를 보존한다. 스플래시와 OG 이미지 자체는 이번 범위 밖이다.
- 페이퍼/잉크/그레이와 `brand`/`onBrand`, Outfit/IBM Plex Sans KR 글꼴 토큰을 추가한다. 기존 `accent`는 작은 링크와 채움색을 겸하므로 일괄 탠저린 치환 대신 잉크로 유지한다. 탠저린 위 글자는 잉크다.

## 2026-09-25 후속 — 공통 버튼·선택 표시

- 공통 `Button`의 primary 배경/글자/로딩 표시를 `brand`/`onBrand` 쌍으로 전환했다. secondary·soft·ghost의 글자는 어둡게 유지하고 danger 로딩 표시는 기존 danger 의미색을 따른다.
- `accentSoft`는 연한 탠저린 `#FFF0DC`로 바꿨다. 선택된 `Chip`은 어두운 글자·외곽선·굵기와 `accessibilityState.selected`를 함께 유지한다. 작은 탠저린 글자는 사용하지 않는다.
- 웹 하단 탭은 활성 아이콘 배경과 등록 버튼 배경에 탠저린을 사용하고, 아이콘·더하기 기호는 잉크로 표시한다. 작은 탭 이름은 잉크/그레이로 유지한다. 경로, 선택 판정, 클릭 동작은 변경하지 않았다.
- 활성 컨트롤의 누름 투명도를 0.9로 유지한다. 공통 버튼은 누름 상태와 비활성 상태를 분리하고, 비활성 버튼만 기존 0.6을 유지한다.
- 기본 탠저린/잉크 쌍의 계산된 대비는 약 7.79:1, 흰 바탕에 누름 투명도 0.9를 합성하면 약 6.42:1이다. 테스트는 흰색/페이퍼 바탕에서 일반·누름 글자 대비 4.5:1 이상을 검사한다. 이 계산은 실제 앱 전체 접근성 인증이 아니다.
- 기존 UI kit 테스트의 primary 배경 기대값 두 곳을 새 토큰으로 맞췄다. 기존 SVG/PNG/ICO, 로고 컴포넌트, manifest, 기능 플래그는 이 후속에서 변경하지 않는다.

## 실제 수행한 후속 검증

- `test-brand-controls.cjs`: 원래 컴포넌트·토큰에서는 6/12 통과, 수정 후 12/12 통과했다. 새 색상 쌍·누름 대비·로딩/비활성/선택 의미·기존 버튼 크기와 경로를 검사한다.
- 로컬 환경은 Node 22.16.0 / TypeScript 5.8.3이다. TSX를 변환해 실제 컴포넌트 함수를 실행하지만, React Native/라우터/JSX host를 대체한 결정론적 검사다. 실제 React renderer나 브라우저 E2E가 아니다.
- 기존 UI kit 테스트와 새 테스트의 JavaScript 문법 검사를 수행했다. 로컬에는 React 전체 실행 환경이 없어 기존 UI kit 전체 실행·프로젝트 타입 검사·웹 빌드는 수행하지 않았다. 해당 결과는 새 head의 필수 CI에서 별도로 확인한다.

## 현재 완료로 간주하지 않은 항목

1. **실제 본문 글꼴 로딩**: 여전히 토큰과 fallback만 있다. 이번 환경의 외부 패키지 서버 연결이 실패해 폰트 의존성·잠금파일·폰트 제공 코드는 변경하지 않았다. Google Fonts 외부 stylesheet/font 요청은 기존 CSP와 맞지 않으므로 넣지 않았다. 동일 출처 웹폰트 제공, 고정 버전·무결성·라이선스 보존, 실제 로딩과 성능 검증이 남는다. 로고는 path이므로 영향받지 않는다.
2. **화면 전체 색상/배치 검증**: 위 공통 컨트롤은 전환했지만 모든 화면을 직접 확인한 것은 아니다. 개별 화면에서 legacy accent를 사용하는 부분은 계속 안전한 잉크색이며 무차별 치환하지 않는다.
3. **실제 앱/기기 검증**: 실행 중인 앱의 헤더 배치·접근성, 브라우저 탭, iPhone 홈 화면 추가, 네이티브 아이콘 빌드는 아직 확인하지 않았다. 자산/컴포넌트 검사는 실제 앱 화면 검증을 대신하지 않는다.
4. 새 head의 `typecheck`, `verify-web`, `database-tests`와 Claude 독립 리뷰를 PR에서 확인해야 한다. 기존 head의 CI 성공을 새 변경의 결과로 사용하지 않는다. PR은 Draft·미병합으로 유지하며 이 문서는 병합 승인이 아니다.

## 재현 가능한 검사

```sh
cd mobile
node scripts/test-brand-assets.cjs
node scripts/test-brand-controls.cjs
node scripts/test-ui-kit.cjs
```

기존 `scripts/run-tests.cjs`가 `test-*.cjs`를 자동 수집하므로 새 workflow 없이 회귀 검사에 포함된다. 원본 자산 검사는 해시·파일 구조·연결을 검사하며 실제 앱 UI나 글꼴 다운로드를 시험하지 않는다.

## 변경하지 않는 보호 영역

DB, Auth, RLS, Storage, CSP/보안 헤더, secrets, CI workflow, 배포 설정은 수정하지 않는다. main 직접 쓰기, 운영 데이터 변경 및 자동 병합은 하지 않는다.
