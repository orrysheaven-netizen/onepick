# AI 댓글의 두 말투

## UI와 제품 기준

- T 버튼: **나 T야. 근거부터 줘.** — 담백한 해석, 선택 이유를 또렷하게.
- F 버튼: **난 에뿌야. 살살해줭.** — 다정한 해석, 선택 사이의 연결을 부드럽게.
- 두 버튼은 MBTI 검사·회원 특성 등록이 아닌 이번 댓글의 전달 방식 선택이다. 누구나 어느 버튼이든 사용할 수 있다.
- 한줄평 우선, 최소 공개 원픽 10개, 나이·민감한 특성 추론 제외, 공격적·부정적 인물평 금지는 두 말투에 동일하게 적용한다.
- T를 독설이나 결점 찾기로, F를 근거 없는 칭찬으로 바꾸지 않는다. 독립적인 두 생성 결과가 항상 같은 문장을 해석한다는 보장은 없으므로 실제 모델 결과는 별도 검토한다.

## 요청·표시

새 앱은 `tone: direct | warm`만 서버에 전송한다. 서버는 인증 후 2KiB/3초로 제한한 JSON에서 고정 값만 받아 작성 지시문을 선택한다. 사용자가 임의 지시문을 보내도 말투 규칙으로 실행하지 않는다. 모드 누락·잘못된 값은 AI 호출/원픽 조회/예약 전에 거부한다.

생성 중에는 두 버튼을 모두 막고 선택한 버튼만 진행 상태를 표시한다. 클릭 당시 말투와 계정을 유지하며, 같은 순간 다른 버튼을 눌러도 중복 생성하지 않는다. 표시용 말투는 버튼 상태가 아니라 서버가 저장한 댓글에서 읽는다. 다른 사람의 프로필에는 생성 버튼이나 MBTI 유형을 표시하지 않고 `담백한 해석`/`다정한 해석`만 표시한다.

## 저장·재사용

기존 프로필별 최신 댓글 한 건 구조를 유지한다. 선택한 말투는 서버 전용 `prompt_version`에 `:direct:tone-v1` 또는 `:warm:tone-v1`으로 포함한다. DB의 읽기 전용 생성 열 `tone`은 그 버전으로부터 계산한다. 일반 회원은 이 열이나 내부 버전을 수정할 수 없다. 별도의 사용자 MBTI 열·회원 선호 저장을 만들지 않는다.

원픽과 작성 규칙이 같아도 말투가 다르면 기존 댓글을 재사용하지 않는다. 새 생성이 성공하면 새 말투·새 생성 시각·비공개 상태로 같은 최신 행을 갱신한다. 생성 실패 시 기존 댓글을 다른 말투로 다시 표시하지 않는다. 이전 댓글에는 임의의 T/F 표지를 붙이지 않고 일반 취향 해석으로 표시한다.

모드 변경은 새 생성 요청이며 기존 10분 제한을 두 말투가 공유한다. T 후 바로 F를 눌러 제한을 우회하지 않는다. 같은 원픽·같은 말투의 유효한 최신 댓글은 기존 재사용 경로를 따른다. 새 생성 결과는 이전 공개 승인을 물려받지 않는다. 기존 댓글 버전 확인, 숨김, 응답 유실 복구, 원픽 변경 시 자동 숨김은 유지한다.

## 배포 규격

새 서버/앱 규격은 `profile-ai-v3-tones`다. 기존 v2 서버가 F 요청을 무시하고 기본 댓글을 반환하는 상황을 막기 위해 앱은 규격이 일치해야 생성 버튼을 활성화한다. 공통 작성 규칙은 `taste-v5-no-age`, 모드별 규칙은 `tone-v1`이다. API 설정이나 실제 모델 접근 권한이 검증됐다는 뜻은 아니다.

2026-09-19 개발 DB의 `20260919093429_add_profile_ai_comment_tone` 마이그레이션을 실제 적용했다. 실제 사용자 댓글은 생성·게시하지 않았다. 서버 전용 저장 함수의 direct/warm 전환·새 비공개 미리보기·최신 한 건·회원 임의 수정 차단·구버전 NULL 처리를 합성 데이터로 검증했고 전부 롤백했다. 최초 검사에서 생성 열 자체의 쓰기 거부(428C9)를 확인한 뒤 검사 예외 조건에 이를 포함했다. DB 권한을 완화하지 않았다.

## 품질 검토

기존 QA 실행기는 두 모드의 실제 생산 지시문을 재사용한다. `ONEPICK_QA_TONE=direct` 또는 `ONEPICK_QA_TONE=warm`으로 실행 대상을 선택한다. 기본값은 direct이며 결과의 promptVersion·promptHash에 실제 선택이 기록된다.

```sh
# 각각 네트워크·API 키 없는 계획만 생성한다.
ONEPICK_QA_TONE=direct node qa/run-profile-ai-quality.cjs plan --out=qa/results/plan-direct
ONEPICK_QA_TONE=warm node qa/run-profile-ai-quality.cjs plan --out=qa/results/plan-warm
```

각 실행의 기존 최대 24회·정확한 호출 승인·CI 유료 실행 금지·오류 중단 규칙은 그대로다. 두 모드의 실제 결과가 각각 같은 입력 근거를 존중하는지, 말투만 적절히 달라지는지는 실제 출력과 수동 검토가 필요하다. 이번에 실제 모델을 호출했다는 기록이 아니다.
