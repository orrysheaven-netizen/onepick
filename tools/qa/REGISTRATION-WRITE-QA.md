# 원픽 등록 1회 쓰기 QA

사용자 승인 범위: 전용 QA 일반 사용자로 테스트 원픽 1건을 생성해 사진 업로드,
한줄평 저장, 상세 이동, 새로고침 후 유지 여부를 확인한다.

## 실행 전

- `One-time Registration QA`는 main 수동 실행 전용이다. 정기 Daily QA는 읽기 전용으로 유지한다.
- main의 CI와 배포가 완료된 뒤 `confirm_registration`을 선택해 실행한다.
- 기존 `daily-qa` Environment의 QA 이메일·비밀번호 Secret만 사용한다.
- 계정에 원픽이 하나라도 보이면 중단한다. 기존 원픽을 교체하지 않는다.
- 로그인 직후와 제출 직전에 세션 만료 여유가 15분 이상인지 확인한다. 10분 job 안에서 토큰 갱신 없이 마칠 수 없으면 쓰기 전에 중단한다.
- 메뉴는 기존 분류의 `도가니탕`을 사용한다. 정확 일치가 안 되면 실패하며 AI 호출은 차단한다.

## 생성되는 데이터

실제 매장을 사용하지 않는다. `원픽 QA 등록 검증 전용 매장`이라는 고정 이름과
동일 이름의 네이버 지도 검색 링크로 신규 매장 경로를 진행한다. 실제 방문 후기가
아님을 한줄평에 명시하고 이미지에도 `ONEPICK QA / TEST IMAGE / NOT A REAL MENU`를 표시한다.

이 앱 경로는 원픽 1건 외에도 연결된 pending 항목·매장·카탈로그 관계와 사진 원본/썸네일을
생성할 수 있다. 기존 정책대로 관리자 승인 전 비공개 상태여야 통과한다.
승인·자동 삭제·기존 데이터 변경은 수행하지 않는다. 앱의 사진 정리 요청도 차단해
이번 실행의 근거와 이전 QA 파일을 보존한다.

## 제한과 판정

- 고정 운영 사이트·Supabase 프로젝트만 사용하고 관리자 계정은 거부한다.
- 전송 직전에도 원픽이 비었는지 확인한다. 서버의 `expectedPreviousPickId=null` 조건을 유지한다.
- staging RPC 1회, 자기 폴더의 새 사진 2개, 등록 RPC 1회만 허용한다.
- 예기치 않은 쓰기와 재전송을 차단한다. GitHub의 같은 run 재실행도 거부한다.
- 새 수동 실행도 기존 원픽이 있으면 실패한다. 실패 후 무작정 새 실행을 만들지 않는다.
- 실제 UI가 사진을 변환·업로드하고 등록하도록 한다. API로 등록을 대신하지 않는다.
- 성공 응답의 원픽/항목 관계, 교체 없음, 비공개 상태, 업로드 2개 성공을 확인한다.
- 새로고침 전후 일반 사용자 권한으로 저장된 원픽·한줄평·사진 참조를 읽어 대조한다.
- 로그에는 고정 단계와 성공 여부만 남긴다. 화면 캡처, trace, 인증 state, 응답 본문을 저장하지 않는다.
- 마지막에 이번 로그인 세션을 폐기한다.

부분 실패는 성공으로 간주하지 않는다. staging/업로드/원픽 저장 중 일부가 남아 있을 수 있다.
자동 재시도나 삭제 없이 실행 단계와 QA 계정 소유 데이터를 검토해야 한다.

## 검증 범위

`node --test tools/qa/registration-write-contract.test.mjs`는 네트워크 없이 실행 권한,
요청 대상·내용 제한, 자기 소유 pending 항목, 사진 쌍, 교체/중복 제출 차단을 검사한다.
운영 E2E 성공 근거는 수동 workflow의 실제 결과이며 오프라인 테스트로 대체하지 않는다.
`mobile/scripts/test-registration-write-guard.cjs`가 같은 테스트를 실행하므로 필수 Mobile CI의
`npm test`에서도 병합 전에 검증한다.

새 Secret 사용 워크플로이므로 병합 전 독립 보안 리뷰와 사용자 병합 승인이 필요하다.
현재 추가 비용이 드는 모델 호출이나 새 서비스는 사용하지 않는다.
